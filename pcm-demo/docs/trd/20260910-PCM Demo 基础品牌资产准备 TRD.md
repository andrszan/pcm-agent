# PCM Demo 基础品牌资产准备技术设计

> 设计日期：2026-09-10
> 状态：已实现，自动化回归、真实生成与兜底接入验证通过
> 适用范围：PCM Demo 第 6 步中存在 frontend 交付单元的产品工作区
> 实现、验证证据及隔离探针的覆盖边界见第八节。

## 一、目标与已确认决策

在基础工程项目化、基础主题处理完成后，为产品准备一套一致、可复用且已经接入前端的基础品牌资产，避免模板标识残留以及后续页面各自制作不同标识。

已确认的执行原则：

- 第 6 步增加独立品牌资产子任务，不增加编号步骤，不扩张原有项目化或主题 Skill 的职责。
- 负责人给执行 Agent 下达任务，Agent 执行 `media-assets`，负责资产选择、生成、实际查看、质量判断、派生、兜底和接入。
- 负责人只依据 Agent 的回复防止任务遗漏，不读产品文件、不看图评选、不复做视觉验收；完成判断保持轻量。
- 整套基础品牌资产共享最多 8 次生成调用，首次生成包含在内；这是提示约束，由 Agent 自行调度，不是程序硬性成本控制。
- 满足用途即可停止，不要求耗尽额度。额度用完仍无合适结果，允许使用合格的简洁 SVG 或文字标识兜底。
- 优先复用已有正式品牌资产；不以发生生图调用作为完成条件。

## 二、范围与产物

### 2.1 基础交付

1. **页面品牌标识**：具有产品身份的品牌图形、可编辑产品名称或二者的组合，可供后续页面复用。
2. **浏览器 favicon**：与页面品牌标识保持一致，适合小尺寸辨识，并已完成浏览器图标配置。

这不是要求两次独立创作。优先从同一个品牌图形派生方形标识、favicon 和页面组合；横向 Logo 可以由前端组件组合图形与产品名称，不必额外生成横图。文字标识兜底时，favicon 可采用一致的简洁字母或字形标记，不能遗漏浏览器图标。

文件格式和数量依据真实用途决定：生成 PNG 可以作为最终图形资产，简洁标识可以直接制作 SVG，品牌名称使用页面文字、字体或其它可编辑机制；不要求所有图片矢量化，也不能通过修改扩展名把 PNG 冒充 SVG。

### 2.2 条件性交付

- Apple Touch Icon：按移动端访问及添加到主屏幕的真实需求准备。
- PWA 应用图标及 maskable 版本：仅在产品确有 PWA 范围时准备，不为图标而增加 PWA 功能。
- 社交分享图：仅在公开页面、内容分享或营销传播有明确需要时准备。
- 深浅背景变体：确有辨识或对比问题时制作，不机械生成多套。

功能图标沿用目标项目已有图标库。首屏图、登录页插画、空状态插画和业务配图不作为本任务的固定交付，由后续具体设计或开发按需处理。

### 2.3 非目标

不建设完整品牌设计系统、资产管理平台、候选评分服务、负责人多模态通道、图像编辑 Provider 或自动矢量化流水线；不新增生成额度配置、程序计数器、预算状态、工具拦截器或成本统计机制；不修改公共三态、对话轮数、运行重试、其它步骤的验收门槛和 Git 流程。

## 三、流程位置与职责

### 3.1 调度顺序

第 6 步保持当前节点和后续节点不变，顺序调整为：

```text
project_bootstrap
→ 存在 frontend 时执行 tailwind_theme
→ 存在 frontend 时执行 brand_assets
→ 第 6 步完成，进入既有后续流程
```

沿用当前适用性和 Tailwind 工程准入，不顺带放宽或改造主题条件。无 frontend 时不创建主题或品牌任务会话；无适用工程时沿用既有跳过路径。前序任务失败或阻塞时，不启动品牌任务。

已有客户品牌资产和品牌约束优先于通用主题偏好。Agent 读取现有事实，不重新定义已确认品牌；无既定品牌时，结合产品定义、当前主题和真实前端制作标识。若发现明确约束冲突，在原会话说明事实、选项和建议，由负责人处理，不擅自重做主题。

第 10 步继续负责跨页面品牌使用规则、产品表面和框架契约；本需求不修改其实现，也不要求它重新生成资产。

### 3.2 三方分工

| 角色 | 职责 |
| --- | --- |
| 执行 Agent | 使用媒体能力，保证实际产物、视觉质量、品牌一致性、适用引用和真实验证 |
| AI-compatible 负责人 | 下达指令，回答必要决策问题，依据回复判断完成或继续，防止明显遗漏 |
| Python 编排器 | 调度独立任务，沿用会话、状态、模型策略和必要确定性边界核验 |

负责人不从文件路径推断图片质量，也不索取逐项完成声明。Agent 已交付结果且没有明确未完成事项时可完成；只在报告出现实际遗漏、矛盾或明确剩余工作时继续，不因缺少“一切无问题”之类表态而追加轮次。

## 四、Agent 执行合同

### 4.1 输入与授权

向品牌任务传入当前产品定义文档引用、目标 frontend 路径，以及存在时的 `.pcm/runtime.json` 引用。Agent 按需读取产品已有品牌资料、主题、资产约定和真实页面；不要求 Python 扫描全部媒体或整理额外品牌资料包。

本任务授权在已准入工具、既有受保护工作区配置和有限尝试范围内获取或生成基础品牌资产，写入目标前端资产与必要引用，并在已有产品文档补充最小使用说明。实际写入不包含无关布局重构、业务页面开发和主题重做。

媒体工具凭据仍属于工作区工具配置，不进入前后端运行配置、开发资源准备清单、公开资产或回复。继续遵循现有 Provider 的来源、能力和错误边界，不自动安装新工具或静默换服务。

### 4.2 选择与有限尝试

- 已有正式资产满足用途时直接复用，不生成替代品。
- 需要新资产时，依据实际图形复杂度选择生成或直接制作简洁 SVG；不是每个项目都必须生图。
- 整套共享最多 8 次生成调用，不按输出文件、尺寸、格式或主题变体分别重新分配额度。
- 每次先查看结果，只有存在具体影响用途的问题才继续调整；第一份合格结果即可采用，不要求为了比较而额外生成。
- 多份候选都合格时，由 Agent 选择最适合产品的一份，派生其它用途；不分别生成互不关联的 Logo 和 favicon。
- 同一任务继续或恢复时，Agent 沿用会话中的已有候选和已用次数，不以新一轮对话为由重置额度。结果不明的已发出调用保守视为已用机会，不反复补抽。
- Python 不计算或核验次数；不新增预算文件、计数状态或恢复账本。
- 额度耗尽仍不合适，采用合格的简洁 SVG 或文字标识兜底，并如实说明采用方式；不能从全部不合格候选中挑相对最好的一张冒充合格。
- Provider 不可用时遵循其错误处理规则，不连续抽卡碰运气。在本任务允许范围内可采用合格的本地 SVG 或文字标识，不因非必需的生成服务缺失阻塞整个开发流程。

### 4.3 质量、文件与接入

以下检查由 Agent 完成，不转化为负责人逐项审核清单或 Python 图像质量 verifier：

- 实际打开并检查图形内容、异常文字、明显畸变、可疑第三方标识和品牌一致性。
- 品牌名称不直接使用模型图片中的文字；保持正确、可编辑和清晰。
- 检查 favicon 在 16×16、32×32 等实际小尺寸的辨识度，必要时简化，不直接压缩完整横版 Logo。
- 检查实际使用背景的对比、边缘、裁剪、留白、文件可读性、格式和体积；PNG 不保证透明底，现有 Provider 不保证可编辑矢量结果。
- 按目标技术栈和已有资产约定选择最终路径、格式与引用入口，不统一硬编码为 `public` 或某个框架的文件约定。
- 配置 favicon；替换本次适用范围内的模板品牌引用。已有页面品牌位置使用同一资产，没有相应页面时不提前创建业务页面。
- 在真实浏览器检查已有页面的品牌呈现和实际图标配置、资源加载；按风险执行必要构建或检查。使用已分配的运行地址，不另选端口。
- 最终产品不依赖 Skill 内部路径、临时链接或外部生成服务；未采用候选放在 Git 忽略的临时位置，不打包进产品。
- 非交付验收截图按工作区约定放入 Git 忽略的 `.test-screenshots/`；必要使用说明进入已有产品文档，不创建候选评分表或专用品牌报告体系。

## 五、提示设计

领域 prompt 描述用途、输入、输出和约束，不出现 PCM 步骤编号或其它领域 Skill 的调用链。`media-assets` 的调用由 PCM 发起，不在其它 Skill 正文中建立跨能力依赖。

### 5.1 初始任务提示要点

```text
/media-assets 为当前产品准备并接入一套一致的基础品牌资产，覆盖页面品牌标识和浏览器 favicon，其它资产按实际用途决定。
优先复用已有正式资产；需要新制作时结合产品定义和当前前端主题，保持品牌文字可编辑。生成、选择、派生、质量检查、前端接入及适用验证由你完成。
整套资产共享最多 8 次生成调用，满足用途即可停止；继续或恢复时沿用已有候选和已用次数，不重新分配额度。生成服务不可用或额度耗尽仍无合适结果时，采用合格的简洁 SVG 或文字标识兜底。
最终资产进入目标前端的实际资产位置并完成必要引用，不重构无关页面或主题。报告采用方式、最终资产和接入结果，以及实际尚未解决的事项。
```

实现时追加真实产品定义、frontend 和适用运行配置引用。Provider 入口、凭据和通用媒体执行细则由实际加载的 Skill 负责，不复制成长篇任务提示。

### 5.2 负责人完成规则

```text
- completed：基础品牌资产已交付并完成适用接入，允许合理复用或合格兜底。
- continue：品牌资产准备或接入仍有明确未完成事项，可以使用现有资料、工程和工具继续处理。
```

沿用公共负责人规则处理 `blocked` 和决策信息不足，不新增严格视觉审核、固定汇报模板、文件逐项声明或生成次数证明。负责人使用 Agent 的真实结果，不亲自读取文件，也不索取“无问题”完成声明。

## 六、最小实现与恢复

### 6.1 接入方式

复用 `AgentDecisionLoopSpec` 和 `run_agent_decision_loop`，新增领域任务 `brand_assets`：conversation key、state key 和 task 使用同一稳定领域名；所需 Skill 为 `media-assets`。建立独立 session、conversation 和既有 system snapshot，沿用当前循环参数，不新增另一套执行框架。

在 `model_policy.py` 登记 `6.brand → brand_assets`，在 `model-policy.toml` 将 `6.brand` 绑定已有 `building` profile，不新建 profile 或调整其它任务参数。初始提示和负责人上下文只传入本任务需要的资料。

公共恢复登记 `_RESUME_STATIC_KEYS[6]` 追加 `brand_assets`，允许当前品牌任务的人工负责人消息投递到原会话。completion verifier 只复用必要工程/Git 边界及已有临时产物处理，不解析品牌说明、不扫描图片判质量、不强制固定文件名或新资产清单。

### 6.2 恢复与兼容

- 前两项完成、品牌任务失败或阻塞时，恢复品牌原会话，不重跑已经完成的项目化和主题 Agent。
- 品牌任务完成但步骤推进中断时，复用其已保存完成历史，避免再次生成。
- 真正不可替代的外部缺口沿用现有 `blocked`；执行错误沿用 `failed`，不将额度耗尽或可本地兜底的生图缺口定义成新的状态。
- 已成功的历史第 6 步不自动补跑品牌任务，不因缺少新品牌记录而判失败，也不宣称历史产品已补齐新资产。
- 尚未完成的旧项目化或主题任务沿用原 system snapshot 和 session；它们完成后才创建新品牌任务。
- 不给 `steps/06.json` 增加必须存在的品牌完成字段，不迁移或改写历史成功数据。新任务完成事实使用现有对话与领域状态保存。
- 模型策略依旧启动时加载且严格验证。升级后重新启动编排以生成包含新任务的策略快照，不热更新运行中进程，不放宽旧快照校验。

### 6.3 预期修改位置

- `pcm-demo/steps/step_06_project_bootstrap/step.py` 及 `test_step.py`：品牌任务、调度、轻量裁决和恢复回归。
- `pcm-demo/model_policy.py`、`model-policy.toml` 及相关策略测试：新任务登记及严格完整性校验。
- `pcm-demo/common/agent_decision_loop.py` 及相关测试：新增合法恢复领域，不改公共三态和循环机制。
- `pcm-demo/steps/step_06_project_bootstrap/README.md`、`pcm-demo/README.md`、`docs/pcm/PCM版AI Agent自动化流程设计.md`：实现时同步三任务顺序、职责和恢复说明。

原则上不修改 `media-assets`、`project-bootstrap`、`tailwind-theme` 和 `ui-ux-framework` Skill 正文。本需求的资产范围和有限尝试属于调用方任务授权，保持各能力独立。

## 七、验证与完成标准

### 7.1 确定性回归

沿用项目现有 unittest，不引入测试框架。至少覆盖：

- 存在 frontend 时严格按项目化、主题、品牌顺序执行，三项 session/conversation 相互独立；无 frontend 时不调用品牌任务。
- 负责人完成品牌任务后才推进；继续或阻塞时保留原会话，人工恢复消息只进入当前品牌对话。
- 品牌任务恢复不重跑前两项，已完成品牌任务不重复生成；前序阻塞不创建品牌会话。
- 历史成功无品牌字段仍按原合同复用，不补跑、不伪造新资产交付。
- `6.brand` 使用既有 profile；缺失分配仍按原策略失败，不新增回退。
- 初始提示保留共享最多 8 次、恢复不重置、可兜底和 Agent 保证质量；负责人规则保持轻量，不要求读文件、看图或逐项证明。

测试只证明调度与提示合同，不能证明实际模型永不超额，也不能证明生成视觉质量。没有程序计数机制，就不编造硬性次数拦截测试。

### 7.2 真实集成

在隔离、获授权的目标产品工作区验证一次新资产制作和接入，实际调用媒体生成通道并查看结果，确认同一标识可用于页面和 favicon；按真实用途允许合格本地派生或兜底。另用明确不可用的生成配置或已知缺口验证本地兜底路径，不需要为了验证而故意耗尽 8 次付费机会。

核对最终资产在目标前端、浏览器引用有效、小尺寸可辨、没有工具凭据进入产品，以及负责人可以依据简洁结果正常完成。不得用假 Agent 返回或本地空图片替代真实生成与浏览器证据。

运行受影响的步骤、公共恢复、模型策略及入口相关测试，必要时执行 PCM Demo 全量 unittest 和 compileall。未执行的真实验证如实保留缺口，不以文档、Mock 或单元测试宣称视觉验收完成。

### 7.3 最终完成

运行代码已接入独立品牌任务，既有恢复与成功兼容未退化；Agent 能在有限尝试提示下交付或合理兜底，并完成真实适用接入；负责人按结果防漏，不复做资产验收；相关测试、真实验证与流程文档已同步。本文状态只在实际实现和验证后更新。

### 8.1 真实生成与接入

隔离产品通过真实 Claude Agent SDK、`run_agent_decision_loop` 和 AI-compatible `request_decision` 执行品牌任务，负责人最终判定 `completed`。主会话已实际查看生成图形、favicon、桌面与移动页面截图。
