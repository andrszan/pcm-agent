# 测试编写与维护

适用于采用本工作区规则的各类开发项目，不限定语言、框架、目录或测试文件命名。新增、修改或审查测试时遵循以下原则。

## 测试目标

- 围绕可观察行为、稳定协议和具体回归风险写测试；从测试名称、输入和断言应能看出什么错误会使它失败，不要求另写测试价值报告。
- 简单不等于低价值。输入保真、权限、路径边界、数据一致性、失败恢复和凭据脱敏等测试，即使只有少量断言也应保留。相同行为已有充分覆盖时，不只替换示例文案重复测试。
- 根据改动风险选择必要的单元、集成或端到端验证，不为凑数量、覆盖率或形式完整增加永久测试，也不为一次局部调整机械搭建新测试体系。

## 断言与测试数据

- 优先检查返回值、状态变化、持久化结果、公开交互和实际副作用。不要仅凭源码中出现某个词、导入了某个模块或使用了某种内部实现，就推断运行行为；源码本身确为生成器或静态检查工具的交付对象时例外。
- 不把自然语言措辞、注释、内部变量名或无合同要求的排版固化为包含断言、禁词清单或整段快照。合法的措辞调整或内部重构不应迫使行为测试同步改写。
- 字符串比较用于真实合同：协议字段、命令与路径语法、解析格式、输入原样保留、兼容标记、脱敏结果，或明确要求逐字一致的交付内容。快照只覆盖有稳定验收意义且能审阅的结果，不机械更新快照掩盖回归。
- 验证资料传递时使用有区分度的测试标记或输入变量，检查内容是否完整到达正确位置、是否误传给其它对象；不要复制产品或提示词句子充当第二份真源。
- 异常测试应辨别预期失败原因和阶段，必要时检查稳定错误码、相关调用、状态与文件是否不变。不锁定无协议要求的内部错误文案，也不放宽成任意异常都算成功。

## Prompt 与模型相关测试

- Prompt 组装测试只验证动态资料、规则注入、调用路由、必要转义及输入输出边界，不逐句复刻角色说明、领域规则、历史禁词或仅供模型阅读的标签排版。纯措辞修改不要求新增永久自动化测试。
- 检查提示词中存在一条要求，不能证明模型理解或执行了它；安全要求的文字存在也不能替代实际权限和副作用验证。模型效果按具体场景的实际决策或执行结果判断，不按是否复述标准句判断。
- Mock、stub 和 fake 用于隔离依赖、注入失败和验证确定性控制流。预设模型返回成功，只能证明程序如何处理成功，不得据此宣称验证了模型判断能力。测试替身不依赖无关中文句子识别分支，优先使用调用参数、明确的响应序列或测试状态。
- 语义回归优先复用少量真实失败场景及脱敏输入，按相关改动针对性验证；不要求每次改 prompt 都调用真实模型或重跑完整产品开发流程。

## 清理与验证

- 混合测试中有有效行为断言时，只删除或改写脆弱部分；确认没有独立保障价值才删除整个方法，不按“比较字符串”或“测试简单”批量删除。清理本次产生的孤儿 fixture、import 和变量，不顺带改产品行为。
- 调整测试后运行受影响的回归；失败先定位原因，不直接放宽断言或更新预期。必要时用错误输入、故障注入或受控变异确认测试确实能发现目标回归，不以剩余测试全绿作为保障未削弱的唯一证据。
