# product-experience-audit — 全项目级集成产品体验审计

## 职责

本 Skill 独立审计当前声明范围内已经形成的完整集成产品。它检查多个需求、模块和产品表面组合后的整体用户体验，不承担单页面、单需求、验证切片或局部改动的设计、实现与开发验收。

1. 从完整集成产品和当前项目事实建立全项目范围、主要用户任务和安全边界；
2. 按跨需求用户任务、产品表面和状态衔接动态拆分覆盖模块；
3. 在可访问的完整产品中执行功能、UX、视觉、组件、适配性和可访问性审查；
4. 核验发现、合并重复、排除猜测和纯偏好；
5. 输出经核验候选、证据、重复项、覆盖缺口和高影响边界。

审计必须从完整产品的主要用户任务出发，并同时关注：

- 功能、状态、权限、数据和跨任务闭环；
- 入口、理解、操作、反馈、恢复和效率；
- 视觉层级、布局、密度、排版、颜色、素材和一致性；
- 控件、表单、列表、详情、导航、对话和状态组件是否适合任务；
- 目标产品实际支持的终端、视口、输入方式、主题和辅助技术。

任何一面都不是附属项。产品具有图形界面时，不能只做功能验证而跳过真实浏览器和截图视觉审查。

## 输出与修改边界

默认在回复中直接返回审计结果，不创建审计初稿、固定日期目录、Manifest、Run ID、阶段报告、证据数据库或专属过程产物。

本 Skill 输出的是候选，不是正式需求：

- 不创建或修改 canonical Backlog、正式需求、TRD、Issue 生命周期或完成状态；
- 不分配正式需求 ID；候选标题或回复内临时序号仅用于本次阅读，不获得项目生命周期含义；
- 不修改业务代码、测试、配置、依赖、产品定义、设计文档、Git 暂存区或提交；
- 不替项目决定正式范围、优先级、解决方案或发布结论。

只有用户明确指定一个项目已经存在、专门接收候选的文件或章节时，才可在读取其结构和仓库状态后精确追加本次经核验候选。不得自行寻找或创建接收位置，不得把 canonical Backlog、正式需求清单或历史档案当作候选接收位置；位置或边界不清时，直接返回结果并说明未写入。

如果允许追加，只编辑本次新增候选，不覆盖用户已有修改，不写正式需求 ID，不顺带同步状态、日期或其它生命周期字段。

## 安全与副作用

在调用方已授权、可复位且不影响真实用户的环境中，可以使用虚构身份和数据执行完成任务所需的创建、编辑、提交、刷新、重试和清理。

未经安全授权，不执行真实资金变化、真实外发、生产数据写入、不可恢复删除、权限授予、账号封禁、密钥轮换或其它高影响操作。到达危险边界时，只检查入口、说明、确认、取消、权限和前置反馈，明确已观察事实、未验证结果与解除条件。

不安装浏览器、CLI、依赖、插件或基础设施，不启动来源或归属不清的服务。使用项目已有的真实运行入口和证据能力；工具缺失时如实记录覆盖缺口，不能用源码、Mock、组件测试或历史结果伪装本次动态体验。

证据和输出遵循数据最小化。不得复制密码、令牌、会话值、请求头、真实个人资料、敏感生产数据或可重放链接；不能安全读取或保留的材料只描述与结论直接相关的脱敏事实和受限位置。

## 建立范围与适用性

读取足够的当前事实：

- 当前声明的完整产品范围、已完成能力、非目标和主要用户任务；
- 各适用交付单元的当前版本、构建、提交、运行环境和仓库边界；
- 可访问入口、测试身份、角色权限、数据准备和复位方式；
- 已有需求、设计规则、验收、测试、已知问题和限制；
- 可用交互、截图、结构、可访问性、网络、日志和数据证据；
- 允许与禁止的副作用。

如果项目没有面向任何用户或实际使用方的可见结果、交互任务或可审计产品表面，立即报告“不适用”，说明应由工程、接口或数据验证覆盖的范围；不要启动浏览器、制造候选或创建文件。

如果调用方只提供单个页面、单个需求、验证切片或局部改动，并要求把它当作全项目审计，明确说明范围不足并无副作用结束。可以指出这类范围应在当前交付的设计、实现和真实验收中处理，但不自动调用其它能力，也不把局部结论扩张为全产品结论。

只有完整集成产品、当前声明范围和主要用户任务可访问时，才根据目标用户、导航或功能入口、跨角色闭环、跨需求状态和共享产品表面，动态整理一组可掌握的审计模块。模块按任务和状态边界组织，不按页面数量机械切分，也不套用固定 Web 模板。API、CLI、桌面、移动、嵌入式或混合产品使用各自真实交付面。

每个模块明确：

- 用户或实际使用方及其目标；
- 正常入口、前置状态和测试数据；
- 可观察的成功结果；
- 相关空态、失败、冲突、恢复和跨模块状态；
- 适用设备、视口、输入方式和辅助技术；
- 副作用边界。

## 真实任务审计

### 功能、任务与状态

从正常入口完成任务，并按风险覆盖真正会改变结果的状态：

- 正常完成和完成后下一步的可发现性；
- 空态、长内容、边界值、重复操作和历史状态；
- 输入校验、请求失败、冲突、失权和安全重试；
- 返回、刷新、重新进入、深链和跨模块衔接；
- 加载、离线、超时、服务异常或外部能力降级；
- 适用的角色差异、隐私窗口和高影响确认。

记录用户寻找入口、理解内容、输入、等待、来回定位、恢复和确认结果的实际成本。不要穷举角色、数据和设备的笛卡尔积，也不要只走 happy path。

### UI、内容、视觉与组件

具有图形界面时，对各模块代表性页面和关键状态生成截图，并**实际读取截图本身**进行判断。只生成截图、只看 DOM、accessibility tree、文件名、尺寸或“无横向溢出”，都不算视觉审查。

结合产品定位、现有设计语言和用户任务检查：

- 第一眼能否理解当前位置、状态、内容主次和主要行动；
- 页面标题、对象、动作、状态、帮助、空态和错误文案是否可理解且一致；
- 信息结构是否贴近用户任务，而不是暴露内部数据结构；
- 是否存在无价值步骤、重复输入、跨页面反复定位或难以恢复的操作；
- 布局、内容宽度、密度、留白、对齐、分组和阅读顺序是否帮助扫描；
- Card、Table、Badge、Tabs 等组件是否用于合适语义，而不是堆叠成通用组件页面；
- 字体、颜色、边界、图标、图片和动效是否清晰、一致并建立信任；
- 危险操作是否与普通操作分离，状态与结果是否可识别；
- 各受支持交付面和尺寸下是否可读、可操作且视觉完整；
- 界面是否仍像脚手架、调试面板、原始数据查看器或无产品特性的通用模板。

“丑”“乱”“不够高级”只是待拆解信号。必须转化为截图中可定位的事实、受影响任务和改进价值；没有产品依据和用户影响的个人风格偏好不形成候选。

### 交互与可访问性

根据目标产品实际交互方式检查：

- 控件名称、角色、状态和当前项是否可理解；
- 键盘、触控、指针、遥控或其它主要输入是否能完成任务；
- 焦点顺序、可见焦点、关闭和焦点归还是否合理；
- 表单标签、字段错误、动态反馈和状态变化是否可感知；
- 颜色、声音、动效或手势是否成为唯一信息通道；
- 主题、缩放、文字长度、窄空间和 reduced motion 等适用设置。

工具无法证明的范围写入覆盖缺口，不以推测补齐。

## 证据边界

证据只能支持实际观察范围：

- 真实浏览器任务可以支持对应角色、数据、版本和步骤下的动态行为，不能自动扩展到未测环境；
- 截图支持可见文案、布局、遮挡、层级、组件、排版和状态，不单独证明交互、权限、持久化、请求结果或根因；
- 录屏支持已展示的操作顺序和反馈，未展示的网络、后端和数据结果不能推断；
- 网络、日志和数据状态可以支持技术结果，仍需结合用户任务说明影响；
- 代码和测试可以解释实现与已有保护，不能替代本次真实体验；
- 历史截图、历史测试和他人结论只能作为背景，不能冒充本次证据。

截图不要求固定保存目录。优先使用项目或调用方已有、已授权且安全的位置；临时浏览器截图可以用于当次实际读取。没有明确持久位置时，不为审计创建专属目录或过程资产。若候选需要引用但证据无法安全长期保留，记录观察条件、脱敏事实和复核限制，不复制敏感图片。

## 候选核验与去重

每个发现先判断：

1. **真实性**：是否来自本次真实任务、实际读取截图或相称证据；
2. **用户影响**：是否影响完成、理解、效率、恢复、信任、适配性或可访问性；
3. **范围**：是否能作为当前产品的合理增量，而不是重定义产品、品牌或架构；
4. **可验收性**：是否描述预期结果和观察方法，而不是锁死未经验证的方案；
5. **证据信心**：高、中、低，并明确限制。

所有有证据且有质量价值的事项都可以成为候选；任务仍能完成或影响较低，不是删除理由。未验证猜测进入覆盖缺口，不伪装成候选。大范围产品、品牌、业务、安全、兼容或架构方向进入高影响边界，不缩写成小改动。

按用户障碍、触发条件、实际伤害、共享组件或共同根因去重：

- 同一问题出现在列表、详情、通知等多个表面时，合并为一个候选并保留所有受影响界面和状态；
- 表达相似但用户目标、影响或验收边界不同的发现保持拆分；
- 已被现有需求、已知问题或本次其它候选覆盖时，列入重复项并指明归属，不再创建候选；
- 页面数量和出现次数可以说明范围，不能机械决定优先级。

默认直接返回：

```markdown

- 结束状态：已完成 / 部分完成且有覆盖缺口 / 不适用
- 审计范围、用户任务与环境：
- 已覆盖交付面与证据能力：
- 未覆盖范围摘要：

## 经核验候选

### 候选标题
- 用户与任务：
- 触发条件和当前事实：
- 预期体验及依据：
- 证据：交互 / 实际读取截图 / 结构 / 网络 / 日志 / 数据
- 用户与产品质量影响：
- 类型：bug / usability / ui-visual / component / adaptation / accessibility / improvement
- 建议优先级：高 / 中 / 低
- 证据信心：高 / 中 / 低
- 受影响表面与状态：
- 关联或重复项：
- 验收要点：
- 非目标与高影响边界：

## 重复项与未纳入项
- 项目、归属和依据：

## 覆盖缺口
- 未验证任务或状态：
- 原因与缺失条件：
- 补验方式：

## 高影响决定
- 已知事实、风险和需要确认的边界：
```

根据实际内容省略空字段，但不能隐藏覆盖缺口、重复项、证据信心或高影响边界。建议优先级只是候选分诊信息，不更新项目正式优先级。

如果用户明确指定了合格的现有候选接收位置，追加内容仍使用该位置已有结构；最终说明精确列出新增候选和修改位置，不把本次候选升级为正式需求。

## 结束状态与自检

- **已完成**：声明范围内的适用任务和证据已执行，候选已核验和去重，覆盖限制全部说明；
- **部分完成且有覆盖缺口**：现有环境允许的审计已完成，但部分任务、角色、状态、设备或证据能力不可用；
- **不适用**：没有用户可见结果或可审计体验任务，并已说明依据。

完成前确认：

- 范围是当前声明的完整集成产品和全部主要用户任务，不是单页面、单需求、验证切片或局部改动；
- 模块来自目标项目真实用户、跨需求任务和交付面，而非固定模板；
- 图形界面已使用真实浏览器，并实际读取代表性截图；
- 功能、UX、内容、视觉、组件、适配性和可访问性获得相称关注；
- 候选有可定位事实、用户影响、证据边界和可验收结果；
- 相同障碍或根因已合并，重复项和覆盖缺口单列；
- 没有把截图、代码、Mock 或历史结果夸大为动态证据；
- 没有执行未经授权的高影响副作用或泄露敏感信息；
- 没有创建或修改 canonical Backlog、分配正式需求 ID、修改产品实现；
- 仅在用户明确指定的既有候选接收位置内精确追加，没有创建专属过程产物。

完成只表示声明范围内的体验审计已按证据收束，不代表产品无其它问题、功能验收通过或发布批准。
