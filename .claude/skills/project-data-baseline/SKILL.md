# project-data-baseline — 项目数据基线收口

## 单一场景与交付目标

仅用于主要业务能力已经开发并集成完成、准备交接的项目；不承担未完成功能的补建，也不重新审计整个项目的开发进度。

本能力直接完成必要的理解、设计、实现、真实验证和交接。最终结果是：

> 接手者取得当前项目，按受跟踪说明准备必要依赖与真实服务后，通过一个项目级初始化命令或等价单一入口获得完整、自然、可操作的数据现场；有登录能力时，可以使用交付开发账号从正常入口登录并完成主要任务。明确放弃当前现场时，可以通过受保护的重置入口恢复同等完整的起点，数据库与所需文件共同可用。

只有方案、TRD、脚本、测试账号或原机器中的一份数据库，不算完成。Agent 在同次调用中直接实施、运行、检查、修复并复验，不把普通设计、编码或测试重新交回调用方调度。

不强制创建 TRD、Backlog、新需求 ID、阶段报告或过程目录，不以另一个 Skill 的输出为前提，不把执行转交给通用设计／开发 Skill。可以使用项目允许的工具和可用子代理，但最终整合与验收由当前 Agent 负责。不暂存、不提交、不建或切换分支、不合并、不推送；不更新项目级需求生命周期或改写归档历史。

## 从当前项目确定范围

先读取足以理解数据使用与恢复的项目事实，避免无边界全仓审计：

- 当前产品的主要角色、正常入口、主要任务和实际可用范围；
- 相关代码、模型、迁移、公开业务能力、权限、事务、异步任务和有效测试；
- 实际配置、数据库、文件／对象存储、已有 Seed、fixture、管理命令和账号说明；
- 运行方式、资源绑定、仓库边界、已有修改及允许执行的数据操作。

检查各相关仓库的 staged、unstaged 和 untracked 状态，保护调用方已有工作。现有代码、契约和运行事实用于判断 Current，文档不能代替它们；适用架构与产品约束继续保留。

先给出简短且自包含的本项目方案：接手者会看到什么、各角色能做什么、哪些数据和文件一起建立、复用／调整哪些入口、初始化与重置影响什么。普通内容、等价实现细节和可恢复环境问题自主处理；涉及必须丢弃或认领已有数据、资源归属不明、权限或高成本兼容变化时，说明准确目标、当前事实、实质可行选项、影响及推荐，再取得必要决定。

没有 Seed 时基于已完成业务建立；已有 Seed 时保留有效能力，只修正内容、入口、恢复或交接缺口，不默认整体重写。已经满足要求时实际核验后可以无代码变更结束，不为表现工作量制造新脚本或文档。

已有适用活动 TRD 时沿用；没有时直接收敛必要设计并实现。复杂恢复、重要兼容或删除合同需要长期维护时，记录在项目已有的合适位置，不同时生成多份重复方案。不把设计文档本身作为最终交付。

## 设计可使用的数据，而非测试陈列

按产品任务组织一套连贯情境，再确定所需数据，不按每张表固定插入若干行：

- 准备必要参考数据、身份、角色、关联业务对象、代表性状态和可信历史；每个主要角色有明确的使用入口和可完成任务。
- 名称、数量、日期、内容、操作者和来源关系符合当前产品领域，不使用需求编号、fixture／run 标签、随机海量记录或极端失败状态堆砌页面。
- 同时有可理解的已有结果和可以继续操作的任务，不把全部对象预置为终态。首次登录的默认上下文与账号说明一致，不要求接手者知道隐藏对象 ID 或先切换到另一个角色空间。
- 近期安排在首次初始化／重置时仍合理；同次中断恢复保持必要时间锚点，不因重跑平移已经创建的历史。业务确认、库存／余额变化和审计通过正式能力形成，不靠改枚举或事后篡改流水制造历史。
- 数据数量、角色、环境、命令名及技术机制按项目决定，不复制其它产品的账号矩阵、样例、数据库方案或锁／进度表结构。无登录、数据库或媒体业务时，不机械新增这些能力。
- 可操作开发数据与确定性自动化 fixture 分开：客户正常使用不必维持测试预设状态，边界测试由自己的数据与清理方式支撑。

目标产品中最终保留且可登录的全部开发账号均为项目专用，不冒用真实个人身份。账号及初始密码按项目规则写入受跟踪交接说明，不能只存在于 `.env`、一次性输出或 Agent 上下文中；不改称演示账号，不引入演示租户、隔离业务数据或生产禁用 Seed 等额外部署限制。临时测试后删除或回滚的短期账号无需逐个交接。用于访问数据库、对象存储、SMTP、OAuth、API、Git 等其它系统的凭据继续保密，不混入交付账号清单。

## 实现最小、完整的初始化与重置

复用当前框架、迁移、管理命令和业务公开能力，形成一个项目级入口下的初始化与重置语义，名称和实现方式不固定。正常产品运行不依赖本 Skill 的内部文件、提示词、临时 URL 或 Agent 会话。

### 初始化

- 从目标空环境建立必要结构、参考数据、交付账号、业务关系和所需持久化内容，不要求客户再拼装零散 Seed、注册管理员或手工补上传。
- 同一基线已经完整建立时，重复执行安全结束，不重复创建，也不重置正常使用后的密码、权限、最近上下文、编辑、消耗、已读、删除或替换文件。
- 已有来源不明业务数据时不按名称认领、不擅自混入、不隐式清空。现有基线需要替换时走明确授权的转换／重置路径。
- 本次操作有可核验的中断事实时按原目标和必要进度续接，不重复已成功部分；配置、源内容或身份不一致时不猜测恢复。
- 默认不提供向已使用现场自动合并新版初始数据的第三种模式。命令自身中断续接不等于存量数据补齐；不同基线修订不得静默覆盖或混合旧现场。

### 重置

- 明确整个约定项目环境的清理范围，包含范围内后来新增的账号、业务记录、会话、任务、上传文件及派生对象，不能用“只删 Seed 对象”冒充恢复完整起点。
- 操作前核验实际数据库／文件／对象作用域及归属，展示目标和不可逆影响，并取得对应确认。调用本 Skill 不等于允许删除任意环境。无交互运行必须具有精确目标的显式授权，不能把 EOF 或笼统的“清理项目”当作同意。
- 取消、错误目标或预检失败在破坏前停止。不清空共享 bucket、父目录或宽泛前缀；开发、测试及临时环境的清理范围不得重叠。无法证明归属的对象不因为旧库或目录已被丢弃就一起删除。
- 先确保恢复输入、必要服务和权限可用，再执行破坏性操作；保护在途业务、后台任务和外部写入。采用与真实风险相称的事务、互斥、停写或进度机制，不机械建设同一种状态机。
- 跨数据库与文件／对象存储不假设原子回滚。删除前保留必要归属和恢复依据，失败后明确已经产生的影响，不把半套现场开放为正常状态；重试不能返回旧阶段再删除新恢复的内容。
- 重建后旧会话、一次性凭据、旧任务和旧文件地址不得意外作用于新对象。完整核验通过后才宣布恢复成功。

编写 reset 与执行实际 reset 是两种授权边界：可以先在明确可丢弃且本次可确认归属的环境验证，最终使用环境的不可逆操作仍按实际目标确认。不为了便于初始化而绕过权限、约束、正常业务状态转换或追加式历史规则。

## 文件、对象存储与外部副作用

业务实际依赖的图片、附件、本地持久化文件及处理结果，与数据库记录属于同一恢复范围：

- 随项目交付必要源文件、可再现输入或已有可靠获取方式，明确其用途、来源权利和资产落点，不依赖原机器路径或第三方临时链接。
- 使用项目真实存储和处理链建立对象，核验内容、处理状态、绑定和正常访问权限。只有数据库引用、只有原图或伪造完成状态不算成功；声明必需的媒体失败时不能静默降级为无图基线。
- 只在当前产品确有价值时取得少量素材，并按项目允许的工具与来源固化；不建立图库、不机械给全部业务对象配图、不虚构素材授权。没有文件业务时不新增对象存储。
- 初始化与恢复不擅自发送真实外部邮件、支付、通知或其它高影响动作，也不为处理基线文件顺带消费用户的其它任务；沿用项目确认的安全路径，不把未发生的副作用记为成功。
- 可以按项目规则管理开发配置，但不伪造外部凭据、不把运行身份换成更宽权限身份。工作区媒体工具配置不进入产品依赖、业务数据或客户端。

## 真实验证与收敛

Agent 自己运行项目适用的检查、测试、构建、服务、接口和浏览器验证。普通失败先定位、修复并复验，不用“脚本已写好”“其它 Skill 没运行”或“环境准备留给用户”结束。

至少证明以下适用结果，并将其对应到本项目的真实入口与证据：

1. **空环境可恢复**：依照 README 可发现的说明，从空的项目专用环境执行单一入口，完成全部必要数据与文件，不依赖隐含补操作。
2. **客户可以使用**：逐个交付角色从正常入口登录，检查实际角色、默认落点、数据可见性、代表性允许与拒绝行为；完成主要跨页面或调用任务，通过刷新、重进、查询确认持久化。
3. **数据质量合格**：内容、数量、日期和关系可信，已有结果可解释且有下一步可操作。存在 UI 时在代表性视口实际读取渲染截图，等待数据／图片加载，而不是只等待标题或检查 DOM。
4. **重复执行不伤数据**：连续初始化，并在真实编辑、消耗、已读、权限变化、上下文切换、删除或文件替换后重跑，证明不重复、不覆盖、不复活。
5. **重置范围准确**：向明确测试目标新增记录和适用文件，确认重置后恢复完整基线；范围外哨兵记录／对象前后不变，未知或重叠范围被拒绝。
6. **失败可以恢复**：验证与当前实现有关的错误目标、取消、并发／在途操作、外部服务失败和中断续接，不能把部分恢复当作成功。
7. **交付内容可复现**：配置示例、源码／构建中的必要资产、账号清单及运行命令一致；当前最终保留的现场与交付说明相符，临时测试数据和文件不无界累积。

为重复保护、删除范围、并发及跨存储恢复等关键行为留下项目可运行的回归测试并实际运行。局部 Mock 可支持测试，但不能代替真实集成和使用证据。只运行受影响范围的既有检查，不用较窄的通过掩盖相关失败；不为验证擅自搭建新的基础设施。

遵守项目指定的端口、进程与截图位置；只停止本次明确启动或归属可确认的进程，不终止未知连接来绕过安全检查。非交付产物按项目约定处理，不混入代码或账号文档。

完成自审，检查范围、真实数据、权限、删除、异常恢复、文档与证据。存在破坏性或跨存储改动时，使用可用的独立审查或等价复核加强安全判断，并逐项处理合理发现；工具与协作方式可替换，不能把安全复核义务省掉。相关小缺陷可在本专项内修复并回归，不扩展为无关业务重做或全局 UI 改版。

## 交接与结束

更新相应仓库 README 的稳定入口、前置条件和链接；账号、复杂数据影响与恢复细节放在项目已有的合适受跟踪位置，不在多个文件重复维护同一清单。替换失效说明，不按需求编号在文档末尾不断追加新入口。

最终返回：实际交付的初始化／重置命令和前提、账号与主要使用情境的文档位置、数据与文件管理范围、真实验证结果、受影响仓库与待提交变更，以及仍适用的限制。没有调用方已提供的证据时不能虚构历史验收；提交成功也不能代替验证。

- **已完成**：初始化、直接使用、重复保护、重置、所需文件及交接全部有适用真实证据，无已知阻断。原实现已满足并实际验证时可明确“无代码变更”。
- **已实现但未完全验证**：只有不可替代的外部条件确实阻止部分验证时使用，说明已实现范围、真实缺口、已尝试动作和补验条件，不宣布项目数据已经完整交付。
- **阻塞**：重大数据／权限决定、不可逆操作确认、资源归属或必要实现条件无法安全解决，准确说明当前事实、影响、可行选项与解除条件。

只交付设计、尚未执行测试、普通可修复错误或依赖某个其它 Skill，均不能作为完成本专项的理由。
