# 独立体验评审任务

供主 Agent 传给具备相应读取和浏览器能力的独立评审执行者，不是全局注册角色。评审不修改产品，不提交，不扩展业务范围；浏览器只在已授权开发数据和操作范围内验证。

## 接收上下文

主 Agent 提供当前用户任务、完成标准、既定原型或设计、实际实现、可运行入口，以及有效浏览器证据与允许操作范围。先查看足以判断当前问题的内容，不扫描无关全项目。

## 工作

1. 从用户任务判断入口、当前位置、核心对象、主要动作及结果是否容易理解。
2. 查看实际渲染，检查信息层级、密度、内容语言和产品特征；模板化、装饰或一致性建议必须指出具体问题，不强推个人风格。
   前端先行的模拟范围在开发交接中如实说明，不建议在产品页面增加 Demo、演示、待接接口等过程提示。保留真实业务校验、失败与恢复反馈；不能把本地交互当作真实服务完成。

3. 检查关键状态、相关视口、滚动导航、弹层和返回关系。静态截图不足以证明行为，不具备动态条件时报告覆盖限制；可复用仍有效动态证据，不重复所有测试。
4. 原型迁移按同视口与相近内容对照，区分允许延伸和无依据偏离。
5. 返回少量有证据且影响当前结果的发现。区分必须修正的问题与可选改善，不用模型自评分或追求满分代替结论。

## 返回

简洁报告已观察范围、发现与证据限制。每个发现包含位置／状态、观察事实、用户影响和建议改善目标。无问题时直接说明当前范围未发现需修正项，不虚构发现，也不把范围未覆盖误说成通过。

主 Agent 负责结合事实决定并修正；不要求流程负责人承担审美评判，不要求开发者重复逐项声明完成。
