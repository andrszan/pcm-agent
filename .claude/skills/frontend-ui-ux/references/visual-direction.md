# 视觉方向与产品内容

## 先解释产品，再选择形式

先回答当前页面服务谁、处理什么、最重要的信息和操作是什么。确定主次后再选构图，不用组件库默认 gallery 决定产品外观。首页可以加强场景与品牌，高频列表和表单重视扫描及连续操作；一致不意味着所有模块同一布局。

## 首次方向选择与已有设计继承

只有尚无明确品牌或视觉方向的新设计才展开比较。先找出影响表达的具体事实：使用者怎样扫描与操作、内容的真实长度和密度、设备与环境、品牌语气及适用素材。不要仅凭“专业、可信、现代”接受通用工作台首选，再事后补理由。

从插件建议、可用参考和产品事实中形成少量有实质差异的方向，通常两个足够。在同一核心任务下，同时比较品牌色、中性色与辅助色的关系，以及排版、密度、构图或表面层次的差异。未指定品牌时，备选方向不能都沿用同一通用主色或仅作相邻色、明暗变体；区分色温、饱和度、强调范围和语义用途，再依据当前内容、资料或参考判断。只换主色不算不同方向，只换布局也不能省略配色选择；“专业、可信、效率”这样的通用词不能单独决定色相。指出各自适合什么、会牺牲什么，再选择更符合当前任务的一种。简短判断通常够用；难以判断的关键差异可做局部视觉小样，不默认制作多套完整原型或额外报告。

方向选择不是颜色抽签，也不是风格名词轮换。相似产品可以合理使用相似设计，绿色、蓝绿、紫色、卡片或渐变都不预先禁止；颜色应与产品表达和使用关系相符，而非为了与上一个项目不同而不同。调用方提供本地主题／preset 资源时，可提取安全的颜色、字型、几何和表面关系作参考，不直接搬入不适配当前栈的 CSS、selector 或运行依赖。

模板默认和初次检索结果只是候选，首次原型的设计仍需接受产品适配与体验评审。已有产品的稳定品牌及前序已经选定并交接的方向则直接继承，不为完成比较动作重新设计，也不要求补交选型历史。继承的是明确的品牌、层级、密度和交互关系；对比度、字体可用性、暗色状态或组件映射等实现细节可在授权内校准，不把每个偶然 CSS 值都冻结，也不借校准改换品牌或业务布局。

## 把设计术语转成可实施决定

需要为布局、风格、材质和细节选词时，按[设计术语与 Prompt 表达库](design-vocabulary-and-prompts.md)的相关分类查阅含义、适用边界与例句。将选择改写为当前对象上的关系，例如标题与元信息的权重、主次按钮的颜色角色、卡片的表面层次；已有设计则同时说明保留关系和允许校准的细节。术语释义集中维护在表达库，本文件负责产品适配与方向判断。

术语是沟通工具，不是风格清单。确定一个主要视觉方向，允许产品不同表面有适当变化，不堆互相冲突的关键词。

## 组件也要形成产品表达

设计不只发生在品牌首屏。后台、工作台、平台的列表行、卡片、筛选器、详情和高频操作同样需要精细处理；密度高、需要可信和效率不等于只能使用平淡的默认控件。

- 卡片按内容和用途设计层次：标题与元数据的字阶、内容和操作区的关系、表面与边框、角部与留白、可点击反馈。有价值时采用适量色面、纹理、渐变或图形细节，不把所有内容都装进同一种白色圆角盒，也不把不可点击卡片做成按钮。
- 按钮形成一致而有变化的体系：主操作、次操作、轻量操作及危险操作有明确权重；可用实色、浅色底、描边、文字和局部图标表达，品牌强调与辅助色按角色分配。相同语义跨页面保持一致，不为丰富配色把每个按钮随机染色；成功、警告和危险色不能被装饰用途混淆。
- 输入、分段选择、菜单与弹层处理完整状态：默认、悬停、键盘焦点、按下、选择、禁用及适用的忙碌／错误。间距、图标尺寸、边框、光学对齐和反馈落点共同决定精细程度，不只增加阴影或圆角。
- 先完成少量关键组件及其任务路径，再把成立的表达推广到同类。沿用现有组件语义和 primitives，不为定制外观重造基础交互，不为展示更多组件增加业务功能。

高级感不是单一审美模板。轻快、温暖、严谨、浓烈或克制都可以做得成熟；具体判断是层次是否成立、细节是否一致、主要操作是否清楚、动态是否连贯，并与当前产品相符。不要为了“克制”抹去所有有辨识度的细节，也不要靠装饰密度证明设计投入。

## 去模板化，不做视觉黑名单

检查是否因为默认套路而采用：居中大标题与双按钮、等大三卡片、没有业务作用的统计数字和图表、层层套框、全站同样渐变、装饰色条或无差别入场。若结构帮助真实内容与任务，可以保留；没有理由时重组信息，不只是换颜色。

不为了“拒绝 AI 味”禁止卡片、渐变、规整后台或熟悉交互，也不以随机不对称制造新颖。避免泛化的“数据概览”“赋能效率”等标题，使用真实业务对象、操作和关系。不要虚构客户背书、业务成果、用户评价或资质来填版面。

文案直接说明事实、行动和结果：统一相同对象与动作的称呼，明确状态与恢复。操作界面不默认给每个标题配副标题、每个模块配介绍、每张卡片配总结，也不自动添加英文眉题、欢迎口号、页脚价值宣言或括号里的教学说明。没有必要说明时，留白或更紧凑的布局都是正常结果。

逐段判断：删除后，用户会不会损失完成任务所需的事实、区分、规则或后果？标题、按钮、数据与布局已经表达清楚的意思直接删，不换成另一句空泛描述。例如“项目”下不再写“在这里管理你的所有项目”；“查看课程”按钮下不再写“点击查看课程安排”。这些例子说明重复关系，不是运行时关键词黑名单。

保留真实内容摘要、必要单位与统计口径、字段标签及非显然输入要求、价格或权限条件、危险操作后果、空态下一动作、校验错误和恢复途径。成功反馈按动作后果需要提供，不额外叠加鼓励口号；业务说明集中到实际需要的位置，不在标题、卡片和页脚重复。内容阅读、商品介绍或品牌叙事表面可以有适当篇幅，但每段应贡献真实信息，不虚构卖点填空。

文案过多先删重复、合并相同信息或改善组织，不能靠更小字号、低对比灰字、隐藏 Tooltip 或折叠关键规则达成表面简洁。字号用于信息层级，不用于把非必要解释挤进页面；关键规则不能只藏在 Tooltip 中。

## 图形、图标与媒体表达

主动寻找能增强识别、理解或产品气质的图形位置：对象类别、功能入口、卡片、空态、引导、内容封面及品牌区域。平台与后台同样可以使用定制 SVG、双色／多色图标、插画和生成图片，不只把图形留给官网首屏；没有现成合适素材时，结合当前设计使用工作区可用媒体工具生成并检查。

- 用可编辑 SVG 表达品牌图形、图解、状态标记及界面插画，按实际显示尺寸处理 viewBox、线宽、细节与留白。图标家族保持几何、笔画和光学重量协调，利用品牌色与辅助色丰富表达，相关业务含义仍一致。
- 区分操作图标、业务类别图形和装饰插画：操作可辨、与标签互补，状态不只靠颜色；装饰图形不抢主要内容，不把文字或必要控件烘焙进图片。
- 按页面容器设计生成图片的主体、构图、比例、文字留白和裁剪；先看实际结果，针对具体缺陷调整描述或制作，再把选定文件固化到产品资产位置。使用真实图片，不用占位色块或空引用冒充媒体交付。
- 在目标组件中检查图片的桌面／移动裁剪、叠字对比、加载失败、暗色适配与体积。保留恰当替代文本，纯装饰图形不制造重复信息；已有可用品牌资产和用户上传内容按原用途保留。

素材应带来内容或表达价值，而不是给已经完整的信息再加一层噪声。产品内容与真实用户上传内容区分，开发过程提示不进入界面。

## 观察结果

快速浏览页面，第一落点应与主任务一致。检查标题、正文、元数据、主要按钮是否有可辨差异；低频内容不抢核心操作。再用接近实际长度与数量的内容检查截断、换行、密度与视觉节奏。既有原型迁移使用相同视口、状态和内容对照，不把“用了同一主色”当作保真。
