# 视觉方向与产品内容

## 先解释产品，再选择形式

先回答当前页面服务谁、处理什么、最重要的信息和操作是什么。确定主次后再选构图，不用组件库默认 gallery 决定产品外观。首页可以加强场景与品牌，高频列表和表单重视扫描及连续操作；一致不意味着所有模块同一布局。

## 把设计术语转成可实施决定

| 术语 | 适用判断与落地方式 |
|---|---|
| 瑞士排版／International Typographic Style | 用清楚网格、对齐、字阶和留白组织高信息量内容；不是只把标题放大加粗 |
| 编辑式设计／Editorial | 以内容叙事、标题层级和图文节奏形成阅读顺序，适合介绍与阅读表面 |
| Bento Grid | 按内容关系及重要程度分配块面积，适合不同层级的能力或内容组合；不能随机拼卡片 |
| 新粗野主义／Neo-brutalism | 以强边界、实色和明确对比建立表达，适合有依据的个性品牌；不牺牲可读与操作反馈 |
| 玻璃拟态／Glassmorphism | 半透明与模糊形成前后层次；核验背景变化、对比和渲染成本，不给所有控件套玻璃 |
| 信息密度／Information density | 按扫描、比较、阅读和设备确定行高、间距、元数据权重，不把“留白多”当作质量通则 |
| 视觉层级／Visual hierarchy | 通过位置、尺寸、对比和分组，使预期重点最先被看到；不是全页一律粗体或亮色 |
| 渐进披露／Progressive disclosure | 保留常用操作与必要信息，将低频细节在需要时展开；不隐藏核心能力 |
| 设计令牌／Design token | 将颜色、尺寸等值的语义落在项目现有体系中，避免组件各自发明，不另外抄一份值表 |

术语是沟通工具，不是风格清单。确定一个主要视觉方向，允许产品不同表面有适当变化，不堆互相冲突的关键词。

## 去模板化，不做视觉黑名单

检查是否因为默认套路而采用：居中大标题与双按钮、等大三卡片、没有业务作用的统计数字和图表、层层套框、全站同样渐变、装饰色条或无差别入场。若结构帮助真实内容与任务，可以保留；没有理由时重组信息，不只是换颜色。

不为了“拒绝 AI 味”禁止卡片、渐变、规整后台或熟悉交互，也不以随机不对称制造新颖。避免泛化的“数据概览”“赋能效率”等标题，使用真实业务对象、操作和关系。不要虚构客户背书、业务成果、用户评价或资质来填版面。

文案直接说明事实、行动和结果：统一相同对象与动作的称呼，减少重复解释，明确状态与恢复。不用口号、套话、夸张比喻、装饰性引号和词语堆叠凑内容；关键规则不能只藏在 Tooltip 中。

图片、插画、SVG、摄影或适当图形可以建立产品辨识度。先评估现有素材、任务收益、成本和写入范围，选择适用的资产，不默认给每页配图。产品内容和实际用户上传内容区分，开发过程提示不进入界面。

## 观察结果

快速浏览页面，第一落点应与主任务一致。检查标题、正文、元数据、主要按钮是否有可辨差异；低频内容不抢核心操作。再用接近实际长度与数量的内容检查截断、换行、密度与视觉节奏。既有原型迁移使用相同视口、状态和内容对照，不把“用了同一主色”当作保真。
