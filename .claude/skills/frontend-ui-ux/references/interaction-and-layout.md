# 布局、导航与交互

## 滚动后的界面也必须设计

承担全局导航、上下文识别或高频核心操作的顶部栏，默认在主要内容滚动时保持可见、可操作。让它离开视口应有当前页面的明确体验理由，不因遗漏滚动设计而发生。

- 长官网默认主导航吸顶，不固定整个 Hero；主入口在滚动后仍可达。
- 后台／工作台一般保留应用导航及必要上下文，主要内容在约定区域滚动；不把所有工具栏永久占在屏幕上。
- 沉浸阅读或特殊展示可以采用普通文档流、按需出现等方式，按产品任务选择，不逐页索取批准。

先确定滚动所有者、常驻区域、表头与导航偏移及弹层关系，再选 CSS：文档流导航常可用 `sticky`；工作台可分区布局；需要相对视口固定时用 `fixed` 并留出占位。祖先 overflow、容器高度及层叠上下文会改变表现，不能以声明了属性证明效果。

实际滚动检查导航、表头、侧栏和浮层不遮挡彼此；锚点目标与获得焦点的内容不藏在顶栏后面。窄屏常驻区域不能吞掉主要操作空间；只有表格、代码等确有必要的局部容器横向滚动，避免整个页面横向溢出。减少没有任务理由的嵌套滚动。

## 按任务组织操作与内容

- 全局导航、页面内筛选、对象操作各有归属，避免在顶栏堆保存／删除。
- 入口、当前位置、返回关系清楚；回到列表保留适当筛选和滚动上下文。
- 主要操作突出，低频和危险操作不与其抢层级；危险操作按已确定语义确认。
- 用真实业务术语和有意义内容，不靠空泛说明或 Tooltip 解释整套功能。
- 表单用可见标签及字段附近错误，避免只靠 placeholder；能推导的信息不重复输入。
- 同一任务在窄屏需要重排、收纳或改变信息优先级，不仅缩小字体并堆成长页。

## 状态与数据

选择当前任务相关的加载、空态、无结果、校验、提交中、成功、失败、失权或冲突；只读页面不机械套用完整写操作状态。错误说明原因及恢复方式，失败后保留合理输入，防重复提交，结果未知时不假装成功。

前端先行允许集中、连贯的模拟数据：创建后可读取，更新后相关页面同步，搜索／筛选有结果及无结果，状态反馈有意义。身份选择或失败触发等开发控制放在测试入口、工具或夹具中，不作为正常产品页面上的“演示模式”。不通过假倒计时或人为延迟强制表演加载。

真实接口接入时核验业务状态、分页、字段语义与错误映射，不只替换 URL。明确当前能证明的是前端行为还是完整业务结果。

## 输入与基本可访问性

相关功能支持键盘、可见焦点、合适触控区域和非纯颜色表达。移动菜单能打开、关闭并恢复合理焦点；弹层处理 Escape、焦点进入／返回以及背景操作隔离。对比、缩放和长内容可读，动效尊重减少动效设置。

## 浏览器检查

实际完成主任务和风险相关状态，至少检查代表性宽屏与窄屏、滚动后及长内容布局。先用动态操作证明行为，再读取渲染；未查看的截图、DOM 数量与构建成功不能替代效果判断。浏览器检查不重复全部服务端测试矩阵。
