# 插件调用与委派

## 显式调用，不依赖自动触发

页面、组件或模块设计与界面代码开发，先调用主要入口。任务里 slash 形式用于明确匹配；执行时使用 Skill 工具的真实标识：

```text
任务首行：/ui-ux-pro-max:ui-ux-pro-max
Skill 工具：skill = "ui-ux-pro-max:ui-ux-pro-max"
```

先确认实际环境已加载插件、入口可见且执行角色有 Skill 工具。一个自定义 Skill 的工具声明不会自动扩大子 Agent 权限。CLI 和 SDK 的插件加载方式由调用方环境配置提供，不猜测用户目录或把本机绝对路径写入产品。

找不到主要入口时报告插件未加载、入口不可见或工具权限不足的具体事实，不能用同名目录、阅读正文或搜索脚本代替调用并宣称已匹配。调用成功后可以依据插件指令读取资料和运行脚本。

## 按任务选择入口

| 完整 slash 名称 | 职责与使用条件 |
|---|---|
| `/ui-ux-pro-max:ui-ux-pro-max` | 默认主要入口；布局、视觉、交互、响应式与技术栈相关建议 |
| `/ui-ux-pro-max:brand` | 需要建立或调整品牌表达、语气、视觉身份时 |
| `/ui-ux-pro-max:design-system` | 需要确定共享 token 职责或组件表达时；不重复生成既有规范 |
| `/ui-ux-pro-max:ui-styling` | 实际栈与其组件建议兼容的样式及界面实现任务 |
| `/ui-ux-pro-max:design` | 包含多类品牌资产的综合任务；不因开发页面就全量调用 |
| `/ui-ux-pro-max:banner-design` | 明确需要横幅、封面等视觉资产时 |
| `/ui-ux-pro-max:slides` | 调用方明确要求演示文稿时，不作为产品页面入口 |

专项入口是按需补充，不替代前端设计主要入口。以当前加载的插件正文核验参数与依赖，不维护工具版本、知识条目数量或所有命令副本。

`ui-styling` 的建议可能采用 Radix，而目标工程可能采用 Base UI 或其他组件体系。不要为调用插件更换现有 primitives、框架或样式系统；不兼容时不调用该专项入口，继续使用主要入口的适用建议。

## 从建议落实到工程

- 提供产品对象、任务场景、阅读／操作密度和实际技术栈，不只搜索“现代 SaaS”。
- 首次设计按插件要求获取设计体系建议，再根据产品挑选；已有设计时保留基线，查询本次相关维度，不把推荐默认值提升为强制迁移。
- 搜索脚本从插件提供的真实路径执行，不硬编码 `~/.claude/skills/` 或假定工作目录。缺结果时按插件建议扩大检索，不编造。
- 推荐写入需要长期协作的工程位置即可。不默认启用插件的持久化或强制覆盖选项，不创建与项目既有框架、主题和代码重复的真源。
- 插件中需要额外工具、账号、生成服务或人工选择的分支，按授权及真实环境处理。不因插件建议就安装新工具、添加产品凭据或引入额外人工审批；无关分支跳过，必要条件缺失如实交接。

## 给开发子 Agent 的调用要求

在专业任务的开头明确列出实际需要的完整入口，并要求先调用再编码。例如：

```text
/ui-ux-pro-max:ui-ux-pro-max

先通过 Skill 工具实际调用上述入口，再完成下述界面任务。
……产品目标、设计依据、关键行为、工程边界、验证要求……
```

同时提供适用规则和工程资料。主 Agent 已调用插件不等于子 Agent 调用过；子 Agent 是否可用取决于自身工具和插件环境。明显的调用错误要解决，不添加固定完成口号、逐项声明或长期调用日志作为产品交付物。
