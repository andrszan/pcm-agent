# 体验评审与定向精修

## 先自查，再独立看结果

实现者先完成实际预览与相关检查。完整原型、完整前端和重要模块由主 Agent 提供分离上下文的体验评审；局部修改按影响相称检查，不每次全项目重审。

评审输入是当前用户任务、完成条件、既定原型／设计与已实现版本、可操作环境及有效证据。截图可判断静态呈现，动态交互需要真实操作或可复现动态证据。缺失范围明确说明，不据静态截图断言交互通过或失败。

独立评审针对体验，不重复全量工程审计。重点观察任务理解、信息层级、产品辨识度、状态与操作、原型偏差、相关设备与滚动。不要默认审查未授权产品范围或要求外部账号。

## 可执行发现

每项意见说明页面／状态或代码位置、实际观察、对用户的影响，以及建议验证的改善目标。区分实际问题和可选偏好，少量优先项胜过无差别长清单。

例如“滚动到订单列表后顶栏消失，跨模块入口不可达，应保持导航可用并验证锚点无遮挡”，而不是“不够精致”。评分只能辅助描述，不以某个分数作为完成条件。

## 主 Agent 裁决与修改

先处理阻碍任务或违反既定设计的问题，再处理有依据、成本相称的视觉改善。主 Agent 可接受、调整或不采纳建议，按当前产品事实决定；评审不授权扩大范围。

一轮围绕一组内聚发现修改，保留已成立的结构、品牌和功能。修正后复验原场景及受影响范围，不默认全页重生成。自查与独立评审可以复用仍有效证据，避免每个参与方重跑全套测试。

任务完成条件满足、采纳问题解决并验证后结束，不为追高分、等价偏好或更多装饰追加轮次。若反复修正仍无明确改善，停止重新设计，定位具体剩余问题、比较更简单办法；必要条件缺失如实交接，不能以“打磨到极致”为由无期限继续。

## 开发交接

执行 Agent 对设计、实现和验证负责。交接说明成果、实际证据与剩余事项，不要求负责人或调用方再评审审美、逐项核对测试或回复完成口号。不默认生成评审流水文档；稳定决定与缺口进入现有授权记录位置。
