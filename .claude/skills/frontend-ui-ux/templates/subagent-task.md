# 前端子任务委派

主 Agent 派发前完成任务说明。默认使用下列主要入口，按实际需求增补专项完整名称；执行前确认接收方具备工具与插件。任务大小决定说明深度，不为几个样式改动填长表。

选词与设计片段见[设计术语与 Prompt 表达库](../references/design-vocabulary-and-prompts.md)。先按当前任务查阅相应分类，再把选定表达写成实际对象上的要求；主 Agent 传递已确定的设计与局部探索空间，子 Agent 按需查阅相关条目。不把整份表达库粘进任务，也不要求每个任务采用示例风格或参数。

```text
/ui-ux-pro-max:ui-ux-pro-max

先通过 Skill 工具实际调用上述入口，再实施本任务。不可用时准确报告缺少的调用条件，不以读文件或搜索脚本冒充调用。

用户与结果：谁在什么场景下，需要完成什么，怎样判断成功。
本次范围：负责的页面／模块／组件，与上下文的关系；不改什么。
设计依据：首次设计还是继承／精修；可读取的原型、当前代码、主题、组件和适用规则路径；选定方向及产品依据、哪些保真、哪些允许校准。尚无明确方向的新设计先简短比较适合本任务的不同方向，再选定；已有方向不重做选型。
信息与操作：主要信息、主操作、低频内容；把选定布局和视觉语言落实到对象、阅读顺序、字阶、颜色角色、密度或表面中的相关维度。写出需保留的关系与可调整细节；参考中的观察与推测分开。文案只保留有任务价值的事实、标签、规则及结果，不自动补副标题、卡片说明或装饰小字，不重复标题和按钮已表达的意思。
组件与动态：点明本任务的关键组件及可见变化，例如卡片内层级、按钮主次、选中与焦点的区别。对关键交互说明触发、对象、起止状态与节奏，按需要补充编排、中断／反向及减少动效替代；具体参数可按实际渲染校准。平台界面同样需要打磨，不默认退回组件库原样。
图形与媒体：适合的定制SVG、多色图标、插画或生成图片，用途、风格关系与资产落点；取得后实际查看并验证在目标组件中的呈现。
行为与数据：相关状态、操作结果、返回关系、数据访问方式和权限呈现；已确定的业务约束。
工程归属：实际技术栈、可复用能力、共享文件负责方和授权改动范围。
验证与交接：局部用户路径、适用视口、滚动和状态检查；主 Agent 负责的整合／独立评审。
```

## 例：维修工单队列

```text
/ui-ux-pro-max:ui-ux-pro-max

先实际调用上述 Skill，再实现工单队列模块。

使用者是维修协调员，需要找到应优先处理的工单并安排维修。沿用调用方提供的原型、主题与组件资料，保持全局导航和品牌，不重设计 Shell。

列表采用适合比较的行式布局，用字阶、对齐和语义对比突出工单对象、优先级、状态及下一动作；次要时间和备注弱化。不要用无任务价值的统计图占据首屏。保留常用搜索及状态筛选，低频条件渐进展开。

覆盖筛选无结果、详情查看、安排维修及失败保留输入。使用传入的数据访问边界；前端先行数据保持列表与详情同步，产品文案不出现模拟、原型或等待接入说明。

在现有列表—详情结构内，选中行用品牌浅色面和清楚标记表达，悬停与键盘焦点可区分。打开详情立即反馈；已展开时连续换单只更新内容，不重复播放整块入场。快速关闭从当前视觉状态继续，真实加载与失败原位呈现；减少动效时保留完整状态。保持品牌、字段和流程，允许校准局部间距、边界明度及过渡节奏。

按实际工程的路由和模块归属实现，复用共享组件，不替换技术栈或 primitives。共享导航由主 Agent 维护；发现必要变更先交接，不同时改写。

验证宽屏与窄屏上的搜索、详情、安排及返回，补查连续换单、动画中关闭、失败重试与键盘焦点。实际滚动长列表，确认全局导航可用，表头不遮挡正文或弹层。完成本模块局部检查并读取实际渲染；主 Agent 统一整合和独立体验评审。不提交、不推送。
```

已有功能精修时，把任务目标替换为具体缺陷与需保持的行为，不暗示允许全页重构。路径由主 Agent 根据现场填写，示例不冻结真实目录或业务规则。
