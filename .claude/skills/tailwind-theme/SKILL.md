# tailwind-theme — 项目专属 Tailwind 主题配色

## 定位

这是一个可独立调用的 Tailwind CSS v4 主题配色能力。它读取产品定位、目标用户、使用场景、已有设计资料和真实前端工程，选择适合的 tweakcn 内置主题或生成一套自定义颜色，并把完整的 light/dark 语义颜色落实到项目实际使用的全局样式入口。

目标是让项目从初始化开始就具有与产品相符、可继续演进的主题配色，而不是沿用模板默认色。light 和 dark 始终是同一个交付合同，不询问是否需要 dark mode，也不允许只完成其中一种模式。

本能力可以在新项目初始化或已有项目重新定制主题时使用，不依赖固定上游、下游、文件路径或其它自定义 Skill。

## 职责与边界

本能力负责：

- 从项目目标、用户、任务、内容密度、使用环境和明确品牌约束中提取视觉方向；
- 读取已有产品级 UI/UX 决定、品牌资料和当前 token，但不要求这些资料必须存在；
- 识别实际前端仓库、Tailwind CSS v4、活动全局样式入口、主题切换方式和语义颜色合同；
- 从 tweakcn 当前主题 registry 中筛选少量候选，核验真实 light/dark token 后选择适配项；
- 没有合适 preset、网络不可用或远程数据不合格时，根据项目事实生成自定义 light/dark 配色；
- 只修改语义颜色变量及确实缺失的 `@theme inline` 颜色映射；
- 验证颜色完整性、语义对比、构建和适用的真实 light/dark 渲染。

本能力不负责：

- 定义产品目标、功能范围、信息架构、App Shell、导航或页面布局；
- 修改字体、字阶、圆角、阴影、间距、tracking、动效、图标或媒体；
- 重构组件、页面、业务功能、主题 Provider 或主题切换交互；
- 把单个 preset 的第三方品牌、Logo、文案或素材带入目标产品；
- 处理 Tailwind CSS v4 CSS-first 之外的主题结构、版本迁移或主题基础设施改造；
- 创建主题报告、Manifest、TRD、Backlog、提交或 push。

已有产品级视觉方向时，将其作为最高优先级的目标输入；没有时，本能力可以根据充分的项目事实形成低风险、可替换的初始主题。改变明确品牌方向、已发布客户定制或兼容合同时，应先说明影响并等待相应决定。

## 输入与事实优先级

调用方可以提供任意组合：

- 项目名称、产品定义、目标用户、核心任务和主要使用环境；
- 已有 UI/UX 框架、品牌资料、设计稿、截图或主题要求；
- 偏好或禁用的色相、气质、饱和度、对比度和行业约束；
- 希望使用的 tweakcn 主题 slug；
- 根目录、前端目录或候选全局样式文件。

不要求调用方提供“是否支持 dark mode”，也不要求手写主题 JSON。light/dark 均为必需输出。

事实优先级：

1. 用户本轮明确给出的品牌和主题要求；
2. 当前有效的产品与 UI/UX 决定；
3. 当前代码、配置、主题切换和实际渲染；
4. 项目目标、用户、任务和内容特征；
5. tweakcn preset、模板和通用色彩经验。

不得仅凭项目名称、行业标签或“AI/SaaS”等泛化词自动选择蓝紫渐变、玻璃效果或高饱和科技色。

## 目标工程合同

本能力面向 Tailwind CSS v4 CSS-first 工程，目标样式入口通常同时具备：

- `@import "tailwindcss"`；
- `:root` 中的语义颜色变量；
- `.dark` 或项目现有等价 dark selector 中的语义颜色变量；
- `@theme inline` 中 `--color-*` 到普通 CSS 变量的映射。

文件不固定为 `frontend/app/index.css`。必须从依赖、样式内容和应用入口 import 关系确认真正生效的文件。若存在多个可能的活动主题源、找不到唯一全局入口、dark selector 不明确或工程不是 Tailwind CSS v4，不猜测、不新建平行主题入口，停止并报告证据。

实际交付的颜色集合由活动 CSS、`@theme inline` 映射、真实 utility/组件消费者和调用方合同共同决定。tweakcn 的 32 个标准颜色名只是远程数据允许读取的最大白名单，不是要求所有项目机械新增的固定输出：本仓默认模板已经包含这 32 项时必须完整更新；目标工程没有 chart、sidebar 等消费者时不为凑数新增；项目已有 `success`、`warning` 等额外语义颜色时，应依据同一配色方向在本地生成并同步更新，不能从远程未知字段导入，也不能留下与新主题冲突的旧默认色。具体白名单和数据边界见 [`references/theme-selection.md`](./references/theme-selection.md)。

## 工作协议

### 1. 保护仓库与识别入口

开始前分别确认根仓库和前端仓库的规则、Git 状态及用户已有修改。读取足以判断主题事实的：

- `package.json`、锁文件和 Tailwind 相关依赖；
- 应用根布局、入口模块和全局 CSS import；
- 含 `@import "tailwindcss"`、`:root`、dark selector、`@theme inline` 或语义变量的样式文件；
- 现有 ThemeProvider、class/data attribute 切换和持久化方式；
- 代表性页面及实际使用的语义颜色 utility。

同一文件混有用户修改时只做可核对的小范围编辑。不得用重新初始化、全量生成或覆盖整份 CSS 的方式应用主题。

### 2. 提取项目视觉方向

从真实资料中形成一条简短、可执行的方向，至少考虑：

- 谁长时间或高频使用产品；
- 核心任务偏操作、判断、阅读、创作还是展示；
- 信息密度、主要设备和使用环境；
- 产品需要表达的可信、克制、活力、自然、精致或技术感；
- 已确认品牌色、禁用色、行业语义和现有客户定制；
- 状态、图表、焦点和 dark mode 的可辨识要求。

方向只服务本次颜色判断，不创建独立设计文档，也不扩展为字体、布局或组件方案。

### 3. 选择 preset 或自定义生成

默认先按需读取 [`references/theme-selection.md`](./references/theme-selection.md)：

1. 根据项目方向从动态 registry 筛选不超过三个可信候选；
2. 读取候选实际 `cssVars.light` 和 `cssVars.dark`，不能只根据名称或分类判断；
3. 只有 preset 的主色、表面层级、状态语义、图表与 dark mode 都适合项目时才采用；
4. 没有明显适配项、显式品牌要求无法满足、网络不可用或远程数据校验失败时，直接生成自定义主题；
5. 不为“优先复用模板”勉强采用相近但不合适的 preset。

自定义生成同样必须先形成完整、可验证的 light/dark 颜色集合，再修改文件。远程读取失败不触发其它未知主题网站、工具安装或第三方 Skill。

### 4. 建立完整 light/dark 配色

light 与 dark 应分别校准，而不是相互机械反转。至少保证：

- `background`、`card`、`popover` 具有清楚而克制的表面层级；
- `foreground` 及各 `*-foreground` 与对应背景保持可读对比；
- `primary` 表达核心操作，不自动成为大面积装饰背景；
- `secondary`、`muted`、`accent` 各有明确语义，不是随意的近似色；
- `destructive` 保持危险语义，不随品牌主色任意变化；
- `border`、`input`、`ring` 在两种模式中都可辨识，焦点不会消失；
- 五个 chart 颜色在常用图表中可区分，不只做难以辨认的连续明暗；
- sidebar token 与主表面一致，同时保留导航选中和焦点层级。

若选中 preset 缺少目标工程已经要求的颜色 token，应在同一配色方向内补齐；不得删除现有语义变量或用模板默认值悄悄填充。无法形成完整且自洽的两套主题时保持文件不变。

### 5. 原子应用主题

写入前先在内存中完成两套 token 和校验，然后一次性小范围编辑：

- `cssVars.light` 或自定义 light token 写入现有 `:root`；
- `cssVars.dark` 或自定义 dark token 写入现有 dark selector；
- 保留项目当前 `.dark`、`[data-theme="dark"]` 或其它明确策略；
- 保留 `@custom-variant dark` 的现有写法；
- 已有 `@theme inline` 时只补当前实际使用且缺失的 `--color-X: var(--X)`；
- 不整体重写 `@theme inline`，不触碰其中的 font、radius、shadow 或其它映射；
- 不消费 tweakcn 的顶层 `css`、`cssVars.theme` 或颜色白名单之外的字段；
- 不把远程 CSS、未知选择器、注释、at-rule 或非颜色变量写入项目。

任何一套模式的数据不完整、值不安全、目标 block 匹配不唯一或编辑无法保持现有结构时，必须零修改结束，不能留下半套主题。

## 验证

完成前按项目实际能力执行：

1. **结构检查**：light/dark 均包含目标工程要求的全部语义颜色变量，没有重复声明、漏项或只改单侧；
2. **边界检查**：diff 只包含允许的颜色值和必要颜色映射，字体、圆角、阴影、spacing、tracking、其它选择器与 import 保持不变；
3. **语义对比**：检查主要背景/前景组合、按钮、危险操作、muted 文本、边框和焦点在两种模式中的可读性；正常正文目标至少满足 WCAG AA 4.5:1，非文本控件和焦点目标至少满足 3:1；
4. **工程检查**：运行项目已有格式、静态检查、测试和构建中与改动相关的命令，不为验证新增运行时依赖；
5. **真实渲染**：项目可运行时，在真实浏览器中分别切换 light/dark，读取代表性页面的实际渲染和 computed color，并检查控制台及失败网络请求；
6. **回归检查**：确认主题切换机制仍工作，字体、圆角、阴影和布局没有因 preset 导入发生变化。

涉及浏览器验收产生的临时截图时，遵循目标项目已有的测试截图约定。无法执行真实渲染时，准确说明未验证范围，不以 CSS 阅读或构建成功代替 light/dark 视觉结论。

## 结束状态

- **已完成**：项目方向有依据，light/dark 完整落地，diff 边界正确，并通过适用构建和真实渲染验证；
- **已实现但未完全验证**：颜色已经安全写入并通过静态或构建检查，但真实浏览器、目标页面或其它必要条件不可用；
- **阻塞**：无法唯一识别活动主题入口、不是支持的 Tailwind v4 合同、项目事实不足以安全形成方向、已有修改冲突或无法原子应用完整 light/dark。

最终只汇报主题来源（tweakcn slug 或 custom）、选择依据、实际修改文件、light/dark 完整性、执行的验证和真实限制。本能力不暂存、不提交、不推送。
