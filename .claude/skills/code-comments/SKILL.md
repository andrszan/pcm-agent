# code-comments — 必要代码注释整理

手动调用后，全量检查目标项目适用的手写维护代码，按需补充、修正或删除普通说明性注释。让维护者理解代码本身不能清楚表达的约束，而不是给每个文件、类或方法补齐说明。充分检查后没有值得修改的注释，也可以完成。

独立完成范围确认、证据阅读、编辑、验证和交接，不依赖其它自定义能力或固定格式的设计材料。不接入主流程，不创建或修改 Backlog、TRD、专属 Manifest、运行报告或注释规范文档；不暂存、提交、推送，不建或切换分支、合并或改写 Git 历史。

## 确认输入与全量范围

- 从调用方取得目标项目、授权仓库／目录、禁止修改区域及已知约束；缺少信息时先查项目事实。仅在归属或授权不能安全判断时请求澄清，不把当前工作区的所有仓库默认为目标。
- 读取目标项目的维护说明、语言与框架、现有注释惯例、检查配置和验证命令；分别检查各仓库分支以及 staged、unstaged、untracked 状态，记录编辑前基线。已有修改不是自动排除整个文件的理由，但必须按当前内容增量编辑，不还原、覆盖、暂存或夹带他人改动；无法安全分离的区段保持不动并交接。
- 结合版本控制文件列表、未跟踪但属于本项目的手写文件和实际目录结构，枚举适用文件并按模块分组。逐个阅读适用文件，必要时分段，不能用关键词搜索、只看 diff、公开方法或抽样阅读冒充全量检查。搜索用于找调用关系，不代替文件检查。
- 排除依赖目录、构建产物、生成代码、外部快照、第三方原文及非本项目维护内容；不改原始版权头。测试、手写迁移和脚本按维护归属及实际约束纳入，不按目录名一概排除。对受校验和或不可变约定保护的历史迁移只读。
- 不为整理注释读取秘密配置或个人数据，不把凭据、真实业务数据或私有环境细节写入注释、输出和命令日志。跨仓库阅读也必须在读取授权内，不追随链接进入未授权目录。

在当前会话中维护已检查、排除及尚未检查的范围即可，不落盘建立新台账。规模超过可用时间或上下文时按模块继续；确实无法完成时报告剩余范围，不静默缩小“全量”的含义。

## 用事实判断是否值得写

每处候选先读实现、实际调用方、相关测试，以及解释该约束所必需的现有契约或设计依据；涉及事务、权限、异步链或兼容时沿调用链核对约束由谁建立、在哪里失效。文档与代码不一致时明确差异，不能只凭旧文档写成现有保障。

仅保留维护者无法直接从清楚的命名、类型和控制流得知，且有证据支持的信息，例如：

- 调用前必须由外层持有的事务或锁，以及作用范围；
- 金额、时间、状态等业务口径及边界；
- 外部副作用、失败后的实际状态、重试限制；
- 并发顺序、资源生命周期、兼容处理及已证实的原因。

写在最靠近约束且便于维护的位置；共享约束优先写在权威实现或接口处，不在所有调用点复制。只解释必要的“为何”或不明显的合同，不逐行翻译代码，不重复签名和类型，不添加无依据的安全、性能、原子性或幂等承诺。不堆积日期、修改流水、装饰分隔线、模板 TODO 或空洞章节。

已有注释准确且有价值则保留；重复、明显误导或过时的普通说明可按事实精简或修正。无法核实历史动机时不猜测；疑似业务 Bug、缺少保障或证据冲突时，不编造理由把缺陷合理化，也不通过注释宣布尚未实现的合同。保留必要疑点和代码位置供交接，能安全处理的其它模块继续。

## 编辑边界与语言适配

只调整必要的普通说明性注释。保持命名、类型、签名、逻辑、配置、依赖、测试断言和其它代码内容不变；不顺手修 Bug、重构、移动代码或格式化全仓。发现必须改代码才能成立的注释需求，停止该处编辑并交接，不扩大任务。

默认沿用目标项目的注释语言，本工作区使用中文；语言风格、排版和文档格式优先遵守现有检查与惯例，不统一翻译已有注释。按所遇语言查阅[语言适配参考](references/language-conventions.md)，不机械套用同一种文档注释模板。

“只改注释”不代表没有行为影响。先识别编译、类型、lint 抑制、覆盖率、代码生成、打包、格式化及工具标记等特殊注释，保持内容、位置和附着关系不动；不在敏感指令与目标语句间插入说明。框架读取的描述、公开文档契约、可执行示例和运行时消费的 docstring 也不作为普通文本随意改写。确实需要改变这些内容时说明消费方与影响，交由另行授权的任务处理。

## 统一标准与有限并发

先统一一次范围、证据要求、注释语言、禁止修改项和验证安排，再按内聚模块分工。小项目直接串行；仅在可用子代理和任务规模适合时有限并发，不按文件无限拆分。

每个执行者取得明确且不交叉的文件写集合、已有修改基线与跨模块依赖信息。允许在授权内跨模块阅读，共享文件指定唯一写入者；发现需要越出写集合时交回协调者，不自行抢写。模块返回已检查范围、实际改动、未改原因、证据位置和疑点，不能只返回修改文件列表。协调者据此核对全部适用文件的覆盖与遗漏。

## 整合验证与独立复核

整合后统一执行一次适用检查，避免各模块重复全仓构建：

1. 对比编辑前基线和最终差异，确认只有本次授权的普通注释变化，原有修改、特殊注释及其附着关系均被保留。逐处复查注释与实现、调用方和测试一致，且无不必要重复；不能仅靠删掉注释后文本相等断言没有行为影响。
2. 按语言及消费路径运行现有适用的语法、静态、类型检查、测试或构建；可能涉及文档消费时核验对应输出／接口没有意外变化。检查命令先确认副作用，使用检查模式而非自动修复，不为验证更新快照、断言或生成文件。若验证必须产生越界改动，保留原文并交接限制。
3. 对最终变更进行独立只读复核，优先由未参与编辑的可用审查者核查价值、事实、覆盖和行为影响；提供当前完整差异、范围与证据。不依赖固定角色或其它能力。没有独立审查通道时自行完成单独一轮复查，并明确独立复核尚缺，不能把自审称为独立审查。

发现本次引入的问题只修正本次注释，并重跑失败项与受影响检查；已有代码缺陷或必须改变非注释内容的问题只带证据交接。不得用修改配置、删断言或忽略失败来制造通过。环境缺失时如实报告尝试、缺少条件和补验方式；无改动时依据实际范围说明检查适用性，不编造执行记录。

## 简短交接

最终直接返回，不另写报告文件：

- **范围**：涉及仓库与模块、实际全量检查范围、排除项和剩余缺口；未检查完不得宣称全量完成。
- **改动**：主要文件及注释解决的理解问题；无改动则明确说明。
- **未改原因**：概括代码已清楚、已有注释足够、证据不足或特殊消费边界，不为每个未改文件写流水。
- **证据与验证**：关键调用方／测试等位置、实际运行的检查及结果、独立复核情况；复用证据标明来源和仍适用的依据。
- **待交接**：疑似缺陷、需要另行授权的改动和未验证范围及补验条件；没有则写无。
