# 语言适配参考

只查目标项目实际使用的语言。以现有检查配置、附近惯例和真实工具消费方式为准；下列提醒不是要求给所有公开符号补文档。普通说明之外的特殊注释保持不动，需要改变时交接。

| 语言／场景 | 适配重点 |
|---|---|
| TypeScript／JavaScript | 不用 JSDoc 重复已有 TypeScript 类型，只补不明显的语义约束。JavaScript 的 JSDoc 可能直接参与类型检查，`@ts-*`、三斜线指令、lint 指令、打包器魔法注释及纯函数标记不是普通说明。React 的请求时序要读 effect 清理、取消与状态写入链，不能把取消请求等同于禁止所有过期结果提交。 |
| Python | 普通 `#` 注释优先沿用项目惯例。docstring 是可通过 `__doc__` 读取的字符串，可能进入 CLI 帮助、框架路由描述、OpenAPI、doctest 或其它运行时输出；新增与改写前追踪消费方，不能证明是纯维护说明时保留原文。编码声明、shebang、类型和 lint 指令保持不动，不用无效字符串表达式冒充注释。 |
| Java／Kotlin | Javadoc／KDoc 可生成公开 API 文档并被插件读取；链接、标签与参数语义需符合项目检查。只补类型未表达的合同，不更改注解、抑制指令或代码生成标记。 |
| Rust | `///`、`//!` 会进入 rustdoc，代码块可能作为 doctest 编译执行，文档属性也可能被宏消费。不要将普通说明改成可执行示例或变更文档属性。涉及 `unsafe` 时先核实调用方和具体安全前提，不能用一句“安全”替代证明。 |
| Go | 公共符号说明沿用项目已有命名开头惯例，正文语言遵守项目规则。`//go:build`、`//go:generate`、其它 `//go:` 指令、旧式构建标签及位置要求均保持不动；cgo 的前置注释可能包含实际编译输入，不能当普通说明改写。 |
| C／C++／C# | Doxygen、XML 文档、分析器标记可能影响工具输出，不能批量更换注释格式。注意预处理续行、注释分隔符和文档附着位置；核对所有权、生命周期或平台兼容事实后再写说明。 |
| SQL／Shell／模板与样式 | 数据库方言的提示／可执行注释、迁移校验和、shebang、Shell 检查指令及模板工具标记保持不动。Shell 续行和 heredoc 中的文本不一定是注释，HTML 注释可能实际发送给客户端；不要将敏感细节放入可见输出。 |

有歧义时先确认语法与消费链。不能确认不会影响运行、接口、编译或工具结果时，不新增／改写该处，交接准确位置和缺少的证据，而不是套用“注释不会执行”的假设。
