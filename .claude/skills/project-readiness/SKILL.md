# project-readiness — 项目准备状态与清单维护

## 定位

这是一个可独立调用的项目级准备能力。它根据调用方资料和当前项目事实，识别整个已确认项目周期中开发、联调、真实体验验收和交付所需的条件，匹配调用方实际提供的外部资源，主动完成能够安全执行的准备、配置与核验，并建立可复核的准备清单。

同一项目周期只建立一次完成的准备基线。一次尚未完成的准备工作可以在原现场继续补齐和核验；已经存在完成基线时，不重新执行资源创建、凭据派生或配置写入，也不把后续范围变化伪装成清单更新。调用方必须先明确这是原任务恢复、旧基线无效，还是一个新的项目周期。

准备清单是实际准备结果的脱敏账本，不是本能力的唯一动作，也不能为自身状态作证。资源、权限或配置只有经过实际准备并取得相称证据后才能标为就绪。

本能力不替项目补做产品或技术决策。资料不完整时可以核验有证据的部分，但整个项目周期必需且尚未决定、提供或验证的条件必须保留为阻塞，不为填满清单虚构依赖、资源或替代方案。

## 核心原则

1. **事实优先**：代码、配置、测试、迁移、运行结果和调用方明确确认高于说明性文档与猜测。
2. **覆盖完整周期**：从当前已确认的产品范围和交付目标判断项目化、开发、联调、真实体验验收和交付所需条件，不因某项资源暂时尚未被当前模板消费就遗漏。
3. **资源动态发现**：调用方提供的资源资料只是本次可用的动态候选池，不是 Skill 内置目录；不预设其文件名、格式、字段、资源类型、服务名称或变量名。
4. **只使用已确定合同**：根据已确认能力要求、技术事实和项目配置方式匹配资源；只有候选满足既定兼容合同才可直接替代，改变产品语义、技术边界、安全、成本或运行方式的替代必须保持待决定。
5. **先执行后定状态**：能安全检查、创建、配置或验证的事项应实际执行。没有工具结果、可复核文件事实或调用方明确确认，就不得标为 `ready`。
6. **最小权限与最小暴露**：优先使用项目专用、环境隔离、可撤销的运行凭据；管理凭据只用于明确授权的准备动作，不作为应用运行凭据。
7. **真实证据**：工具存在、资源说明、Mock、静态数据、文档自述或截图不能替代真实服务、真实权限路径、真实配置和真实浏览器行为。
8. **唯一基线**：基于本次可访问事实为一个项目周期建立唯一、完整、可追溯的准备基线；只允许继续同一次尚未完成的工作，不依赖隐藏状态，也不重复执行已经完成的基线。

## 可接受的输入

调用方可以提供任意组合：

- 产品目标、最终范围、用户流程、验收要求和交付约束；
- 一个或多个仓库、工程目录或运行环境；
- 已确认的技术决定、能力要求、配置契约和外部服务约束；
- 调用方本次可提供的真实外部资源资料，包括账号、凭据、授权、素材、设备或其它 Agent 无法自行取得的条件；
- 测试账号、角色矩阵、素材、数据、设备、浏览器或发布要求；
- 同一次尚未完成准备工作的清单、现场和可复核证据。

外部资源资料可以位于任意经授权且可读的位置，并采用任意足以理解的表达形式。本能力不得要求调用方改成固定 JSON、表格、字段集合或特定文件名，也不得因为某项本机运行时、工具或可自行验证条件没有出现在资源资料中，就判定它缺失。

## 工作方式

### 1. 读取当前上下文

按项目实际范围读取：

- 项目规则、产品范围、验收与交付资料；
- 目标仓库边界、Git 状态、依赖、锁定文件、构建与测试配置；
- 配置加载方式、配置校验、公开示例和安全忽略规则；真实开发配置仅在必要范围内读取；
- 启动、迁移、初始化、健康检查、联调、浏览器验收和交付入口；
- 调用方提供的外部资源资料及其中与当前项目有关的公开说明和真实访问条件；
- 同一次尚未完成准备工作的清单、现场及其可复核证据。

资料冲突时区分当前事实、已确认决定、目标状态、假设和待确认事项，说明冲突影响，不静默选择其中一版。

### 2. 建立整个项目周期的准备清单

从已确认项目范围逐项推导必要条件，而不是从资源资料反推项目应该使用什么。按需覆盖：

- 仓库、目录访问、运行环境、依赖和项目命令；
- 数据存储、本地或外部服务、迁移、初始化和可复位数据；
- 开发、测试、联调和交付配置及其公开配置契约；
- 外部服务的开发账号、授权范围、回调、白名单、沙箱和测试身份；
- 文案、图片、字体、授权记录和其它必要素材；
- 启动、健康检查、真实联调、自动化检查和浏览器验收条件；
- 域名、证书、备份恢复、隐私、安全或其它交付条件。

简单项目省略无关类别。尚未决定的必要方案只记录待决定事项、影响和解除条件，不展开或擅自采用具体候选。最终范围中任何不可替代的必要条件，只要尚未准备并验证，就属于项目准备阻塞，即使它在开发后期才会被使用。

覆盖整个项目周期是为了提前确认后续工作的前置条件，不代表在准备核验中提前实现业务、运行尚不存在的最终验收或执行发布。这里只实际完成能够独立准备和安全验证的环境、资源、权限、配置、身份、数据及验收入口。

### 3. 匹配调用方可用资源

对每项需要调用方提供的外部条件：

1. 根据能力、权限、环境、限制和使用边界查找能够满足既定合同的候选，不只比较名称；
2. 完全匹配或已确认兼容合同内的候选可以直接使用；
3. 会改变技术边界、产品行为、安全、隐私、成本、部署或验收方式的候选只能记录为替代建议，不能静默采用；
4. 没有完全匹配项时，说明已检查的兼容边界、候选差异和实际影响；
5. 必需且没有可接受资源或已确认替代方案时标为阻塞；确实不影响已确认最终范围时记录为非必需，而不是为了继续流程伪装成 `not-applicable`。

不得机械使用资源池中的全部内容，也不得把资源资料中的字段原样转换成环境变量。只处理当前项目真实需要且合同明确的部分。

### 4. 准备资源并落地配置

在调用方授权、项目事实和安全边界允许时，主动完成必要准备：

- 使用现有项目命令或服务方式准备本机可生成的配置、目录和数据；
- 使用明确授权的维护条件创建项目专用、环境隔离、可撤销的开发或测试资源与最小权限运行凭据；
- 不创建生产资源、未授权付费资源、正式外部账号、不可逆数据或权限范围不明的共享基础设施；
- 先确认目标仓库、配置加载方式和忽略规则，再向项目实际使用的 `.env` 或等价本地配置写入真实可用值；
- 同步维护对应的 `.env.example` 或项目既有公开配置示例，只写配置键、可公开默认值、安全占位和必要的公开使用说明；
- 可以参考外部资源资料中的公开限制、初始化方式、回调要求、使用边界和复验方法补充注释或项目既有配置说明，但不得复制秘密、私有连接信息或整份资源资料；
- 只补齐项目已确认或能够从现有工程事实唯一确定的最小配置契约；无法安全确定键名、加载位置、权限或用途时保持阻塞，不自行发明。

管理、维护或共享根凭据不得写入应用运行配置。若资源池只有维护凭据，应在授权范围内派生项目级运行凭据并使用后者；无法派生时不得把维护凭据可用误报为项目已就绪。

### 5. 使用最终运行条件主动核验

安全且与项目周期相关的检查应实际执行，例如：

- 确认各仓库边界、工作树、忽略规则和配置文件归属；
- 检查项目声明的运行条件、依赖、配置键和可执行命令；
- 使用最终写入项目配置的运行凭据验证身份、权限和所需最小读写能力，而不是只使用管理凭据探测服务存在；
- 按项目现有方式运行与准备条件直接相关的最小连接、权限、初始化或安全烟雾验证，不替工程项目化、业务开发或最终验收提前执行完整工作；
- 核验后续真实浏览器验收所需的浏览器能力、测试身份、可复位数据、目标视口和可访问入口；已有可运行入口时只执行足以证明准备条件的安全检查，不把它冒充最终体验验收；
- 对临时对象或数据完成必要清理，避免验证本身污染后续开发和验收；
- 检查证据是否足以证明对应状态，而不是只证明工具、endpoint 或高权限账号可用。

不得为了把条目标成 `ready` 而扩大授权、降低权限要求、删除验收条件或采用未确认替代方案。缺少不可替代条件时，保留原要求并明确阻塞、补齐责任和复验方法。

## 体验验收准备

涉及用户界面或用户可见流程时，准备清单应覆盖以下条件。

### 测试身份与角色

- 为每条受保护流程准备可用的测试身份，明确其角色、资源范围、租户或组织归属；
- 同时覆盖允许、禁止、会话过期、账号停用或角色变更等实际需要的路径；
- 测试身份不得共用生产凭据，秘密只保存在受保护的开发配置中；
- 记录身份由谁提供、有效期、复位方式和重新验证条件，不记录密码或令牌原文。

### 可复位数据

- 为关键流程准备已知初始状态、可识别样本和预期结果；
- 明确创建、重置、清理和重复执行方式，避免一次验收改变后续验收前提；
- 覆盖空数据、正常数据、边界数据、冲突或失败数据中与当前验收有关的部分；
- 涉及异步任务、缓存或外部副作用时，说明复位完成的判定和等待条件。

### 目标视口与浏览器

- 从调用方要求、用户分布或项目现有支持矩阵确定目标浏览器、版本范围、设备类别和视口；
- 至少为每个关键布局断点给出可重复的视口尺寸，不以“桌面端”“移动端”等模糊描述代替；
- 记录浏览器能力、系统字体、缩放、语言或时区中会影响结果的条件；
- 无明确支持矩阵且无法从产品和工程事实确定时，保持待确认和阻塞，不自行承诺任意浏览器范围。

### 验收证据与安全

- 每项证据应关联场景、身份/角色、数据状态、浏览器和视口、执行时间及结果；
- 同时检查页面结果、控制台错误、关键网络失败、权限越界和敏感信息暴露；
- 截图或录屏只能证明可见结果，不能单独证明权限、数据隔离、请求成功或恢复行为；
- 证据必须脱敏，不包含密码、令牌、完整个人数据、内部秘密或不必要的原始响应；
- 危险操作只在隔离且可恢复的数据上验证，并记录授权、结果和恢复路径。

## 清单格式

默认创建：

```text
docs/requirements/项目准备清单.md
```

每项至少记录：

| 字段 | 含义 |
|---|---|
| 项目 | 准备内容的短名称 |
| 生命周期用途 | 使用方及开发、联调、真实体验验收或交付阶段 |
| 必要性与阻塞 | 是否为最终范围必要条件；未就绪是否阻塞整个项目准备 |
| 资源匹配 | 使用的脱敏资源标识、兼容依据或候选差异 |
| 配置落点 | 实际开发配置、公开示例或说明位置；不记录秘密值 |
| 核验方式 | 实际命令、步骤或需要人工确认的事项 |
| 状态 | `ready` / `missing` / `pending` / `not-applicable` |
| 脱敏证据 | 核验摘要、时间和证据范围 |
| 实际影响 | 缺少时具体无法完成什么 |
| 补齐与复验 | 需要谁提供什么，以及如何重新验证 |

状态含义：

- `ready`：所需资源已经匹配并按授权完成必要准备，真实配置已落地且使用最终运行条件通过实际检查；
- `missing`：已确认必需条件缺失、不可用或没有满足既定合同的候选；
- `pending`：仍待决定、授权、提供、配置、人工确认或执行核验；
- `not-applicable`：根据当前已确认最终范围和交付目标确实不需要，不能用于表示推迟到后期或暂时无法准备。

清单开头说明已覆盖的最终范围、核验日期、实际创建或修改的配置与资源类别，以及项目能否继续。结尾汇总阻塞项、非必需项、责任方和解除条件。任何最终范围必要项为 `missing` 或 `pending` 时，项目准备状态必须明确为阻塞，不得以其它条目已就绪抵消。

## 配置与秘密

读取、创建、修改和使用开发环境配置时必须：

- 逐个确认实际配置所属仓库及其 Git 忽略规则，不假设根仓库规则覆盖独立子仓库；
- 配置合同新增、删除或调整时同步实际 `.env` 与对应 `.env.example`，无论是否伴随代码修改；
- 实际配置使用真实可用的项目运行值；公开示例只保存配置键、可公开默认值、安全占位和不含秘密的用法说明；
- 客户端可见配置只使用可公开值，不把密码、令牌或私有密钥写入会进入浏览器或其它公开产物的变量；
- 遵循项目真实的配置加载方式，不假设结构化值可以被 shell 直接加载；
- 不在命令文本、进程参数、文档、日志、测试固件、diff 摘要或回复中回显秘密；
- 清单只记录足以判断状态的资源标识、配置键和脱敏证据，不复制外部资源资料正文；
- 完成后分别检查适用仓库状态，确认秘密没有被暂存、跟踪或写入公开文件。

## 结束与汇报

继续同一次尚未完成的准备工作时，先核对已有文件、资源和证据，只继承仍能复核的现场，并完成剩余准备与验证。若项目已经存在完成的准备基线，应停止新的执行，不重复创建资源、派生凭据、重写配置或刷新结论；后续范围变化、资源失效或技术决定变化由调用方先明确原基线是否作废以及是否进入新的项目周期。

完成后汇报：

- 整个已确认项目周期的准备状态、依据和核验时间范围；
- 创建或更新的准备清单、实际开发配置、公开配置示例和说明文件；
- 实际匹配、创建、配置和验证的资源类别及脱敏标识；
- 关键 `ready`、`missing`、`pending` 和 `not-applicable` 项；
- 体验验收所用身份、数据、浏览器、视口和脱敏证据范围；
- 未解决事项、实际影响、责任方和补齐/补验方式；
- 实际执行的命令与结果。

只要存在最终范围必要且未验证成功的阻塞项，必须明确报告项目准备未完成，不能给出可以进入后续开发流程的结论。

## 避免

- 未读取当前资料和工程事实就套固定资源、服务、变量或清单格式；
- 把调用方资源池当作项目需求来源，或因为池中存在某项资源就决定使用它；
- 把候选技术、本机工具、旧项目样例或模板说明写成项目决定；
- 只生成准备清单，不执行能够安全完成的资源准备、配置写入和实际核验；
- 使用管理凭据证明服务存在，却没有准备并验证项目运行凭据；
- 把真实秘密复制到 `.env.example`、公开说明、日志、测试、清单或回复；
- 用 Mock、静态数据、截图、文件存在或文档自述冒充真实服务与权限路径可用；
- 只准备当前启动条件，遗漏最终范围中后续联调、体验验收或交付的不可替代条件；
- 为显示就绪而改变产品、技术方案、权限边界或创建未授权资源。
