# project-readiness — 项目准备状态与清单维护

## 定位

这是一个可独立调用的准备状态分析能力。它根据调用方资料和当前项目事实，识别开发、联调、体验验收或发布所需条件，主动核验能够安全检查的内容，并生成或更新可执行的准备清单。

准备清单记录已经确定的实现和验收条件，不替项目补做技术决策。资料不完整时可以开始，但必须说明证据缺口和实际影响，不为填满清单虚构依赖。

## 核心原则

1. **事实优先**：代码、配置、测试、迁移、运行结果和调用方明确确认高于说明性文档与猜测。
2. **只核验已确定内容**：技术或服务尚未决定时记录待确认事项，不根据本机工具或常见做法擅自选型。
3. **按实际影响排序**：优先处理阻碍当前开发、联调或验收的事项，不把所有未来依赖都标成当前阻塞。
4. **主动且安全地检查**：能通过现有项目命令和本地可逆操作确认的内容应实际检查；付费、生产权限、不可逆操作和只能人工判断的事项保留为待确认。
5. **真实证据**：工具存在、Mock、静态数据或截图不能替代真实服务、真实权限路径和真实浏览器行为。
6. **秘密最小暴露**：必要时可以使用开发配置完成核验，但文档、日志和回复只保留脱敏证据。
7. **状态可更新**：方案、工程或外部条件变化后，只更新受影响条目，不把历史核验结果继续当作当前事实。

## 可接受的输入

调用方可以提供任意组合：

- 产品目标、用户流程、验收要求和交付约束；
- 一个或多个仓库、工程目录或运行环境；
- 已确认的技术决定、配置契约和外部服务要求；
- 现有准备清单及希望核验、回填或纠正的范围；
- 测试账号、角色矩阵、素材、数据、设备或浏览器要求；
- 希望只检查的特定类别。

## 工作方式

### 1. 读取当前上下文

按项目实际范围读取：

- 项目规则、说明文档和调用方资料；
- 目标仓库边界、Git 状态、依赖、锁定文件、构建与测试配置；
- 配置示例、配置校验和安全忽略规则；真实开发配置仅在必要范围内读取；
- 启动、迁移、初始化、健康检查、联调和浏览器验收入口；
- 已有准备清单及其可复核证据。

资料冲突时区分当前事实、已确认决定、目标状态、假设和待确认事项，说明冲突影响，不静默选择其中一版。

### 2. 确定准备范围

只纳入当前范围已经需要或已确认将在指定里程碑需要的条件，例如：

- 仓库、目录访问、运行环境、依赖和项目命令；
- 数据存储、本地服务、迁移、初始化和可复位数据；
- 开发配置、公开示例和配置契约；
- 外部服务的开发账号、回调、白名单、沙箱和测试身份；
- 文案、图片、字体、授权记录和其它必要素材；
- 启动、健康检查、真实联调、测试、构建和浏览器验收条件；
- 发布阶段才需要的域名、证书、备份恢复、隐私和安全条件。

简单项目省略无关类别。尚未决定的方案只记录“待决定什么、决定前无法核验什么”，不展开具体候选配置。

### 3. 主动核验

安全且与当前范围相关的检查应实际执行，例如：

- 确认仓库边界、工作树、忽略规则和文件归属；
- 检查项目声明的运行条件、依赖、配置键和可执行命令；
- 按项目现有方式运行安装就绪、迁移、初始化、健康检查、测试或构建；
- 启动项目已支持的本地服务并完成必要联调，结束后清理本次临时进程；
- 在真实浏览器中核验主要入口、角色路径、目标视口、控制台和失败网络请求；
- 检查证据是否足以证明对应状态，而不是只证明工具可用。

不得为了把条目标成 `ready` 而擅自创建外部账号、生产资源、持久基础设施或不可逆数据。缺少不可替代条件时，保留原验收标准并写明补验方式。

## 体验验收准备

涉及用户界面或用户可见流程时，准备清单应集中记录并核验以下条件。

### 测试身份与角色

- 为每条受保护流程准备可用的测试身份，明确其角色、资源范围、租户或组织归属；
- 同时覆盖允许、禁止、会话过期、账号停用或角色变更等实际需要的路径；
- 测试身份不得共用生产凭据，秘密只保存在受保护的开发配置中；
- 记录身份由谁提供、有效期、复位方式和重新验证条件，不记录密码或令牌原文。

### 可复位数据

- 为关键流程准备已知初始状态、可识别样本和预期结果；
- 明确创建、重置、清理和重复执行方式，避免一次验收改变后续验收前提；
- 覆盖空数据、正常数据、边界数据、冲突或失败数据中与当前验收有关的部分；
- 涉及异步任务、缓存或外部副作用时，说明复位完成的判定和等待条件。

### 目标视口与浏览器

- 从调用方要求、用户分布或项目现有支持矩阵确定目标浏览器、版本范围、设备类别和视口；
- 至少为每个关键布局断点给出可重复的视口尺寸，不以“桌面端”“移动端”等模糊描述代替；
- 记录浏览器能力、系统字体、缩放、语言或时区中会影响结果的条件；
- 无明确支持矩阵时，标记待确认，不自行承诺任意浏览器范围。

### 验收证据与安全

- 每项证据应关联场景、身份/角色、数据状态、浏览器和视口、执行时间及结果；
- 同时检查页面结果、控制台错误、关键网络失败、权限越界和敏感信息暴露；
- 截图或录屏只能证明可见结果，不能单独证明权限、数据隔离、请求成功或恢复行为；
- 证据必须脱敏，不包含密码、令牌、完整个人数据、内部秘密或不必要的原始响应；
- 危险操作只在隔离且可恢复的数据上验证，并记录确认、授权、结果和恢复路径。

## 清单格式

默认创建或更新：

```text
docs/requirements/项目准备清单.md
```

每项至少记录：

| 字段 | 含义 |
|---|---|
| 项目 | 准备内容的短名称 |
| 适用阶段 | 当前开发、指定里程碑、体验验收或发布 |
| 核验方式 | 实际命令、步骤或需要人工确认的事项 |
| 状态 | `ready` / `missing` / `pending` / `not-applicable` |
| 脱敏证据 | 核验摘要、时间和证据范围 |
| 实际影响 | 缺少时具体无法完成什么 |
| 补齐与复验 | 需要谁提供什么，以及如何重新验证 |

状态含义：

- `ready`：已通过实际检查或明确确认可用；
- `missing`：已确认缺失或不可用；
- `pending`：仍待提供、决定、人工确认或执行核验；
- `not-applicable`：根据当前范围和交付目标不需要。

清单开头说明当前范围、核验日期和项目现在可以或不能进行的工作；结尾汇总阻塞项、可延期项、责任方和重新核验条件。调用方已明确要求生成或更新且范围清楚时可直接落盘；仅要求分析时不创建文档。

## 配置与秘密

必要时可以读取、创建或修改开发环境配置以完成真实核验，但必须：

- 确认包含秘密的实际配置已被 Git 忽略；
- 不暂存、提交、展示或复制秘密到文档、日志、测试固件和回复；
- 公开示例只保存配置键、安全默认值和占位说明；
- 遵循项目真实的配置加载方式，不假设结构化值可以被 shell 直接加载；
- 命令输出和准备清单只保留足够判断状态的脱敏信息。

## 更新与结束

更新现有清单时，先核对旧证据是否仍有效，只修改本次事实变化涉及的条目。已不适用且仍有追溯价值的内容标记为 `not-applicable` 并保留简短依据；没有价值的重复或错误条目可以删除，并说明原因。

完成后汇报：

- 当前准备状态、依据和核验时间范围；
- 创建或更新的文件；
- 关键 `ready`、`missing`、`pending` 和 `not-applicable` 项；
- 体验验收所用身份、数据、浏览器、视口和脱敏证据范围；
- 未解决事项、实际影响和补齐/补验方式；
- 实际执行的命令与结果。

## 避免

- 未读取当前资料和工程事实就套固定清单；
- 把候选技术、本机工具或模板说明写成项目决定；
- 用 Mock、静态数据、截图或工具存在冒充真实服务与权限路径可用；
- 只有测试账号却没有角色范围、可复位数据、目标视口和浏览器条件；
- 证据缺少场景上下文，或包含秘密和不必要的敏感数据；
- 为显示就绪而改变产品、技术方案或创建不可逆资源。
