# project-readiness — 项目准备状态与清单维护

## 定位

这是一个可独立调用的开发资源准备能力。它根据调用方资料和当前项目事实，识别完成当前自动化开发、开发环境联调和开发环境真实验收所需的外部资源，匹配调用方实际提供的动态资源候选池，主动完成能够安全执行的资源创建、配置落地与真实核验，并建立可复核的准备清单。

同一自动化开发周期只建立一次完成的准备基线。一次尚未完成的准备工作可以在原现场继续补齐和核验；已经存在完成基线时，不重新执行资源创建、凭据派生或配置写入，也不把后续生产部署工作伪装成清单更新。

准备清单是实际资源准备结果的脱敏账本，不是本能力的唯一动作，也不能为自身状态作证。资源、权限或配置只有经过实际准备并取得相称证据后才能标为就绪。

本能力不替项目提前完成业务实现、依赖安装、迁移、Seed 或最终产品验收。产品规则、架构细节和隐私保留等尚未决定时交给后续设计与开发，不形成开发资源清单条目。生产发布准备不属于本能力或清单准入范围。AI Agent 工作区固有的通用开发工具及其私有凭据（例如媒体资源检索或定制图片生成）也不属于目标项目候选资源、项目准备清单或目标项目 `.env`；只有产品自身已确认需要的外部服务、素材或验收条件才按本能力处理。

## 核心原则

1. **事实优先**：代码、配置、测试、迁移、运行结果和调用方明确确认高于说明性文档与猜测。
2. **只覆盖开发准备**：只有当前自动化开发、开发环境联调或开发环境真实验收所需，且必须由调用方提供或授权的外部资源才能进入项目准备清单；只服务生产部署或生产运行的正式域名、DNS/TLS、生产资源与凭据、生产回调与配额、监控、备份、容量和发布安全不属于本能力或清单准入范围。
3. **资源动态发现**：调用方提供的资源资料只是本次可用的动态候选池，不是 Skill 内置目录；不预设其文件名、格式、字段、资源类型、服务名称或变量名。
4. **先调查并在授权内自主解决**：根据已确认能力要求、技术事实和项目配置方式匹配资源；普通配置、兼容性和准备事项有多个可行做法时，继续核验并采用满足既定合同、影响最小的方案，不把多选项本身当作上抛理由。只有替代会改变产品语义、技术边界、安全与数据使用边界、显著成本或运行方式，且现有授权不足时，才保持待决定。
5. **先执行后定状态**：能安全检查、创建、配置或验证的事项应实际执行。没有工具结果、可复核文件事实或调用方明确确认，就不得标为 `ready`。
6. **最小权限与最小暴露**：优先使用项目专用、环境隔离、可撤销的运行凭据；管理凭据只用于明确授权的准备动作，不作为应用运行凭据。服务不支持派生项目身份时，只有调用方明确授权的非管理、非生产共享开发身份，且其数据、操作、收件人或其它实际使用范围满足当前开发合同并可复验，才可作为兼容资源；不能仅因“共享”标签判定不可用。
7. **真实证据**：工具存在、资源说明、Mock、静态数据、文档自述或截图不能替代真实服务、真实权限路径、真实配置和真实浏览器行为。
8. **唯一开发基线**：基于本次可访问事实为一个自动化开发周期建立唯一、完整、可追溯的资源准备基线；只允许继续同一次尚未完成的工作，不重复执行已经完成的基线。
9. **现有绑定优先**：匹配候选前先验证项目受保护实际配置中的非空运行凭据和资源绑定；满足当前开发合同时原样保留，不用候选池中的维护、共享或更宽权限身份替换，也不把候选凭据的探针结果误记为最终项目凭据结果。候选池只用于补齐缺失、失效或确实不合格的绑定。清单只描述最终选定绑定及其兼容和验证证据，不得提及、比较或说明未采用候选，否定表述也不例外。
10. **准确交接决定与外部缺口**：确需负责人决定时，在当前回复中讲清准确问题、已核验事实与约束、可行选项、各自影响、推荐理由，以及它实际阻碍哪些准备或开发范围；不只给路径或“请确认”。涉及秘密、个人数据或安全控制不自动要求重新批准，按既有授权与最小暴露边界处理。必要外部授权或凭据无法自行取得时，交接补齐条件与复验方式，不能把它当作可后置的普通设计。

## 可接受的输入

调用方可以提供任意组合：

- 产品目标、当前开发范围、用户流程和开发环境验收要求；
- 一个或多个仓库、工程目录或运行环境；
- 已确认的技术决定、能力要求、配置契约和外部服务约束；
- 调用方本次可提供的真实外部资源资料，包括账号、凭据、授权、素材、设备或其它 Agent 无法自行取得的条件；
- 开发测试账号、角色矩阵、素材、数据、设备或浏览器要求；
- 同一次尚未完成准备工作的清单、现场和可复核证据。

外部资源资料可以位于任意经授权且可读的位置，并采用任意足以理解的表达形式。本能力不得要求调用方改成固定 JSON、表格、字段集合或特定文件名，也不得因为某项本机运行时、工具或可自行验证条件没有出现在资源资料中，就判定它缺失。

## 工作方式

### 1. 读取当前上下文

按项目实际范围读取：

- 项目规则、产品范围和开发环境验收资料；
- 目标仓库边界、Git 状态、依赖、锁定文件、构建与测试配置；
- 配置加载方式、配置校验、公开示例和安全忽略规则；真实开发配置仅在必要范围内读取；
- 启动、初始化、健康检查、开发联调和开发环境浏览器验收入口；
- 调用方提供的外部资源资料及其中与当前项目有关的公开说明和真实访问条件；
- 同一次尚未完成准备工作的清单、现场及其可复核证据。

资料冲突时区分当前事实、已确认决定、目标状态、假设和确需负责人决定的事项，先调查当前准备所需事实并在授权内消解普通差异。尚未实现的业务能力、后续技术设计、待验证假设和外部资源缺口含义不同，不得统称为阻塞或“待确认”；只有实际越权的高影响冲突才请求负责人决定，并说明它对当前准备的准确影响。

### 2. 建立开发阶段资源准备清单

从已确认开发范围逐项推导需要由调用方提供、且 Agent 无法自行生成的外部资源，而不是从资源资料反推项目应该使用什么。按需覆盖：

- 开发和测试数据库、中间件、对象存储及其它外部服务；
- 外部服务的开发账号、最小权限凭据、回调、白名单、沙箱和测试身份；
- 开发联调和真实开发验收所需的素材、私有数据、专用设备或外部审批；
- 项目受保护本地配置及对应公开配置键合同；
- 当前开发必须依赖的其它不可替代外部条件。

本机运行时、包管理器、依赖安装、迁移、Seed、构建、测试、应用启动和业务实现由 Agent 或后续开发步骤按工程事实完成，不构成“资源清单缺失”阻塞。只服务生产部署或生产运行的环境、正式域名、DNS/TLS、生产数据库/对象存储/邮件资源与凭据、生产回调与配额、监控、备份恢复、容量、发布安全和发布级隐私治理在清单生成前直接排除。项目准备清单不是范围外事项账本，正文任何位置都不得列举、命名或汇总这些事项，也不得借“未纳入清单”“范围外”“未来事项”“非阻塞”、无状态说明或 `not-applicable` 保留它们。资源名称本身不能决定范围：开发 SMTP TLS、localhost 回调、开发白名单、沙箱能力和开发配额仍按当前开发用途纳入。

项目准备只允许以下两类阻塞：

1. 已确认开发必须依赖的外部资源在调用方候选池中不存在，当前环境也无法安全生成，且没有满足既定合同的兼容替代；
2. 已匹配的开发资源缺少完成必要准备或核验的外部授权、凭据，或经过真实连接、权限和最小能力验证后不可用、凭据无效、权限不足、隔离不符合开发要求，或缺少开发必需的接口能力、可用配额、回调注册、白名单及其它既定合同能力。

产品规则、技术细节或隐私策略尚待设计时交给后续产品/技术设计，不把“需要决定”误报为外部资源阻塞。只收敛与本次开发资源准备有关、且已经到解决时机的未决，不全盘重审上游内容。确需后置且影响后续工作的事项，在执行回复中说明现在为何不阻碍、由什么工作承接或依赖什么证据，以及最迟在何种使用条件出现前解决；不把它写进准备清单，也不新增固定字段、状态或范围外台账。当前已有足够事实和授权可解决的配置、核验或资源匹配问题必须直接处理，不能继续挂起。

### 3. 匹配调用方可用资源

对每项需要调用方提供的外部条件：

1. 先读取并验证所属仓库受保护实际配置中的现有非空运行凭据和资源绑定；若满足当前开发合同，保留该绑定并直接以其作为最终探针身份；
2. 仅当现有绑定缺失、失效或不合格时，根据能力、权限、环境、限制和使用边界查找能够满足既定合同的候选，不只比较名称；
3. 完全匹配或已确认兼容合同内的候选可以直接使用；
4. 会改变技术边界、产品行为、安全、隐私、成本、部署或验收方式的候选只能在执行回复或负责人决策上下文中作为替代建议说明，不能静默采用，也不得写入项目准备清单；
5. 没有完全匹配项时，在执行回复中说明已检查的兼容边界、候选差异和实际影响；项目准备清单只保留最终选定绑定，未采用候选不进入正文；
6. 开发必需且没有可接受资源或已确认替代方案时标为阻塞；不属于当前开发必需外部资源的候选不进入清单，正文中也不得以排除说明、候选差异清单或无状态记录提及。

不得机械使用资源池中的全部内容，也不得把资源资料中的字段原样转换成环境变量。只处理当前项目真实需要且合同明确的部分。

### 4. 准备资源并落地配置

在调用方授权、项目事实和安全边界允许时，主动完成必要准备：

- 使用现有项目命令或服务方式准备本机可生成的配置、目录和数据；
- 使用明确授权的维护条件创建项目专用、环境隔离、可撤销的开发或测试资源与最小权限运行凭据；服务不提供子账号或凭据派生能力时，可以使用调用方明确授权、非管理且非生产，并且实际作用范围满足当前开发合同的共享开发身份，但必须记录兼容依据、使用边界和复验结果；共享管理或根凭据、生产身份、能够访问合同外资源的身份不得作为应用运行凭据，无法派生合格身份时按第二类资源阻塞处理；
- 不创建生产资源、未授权付费资源、正式外部账号、不可逆数据或权限范围不明的共享基础设施；
- 先确认目标仓库、配置加载方式和忽略规则，再向项目实际使用的 `.env` 或等价本地配置写入真实可用值；
- 对已经选定且当前开发需要的每项外部运行资源，必须把最终项目运行凭据和资源绑定持久化到适当的受保护本地配置，确保后续开发无需重新读取共享资源池才能使用；即使消费代码稍后实现，只要配置键、归属和用途能由已确认技术合同、资源合同或工程惯例唯一确定，也应先建立最小配置键合同，不得让真实凭据只留在调用方资源资料或准备清单中；
- 同步维护对应的 `.env.example` 或项目既有公开配置示例，只写配置键、可公开默认值、安全占位和必要的公开使用说明；
- 可以参考外部资源资料中的公开限制、初始化方式、回调要求、使用边界和复验方法补充注释或项目既有配置说明，但不得复制秘密、私有连接信息或整份资源资料；
- 只补齐项目已确认或能够从现有工程事实唯一确定的最小配置契约；键名、加载位置或结构尚不清楚时，继续读取代码、公开示例和资源说明并建立最小合同，不把项目内部配置问题单独判为 `blocked`。只有其背后确实存在两类外部资源问题之一时才阻塞；

管理、维护或共享根凭据不得写入应用运行配置。若资源池只有维护凭据，应在授权范围内派生项目级运行凭据并使用后者；无法派生时不得把维护凭据可用误报为项目已就绪。

### 5. 使用最终运行条件主动核验

安全且与开发资源准备相关的检查应实际执行，例如：

- 确认各仓库边界、工作树、忽略规则和配置文件归属；
- 检查项目声明的运行条件、依赖、配置键和可执行命令；
- 使用最终写入项目配置的运行凭据验证身份、权限、隔离和开发所需的最小能力，包括适用的接口操作、配额、回调、白名单或沙箱能力，而不是只使用管理凭据探测服务存在；权限与隔离按实际可见范围和可执行行为判断，若服务的列表接口只返回获授权项目资源且范围外读取或操作被拒绝，不因列表接口本身成功而误判越权；
- 按项目现有方式运行与准备条件直接相关的最小连接、权限、初始化或安全烟雾验证，不替工程项目化、业务开发或最终验收提前执行完整工作；
- 核验后续开发环境真实浏览器验收所需的浏览器能力和外部测试身份；可由业务实现、Seed 或 fixture 生成的数据和角色不要求在本步骤提前创建；
- 对临时对象或数据完成必要清理，避免验证本身污染后续开发和验收；
- 按实际开发用途检查证据是否覆盖所需操作，结论不超出已验证的能力；例如需要数据读写时，建表和删表成功不能替代读写验证。缺少所需行为的证据时继续完成相称的最小核验，不把工具、endpoint 或高权限账号可用当作资源就绪。

不得为了把条目标成 `ready` 而扩大授权、降低开发隔离要求或采用未确认替代方案。缺少开发必需外部资源，或资源真实不可用、凭据无效、权限/隔离不合格、必要能力/配额/回调/白名单不足时，保留要求并明确阻塞、补齐责任和复验方法；不属于当前开发资源准入范围的事项不得写入清单。

## 体验验收准备

涉及用户界面或用户可见流程时，准备清单只核验开发环境中不可自行取得的外部验收资源；业务页面、产品内角色、Seed 数据和完整验收在实现后处理。

### 测试身份与角色

- 外部身份提供商、第三方沙箱或专用设备要求真实测试账号时，准备可用身份并记录角色、环境、有效期和复验方式；
- 产品自身的用户、角色和权限测试身份由后续业务实现与 Seed/fixture 创建，不因当前尚未实现而阻塞资源准备；
- 测试身份不得共用生产凭据，秘密只保存在受保护的开发配置中；
- 只有开发必须依赖且无法自行创建的外部测试身份缺失或不可用时才构成阻塞。

### 可复位数据

- 外部服务必须由调用方提供私有测试数据时，确认其可用、可复位和允许操作边界；
- 项目自身的正常、空、边界、冲突和失败数据由后续模型、migration、Seed 或 fixture 创建；
- 当前没有业务表或 Seed 不属于外部资源缺失，也不阻塞项目准备；
- 外部测试数据缺失只有在当前开发确实无法自行生成替代数据时才阻塞。

### 目标视口与浏览器

- 确认当前机器至少具备项目后续真实浏览器验证所需的可用浏览器通道；
- 目标视口、浏览器矩阵、辅助技术和完整体验覆盖由后续设计与开发验收确定；
- 浏览器工具可由当前环境恢复或安装时主动处理，不要求写入外部资源候选池；
- 只有开发必须依赖且当前环境无法取得的专用浏览器、设备或外部测试平台缺失时才阻塞。

### 验收证据与安全

- 每项证据应关联场景、身份/角色、数据状态、浏览器和视口、执行时间及结果；
- 同时检查页面结果、控制台错误、关键网络失败、权限越界和敏感信息暴露；
- 截图或录屏只能证明可见结果，不能单独证明权限、数据隔离、请求成功或恢复行为；
- 证据必须脱敏，不包含密码、令牌、完整个人数据、内部秘密或不必要的原始响应；
- 危险操作只在隔离且可恢复的数据上验证，并记录授权、结果和恢复路径。

## 清单格式

默认创建：

```text
docs/requirements/项目准备清单.md
```

清单用于交接实际资源准备结果，不把执行检查项逐项展开成固定字段。按资源类别组织短段落、列表或简短表格；长说明不塞进横向大表格，不以行数少作为精简目标。

让接手者能够找到：

- 当前开发用途、最终选定绑定的脱敏标识，以及影响使用的兼容条件或限制；
- 实际配置与公开示例的位置、必要配置键，以及凭据保护和忽略状态；
- 当前状态，使用最终运行配置实际核验的操作、结果和时间范围，以及足够复验的命令入口或步骤；证据摘要与用途对应，不粘贴完整日志，也不为清单强制新建证据目录、截图或机器快照。

同类资源在不同环境下的共同事实只写一次，分别说明各环境的绑定、配置落点、权限边界及验证结果；不能为了合并而隐藏某个环境的缺口。已就绪资源重点写准备结果，不逐项重复假设性故障影响、阻塞分类或通用恢复话术；影响实际使用的限制和必要复验条件仍应保留。未就绪资源写清缺少什么、实际影响、是否符合既有阻塞条件、需要谁补齐什么及如何复验，不虚构责任人。

状态含义：

- `ready`：开发所需资源已经匹配并按授权完成必要准备；最终项目运行凭据和资源绑定已持久化到受保护的实际配置，公开配置示例已同步，且使用该最终运行条件通过实际检查；
- `missing`：已通过开发范围准入的必需外部资源在候选池中不存在且当前环境无法安全生成；没有满足既定合同的兼容替代时阻塞；
- `pending`：已通过开发范围准入的外部资源仍待授权、配置或核验；能自行完成的继续执行，缺少必要外部授权或凭据、或已匹配的开发必需资源无法通过真实验证时，按既有资源阻塞条件交接，不以 `pending` 代替完成。

清单开头简要概括当前开发资源范围、核验日期、实际创建或修改的配置与资源类别，以及是否可以继续项目化和开发，不列举被排除的对象。存在资源阻塞时集中说明责任方和解除方法，正文已交代的缺口不再全文重复；没有缺口时不另设空的阻塞汇总或重复就绪结论。正文任何位置都不得提及依赖、migration、Seed、业务实现、产品设计、生产发布、未来治理或其它非当前必需候选；不得建立“未纳入清单”、范围外、未来事项、非阻塞或无状态章节。

## 配置与秘密

读取、创建、修改和使用开发环境配置时必须：

- 逐个确认实际配置所属仓库及其 Git 忽略规则，不假设根仓库规则覆盖独立子仓库；
- 配置合同新增、删除或调整时同步实际 `.env` 与对应 `.env.example`，无论是否伴随代码修改；
- 实际配置使用真实可用的项目运行值；包含秘密的文件在适用平台上必须限制为仅当前用户可读写（POSIX 通常为 `0600`）；公开示例只保存配置键、可公开默认值、安全占位和不含秘密的用法说明；
- 客户端可见配置只使用可公开值，不把密码、令牌或私有密钥写入会进入浏览器或其它公开产物的变量；
- 遵循项目真实的配置加载方式，不假设结构化值可以被 shell 直接加载；
- 不在命令文本、进程参数、文档、日志、测试固件、diff 摘要或回复中回显秘密；
- 清单只记录足以判断状态的资源标识、配置键和脱敏证据，不复制外部资源资料正文；
- 完成后分别检查适用仓库状态，确认秘密没有被暂存、跟踪或写入公开文件。

## 结束与汇报

继续同一次尚未完成的准备工作时，先核对已有文件、资源和证据，只继承仍能复核的现场，并完成剩余准备与验证。负责人作出决定或授权内事项自主解决后，及时更新受影响的活动清单、实际配置和公开示例，把结果写回生效位置并删除已经失效的待授权、待核验、旧选项或阻塞描述；不改写已经归档的准备记录。若项目已经存在完成的开发资源基线，应停止新的执行，不重复创建资源、派生凭据、重写配置或刷新结论。后续生产部署要求不进入项目准备清单，也不会使开发基线失效；只有开发范围新增不可替代外部资源，或既有开发资源失效时，才由调用方明确是否作废原基线。

完成后在执行回复中说明当前资源准备结果、创建或更新的文件位置，以及关键操作、实际结果和核验时间范围。涉及外部验收资源时，说明与该资源有关的身份、数据或浏览器条件及证据范围；有未解决事项时，讲清实际影响、责任方和补齐/复验方法。回复应足以支持调用方判断是否还需要继续，不全文复述清单，也不只给一个文件路径或笼统的完成声明。

只有符合以下任一条件时，才必须明确报告项目准备未完成并阻止进入后续开发：开发必需外部资源在候选池中不存在、当前环境无法安全生成且无兼容替代；或已匹配资源缺少必要外部授权或凭据、真实不可用、凭据无效、权限不足、隔离不合格，或缺少开发所需接口能力、可用配额、回调/白名单及其它既定能力。其它 `missing` / `pending` 不得用于阻塞开发。

## 避免

- 未读取当前资料和工程事实就套固定资源、服务、变量或清单格式；
- 把调用方资源池当作项目需求来源，或因为池中存在某项资源就决定使用它；
- 把候选技术、本机工具、旧项目样例或模板说明写成项目决定；
- 只生成准备清单，不执行能够安全完成的资源准备、配置写入和实际核验；
- 忽略受保护实际配置中已经存在且满足合同的项目运行绑定，改用候选池中的维护、共享或更宽权限身份探针、覆盖配置或判定最终隔离；
- 在清单中记录或比较未采用候选，包括“未使用某候选”“没有采用管理身份”等否定表述；
- 使用管理凭据证明服务存在，却没有准备并验证项目运行凭据；
- 把外部运行资源标为 `ready`，却只把真实凭据留在共享资源资料中，没有持久化到项目受保护配置并同步公开键合同；
- 把真实秘密复制到 `.env.example`、公开说明、日志、测试、清单或回复；
- 用 Mock、静态数据、截图、文件存在或文档自述冒充真实服务与权限路径可用；
- 只验证 endpoint 或登录成功，遗漏开发所需接口能力、可用配额、回调注册、白名单、沙箱范围或其它既定能力；
- 仅因凭据标为共享，或服务列表接口成功但只返回获授权项目资源，就忽略明确授权、实际作用范围和范围外拒绝证据并误报阻塞；
- 把只服务生产部署或生产运行的正式域名、DNS/TLS、生产资源与凭据、生产回调与配额、监控、备份、容量或发布安全条件写入开发资源清单，或把它们当作开发阻塞；
- 把尚未实现的业务代码、migration、Seed、产品内测试账号、页面或最终验收结果当作外部资源缺失；
- 遗漏当前开发真正依赖的外部服务、账号、凭据、素材或专用设备；
- 为显示就绪而改变产品、技术方案、权限边界或创建未授权资源。
