# media-assets — 开发期媒体获取、生成与固化

## 定位

这是一个可独立调用的开发期媒体工具。它根据当前产品与工程事实复用已有资产，通过已准入且能力匹配的 Provider 检索已有媒体或生成单张定制图片，检查调用方传入及本次取得的真实文件，并将最终采用的资源固化到目标项目的实际资产位置；同时维护稳定测试 fixture。

媒体应改善内容识别、场景理解、品牌表达、产品展示或真实上传验证。有明确收益且来源、成本和写入范围已获授权时主动落实，不因调用方未指定来源而停留在占位资源；没有明确价值时不机械添加图片或视频。

本能力不负责产品运行时媒体搜索或生成、对象存储架构、数据库设计、权限、迁移、恢复或批量内容生产，也不把任何 Provider 变成目标产品的隐藏依赖。

## 核心合同

开始实际获取前，先从当前可访问事实收敛：

1. 资源的用户价值、页面或测试用途；
2. 类型、主题与主体、目标容器和比例、主体位置、文案留白、裁剪重点、风格色彩及禁止元素；
3. 目标项目已有的资产约定与明确最终落点；
4. 需要已有资产复用、候选检索、定制生成、传入文件检查还是测试 fixture；
5. 当前任务是否已经授权相应外部调用、成本和文件写入。

视觉用途、授权范围和目标位置已经确定时直接执行，不要求调用方重复点名来源。只需方向建议时不获取或生成文件；执行目标必须取得并检查明确文件，不能只返回 prompt、假称已生成，或循环检查尚未通过真实命令生成的路径。目标位置不明、外部调用可能产生未授权成本或存在多个实质不同方案时，只形成有限建议或请求必要决定。

已有正式资产能满足用途时直接复用；已有本地文件只需检查和固化时，不联网检索或重新生成。真实通用摄影通常适合检索，品牌化或特定构图可以直接生成，不要求先穷尽图库。测试 fixture 按验证目的选择，不进入正式产品配图的默认候选。

## Provider 选择

Provider 是本能力内部的可选适配，不是独立运行时或产品模块。需要外部检索或生成时读取 [Provider catalog](providers/README.md) 中受维护的受控映射；不得扫描任意目录、自动注册新文件、安装未声明依赖或把未登记来源视为可用 Provider。

- 调用方明确 Provider 时，只读取 catalog 映射的对应说明，核验状态、能力、配置和限制；
- 来源未明确时，按媒体用途和所需能力筛选已准入 Provider。只有一个明显匹配项时直接采用；多个同等可行项涉及不同成本、来源权利或结果语义时，只比较少量候选并请求决定；
- 没有匹配项、配置缺失、服务不可用、接口不兼容、额度不足或使用边界不满足时，根据真实调用错误报告缺口；
- 已选择的 Provider 失败后不静默改用另一个来源，不自动安装 SDK、CLI、Plugin 或连接未声明的公共服务。

Provider 凭据只从调用方授权的受保护配置取得。不得回显、复制到目标产品前后端运行配置、写入业务数据、测试清单、日志或最终回复。

## 单张定制生成

生成 prompt 采用补缺原则：用途、主体、构图与文案留白、裁剪重点、风格和禁止元素足以支持目标结果时直接使用；缺少哪项只补哪项。不追求提示词长度，不强制检索案例、补充镜头参数或产出多个视觉方向。普通单图不额外创建计划、过程报告或 prompt 文件；只有长输入确有需要时才使用 `--prompt-file`。

已授权且目标明确后，从工作区根目录执行固定入口，并为 `-f` 提供目标项目中明确的 `.png` 路径：

```bash
uv run --no-project .claude/skills/media-assets/scripts/generate_image.py -p "视觉描述" -f <明确.png路径>
```

- 普通单图直接使用 `-p`；长输入确有需要时按 Provider 说明改用 `--prompt-file`，不为普通任务额外创建 prompt 文件；
- 固定只生成单张，不传递或开放 `n`；
- 脚本通过 `uv` 和 PEP 723 在隔离环境准备已声明依赖，不向目标产品增加 Python 依赖；
- 其它参数、默认值、工作区配置和响应合同以 [`openai-compatible-image` Provider 说明](providers/openai-compatible-image/README.md) 为唯一依据；
- 命令失败时只依据真实 stderr、退出码和未产生文件的事实报告，不静默换模型、接口、Provider 或临时脚本。

只有首次接入、维护固定脚本或真实错误明确显示接口不兼容时，才查阅对应官方文档；普通生成不为联网研究 API 或重写脚本而延迟执行。

## 候选检查与资产固化

无论复用、检索、生成还是检查调用方提供的媒体，都遵循以下规则：

1. 每次围绕一个明确目标处理有限候选；生成默认单张，不自动扩词、翻页抓取、并发预热或建立素材库；
2. 实际查看视觉内容，结合 OCR、主体语义、构图、比例、异常文字、水印、品牌标识、敏感内容和目标容器适配性检查；
3. 只处理最终选定的少量资源，不用结果批量填充数据库、Seed、列表、索引或用户内容；
4. 临时预览、下载或签名 URL 只用于当次处理，不能成为页面、数据库、Seed、fixture 或其它产品运行时依赖；
5. 将选定资源写入目标项目已有约定的位置，并按用途核验真实 MIME、文件特征、尺寸或时长、体积、完整性与可读性；必要时记录哈希；
6. 用于界面时，在真实目标容器中检查桌面及移动端的主体裁剪、文字叠加、对比、加载失败和视觉层级；测试文件按对应真实行为验证，不能以文件存在或接口成功代替；
7. 只针对实际看到的具体缺陷，在已授权有限预算内修正，不无界重抽；
8. 产品 UI 默认不展示每张已固化静态资源的来源。只有明确许可、合同、审计、替换或产品展示要求时，才保留相称的最小内部依据。

模型图片中的文字不作为最终 Logo 或品牌名称；文字标识应由 SVG、字体或其它可编辑机制承载。背景图不替代页面的标题、按钮或需维护的数据。

## Fixture 维护与使用

本 Skill 随附的 `assets/fixtures/` 保存稳定测试输入、实际清单和维护说明。该集合由维护者按明确测试需求扩充，本能力不为填满目录而自动下载或生成测试资源。

- Fixture 用于上传、预览、格式、大小和失败状态等测试，不是产品静态资产、公开素材库或对象存储模拟器；
- 选择或复用已有 fixture 前，先读取 [fixture manifest](assets/fixtures/manifest.json)，根据用途、真实 MIME 和 `expectedResult` 选择满足当前测试的最小集合；
- 添加、替换或删除 fixture 前，先读取 [fixture 维护说明](assets/fixtures/README.md)，并同步更新实际清单；将 fixture 纳入目标项目前，也先核对该说明中的复制边界；
- 仅作工作区本地验证且路径稳定可访问时，可以直接使用本目录；只有目标产品的自动化测试需要将 fixture 纳入其独立仓库或 CI 输入时，才由负责该测试的 Agent 将所需最小文件复制到项目已有测试资源目录；
- 产品运行时代码不得依赖本 Skill 的内部路径；产品专属视觉资源进入目标项目自己的资产位置，动态用户媒体由对应产品设计和开发处理；
- 测试不在每次运行时联网随机获取 fixture；涉及上传时使用目标项目真实上传路径验证，不能以 Mock、文件存在或截图代替真实行为。

## 停止边界

遇到以下情况时停止直接执行并报告影响：

- 需要决定产品是否将媒体作为核心输入、输出或必需内容；
- 需要创建对象存储、修改数据库、设计权限、清理、迁移或恢复；
- 计划系统性批量搜集或生成业务媒体；
- 目标位置、写入范围、成本或来源权利无法安全判断；
- 现有 Provider 不能满足已确定能力合同。

## 完成与汇报

完成后报告资源用途、复用或 Provider 选择依据摘要、适用时的实际命令结果、候选与文件检查、最终文件路径、文件校验、目标项目实际引用或测试结果，以及尚未解决的缺口。方向建议未生成文件时明确说明；执行目标未取得明确文件时不得冒充完成。不得回显凭据、认证头、临时 URL、完整原始响应或敏感 prompt。

不自动提交、建分支、合并或 push。
