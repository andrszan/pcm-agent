# media-assets — 开发期媒体资源

## 定位

这是 AI Agent 工作区的固定开发工具能力，用于在已经明确媒体用途时，受控地获取、筛选、生成、固化或维护少量媒体资源。它不属于目标产品的运行时功能、外部资源准备基线或项目模块依赖。

本能力固定可用，但不意味着每个项目都必须联网检索、下载或生成图片。先判断媒体是否能改善内容识别、品牌表达、数据理解、真实上传测试或用户决策；没有明确价值时不为装饰而添加无关素材。

## 工作区配置与秘密

只在需要实际调用 Provider 时读取工作区根目录受保护的 `.env`，并遵循根 `.env.example` 的键合同：

- `PIXABAY_API_KEY`：Pixabay 的开发期受控检索与下载；
- `MEDIA_IMAGE_BASE_URL`、`MEDIA_IMAGE_API_KEY`、`MEDIA_IMAGE_MODEL`：兼容 OpenAI Images API 的本地图片生成代理，默认模型为 `gpt-image-2`。

这些键只属于 AI Agent 工作区：

- 不写入 `frontend/`、`backend/` 或其它目标产品配置；
- 不写入 `docs/ignore/dev-resource-list.md`、项目准备清单、活动 TRD、fixture 清单、日志或回复；
- 不使用 `LLM_*` 键，避免与 `pcm-demo` 的独立模型配置混淆；
- 缺少键、代理不可达或响应不兼容时，准确报告缺失条件，不伪造凭据、素材或替代服务。

## 调用前收敛

先读取与当前目标直接有关的事实：产品资料、UI/UX 框架或活动 TRD、目标仓库边界、资产目录约定、现有素材和 Git 状态。调用方必须明确：

1. 资源用途及其页面、组件、测试或数据语义；
2. 所需类型、构图、比例、风格、文字限制和无图/失败时的表现；
3. 资源来源：Pixabay、定制生成或既有 fixture；
4. 最终目标目录或由当前工程事实唯一确定的资产落点；
5. 是否只需要候选，还是已授权下载、生成或写入文件。

只需要候选时，不下载、不生成、不写入文件。未确定用途、目标位置或写入授权时，先返回需要确认的事项。

## Pixabay：受控候选与少量下载

Pixabay 只作为 AI Agent 开发期的受控来源，不是产品运行时搜索服务、业务数据源或可批量构建的素材库。

1. 每次只围绕一个明确视觉目标检索；不自动翻页、扩展关键词、并发扩大查询或建立预抓取集合。
2. 先展示有限候选，由 Agent 结合图像内容、OCR、构图、比例、主体语义、异常文字、水印、品牌标识和目标容器适配性进行抽查与比较。
3. 对下载行为，先明确选中的候选、用途和目标文件名；只下载少量已选资源，不用搜索结果批量填充数据库、Seed、列表、索引或用户内容。
4. API 返回的 URL 仅用于当前候选检查或下载，不能写入产品页面、数据库、Seed 或 fixture 清单作为长期链接。最终使用的资源必须下载并固化到对应项目资产位置。
5. 遵循 Provider 当时的条款与资源页事实。不能仅凭 API 成功推断人物肖像、商标、品牌、建筑或再分发场景一定可用；发现明显不适用内容时换候选或报告缺口。

产品 UI 默认不展示每张已固化静态图片的来源说明。只有产品自身向用户展示第三方搜索结果，或调用方存在明确授权、合同、审计或替换要求时，才按需要保留最小内部依据。

## 定制图片生成：仅限品牌视觉

本地代理兼容 `POST /images/generations`。仅在调用方已确认定制视觉目标时，使用根 `.env` 的 `MEDIA_IMAGE_*` 配置发起少量生成。

适用范围：Logo 图形方向、官网 Hero 图、品牌背景、定制插画等品牌表达资产。

不适用范围：

- 后端数据库、Seed、迁移、定时任务或批处理的图片填充；
- 商品、文章、城市、菜谱或其它业务记录的批量封面；
- 用户内容、用户上传文件或测试 fixture 的批量生产；
- 不断重试直到“看起来足够好”的无上限生成。

每次只围绕一个视觉目标生成单张候选；先比较并选择，再决定是否需要有限的下一候选。生成前明确尺寸、构图、色彩、主题、禁止元素和是否包含文字。模型图片中的文字不作为最终 Logo 或品牌名称：图形标记可以作为参考或资产，文字标识应由 SVG、字体或 CSS 保持可读、可维护和可替换。

首次使用某个本地代理时，核验其认证方式、base URL 是否已包含版本前缀、响应是 URL 还是 base64、支持的尺寸/格式字段与错误结构。不得因为代理不兼容而自动切换公共服务或安装新的 SDK。

## Fixture 维护与使用

Skill 目录下的 `.claude/skills/media-assets/assets/fixtures/` 保存可复现测试输入的维护说明和清单模板。真实 fixture 由维护者后续添加；本能力不在首次调用时自动下载或生成 fixture。

- Fixture 只用于上传、预览、格式、大小、失败状态等测试，不是产品静态资产或公开素材库；
- 测试优先复制稳定 fixture 到目标项目约定的测试目录，不在每次测试时联网搜索；
- 产品专属官网图、内容图或品牌图进入目标产品自己的资产目录；动态用户媒体、对象存储、权限、迁移和恢复由工程架构与活动 TRD 决定；
- 添加、替换或删除 fixture 时遵循 `.claude/skills/media-assets/assets/fixtures/README.md`，不记录 API key、Cookie、完整原始响应或临时下载 URL。

## 最终检查与汇报

完成后只汇报：资源用途、选择或生成依据摘要、最终文件路径、是否写入目标项目、使用的 fixture、适用的文件校验及尚未解决的缺口。不得回显秘密、临时 Provider URL、完整请求头或完整敏感提示词。

若当前操作会创建产品级对象存储、修改数据库、设计迁移、上传到外部生产服务或改变产品媒体策略，停止本能力的直接执行，交由相应的架构、TRD 或开发任务决定。
