# Media Provider Catalog

本目录保存 `media-assets` 已准入的第一方 Provider adapter。Provider 是当前 Skill 的内部适配说明，不是独立 Skill、Plugin、运行时模块或目标产品依赖。

## 受控 Catalog

| ID | 状态 | 能力 | 选择条件 | 说明 |
|---|---|---|---|---|
| `pixabay` | `available` | 搜索已有图片/视频、下载选定资源 | 需要通用图库素材，且现成媒体比定制生成更适合 | [`pixabay/README.md`](./pixabay/README.md) |
| `openai-compatible-image` | `available` | 通过 OpenAI-compatible Images API 生成单张 PNG | 需要品牌化或特定构图，生成目标、成本和写入范围已获授权 | [`openai-compatible-image/README.md`](./openai-compatible-image/README.md) |

Catalog 登记已有媒体检索与单张定制生图能力。调用方已有本地文件只需检查、固化或测试时，不经过 Provider 选择。

Catalog 是人工维护的闭集。核心 Skill 只使用本表登记的 Provider：

- 不递归扫描 `providers/`；
- 不因为出现新目录或 README 就自动注册；
- 不下载、安装或加载外部 Provider；
- 不执行 catalog 与核心能力合同之外的 Provider hook、安装器或任意脚本；
- 新增、停用或替换 Provider 时，必须同时审查并更新本 Catalog、对应 adapter 文档、工作区公开配置示例和相关 eval。

## Adapter 文档合同

每个已登记 Provider 的说明必须完整覆盖以下内容。

### 1. 身份与能力

- 稳定且唯一的 Provider ID；
- 当前状态；
- 支持的能力和输出媒体类型；
- 适用与不适用场景；
- 不能替代的产品运行时或基础设施能力。

### 2. 选择条件

- 什么任务语义允许选择该 Provider；
- 与其他能力类别的区别；
- 需要调用方明确决定的成本、来源权利或结果差异；
- 是否支持只查看候选或实际下载。

### 3. 配置合同

- 所需配置键和可公开默认值；
- endpoint、鉴权和版本前缀规则；
- 配置由调用方授权的受保护环境提供；固定工具入口定义工作目录 `.env` 读取规则时，adapter 必须明确优先级与不搜索范围；
- 文档只记录键名和公开值，不保存凭据、Cookie 或完整认证头。

### 4. 输入与归一化输出

- 允许的检索词或视觉 brief、尺寸、比例、格式、语言和文字约束；
- 请求前检查和接口适配；
- 如何把响应归一化为有限候选、已获取或已生成文件及明确错误；
- 候选至少能关联稳定 ID、预览信息、用途和必要的来源事实；
- 临时 URL、base64 或完整响应只用于当次处理，不进入产品或 fixture 合同。

### 5. 调用限制与错误行为

- 单任务查询、候选、下载、生成和重试上限；
- 有限批量获取的适用边界与所选 Provider 的能力、许可要求；禁止自动翻页扩词、遍历式下载和无明确用途的素材库囤积，不以限速替代许可判断；业务数据库与 Seed 逻辑由产品开发负责；
- 配置缺失、认证失败、限流、额度不足、响应不兼容、下载失败和内容不适用时的错误分类；
- 失败时报告真实缺口，不静默 fallback 到其它 Provider。

### 6. 内容与安全边界

- 许可、人物、商标、品牌、水印、敏感内容和署名的检查边界；
- 不把 API 成功等同于具体资源适用于所有用途；
- 不回显秘密、完整原始响应或敏感提示词；
- 不让 Provider 进入目标产品运行时配置或客户端。

### 7. 落盘与验证

- 选中候选或明确生成目标后才下载或保存；
- 校验真实 MIME、文件特征、尺寸或时长、体积、损坏和可读性；
- 按目标项目已有资产约定写入并核验实际引用；
- 临时 Provider URL 不得持久化；必要时记录文件哈希和最小内部来源依据。

## 扩展规则

新增与现有能力类别相同的 Provider 时，只需：

1. 新增 `providers/<provider-id>/README.md`；
2. 在受控 Catalog 登记唯一 ID、状态、能力、选择条件和精确路径；
3. 按需补充工作区公开配置示例；
4. 添加选择、失败和安全边界 eval。

只有新 Provider 改变了全局媒体能力、授权模型、安全政策、fixture 定义或产品边界时，才修改核心 `SKILL.md`。
