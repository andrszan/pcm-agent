# OpenAI-compatible Image Provider

## 身份与能力

- **ID**：`openai-compatible-image`
- **状态**：`available`
- **能力**：通过兼容 OpenAI Images API 的服务生成少量定制图片
- **适用**：Logo 图形方向、官网 Hero 图、品牌背景、定制插画及现成素材无法满足的明确构图
- **不适用**：数据库、Seed、迁移、定时任务或批处理配图；商品/文章/城市/菜谱等普通业务记录的批量封面；用户内容或 fixture 的批量生产

该 Provider 是开发期定制视觉工具，不是目标产品运行时模型依赖。

## 配置合同

| 配置键 | 必要性 | 说明 |
|---|---|---|
| `MEDIA_IMAGE_BASE_URL` | 必需 | 兼容服务的 API 基地址；是否已包含版本前缀必须按当前服务核验 |
| `MEDIA_IMAGE_API_KEY` | 必需 | 开发期访问凭据，只从调用方授权的受保护配置读取 |
| `MEDIA_IMAGE_MODEL` | 必需 | 当前服务可用的图片生成模型标识；本工作区公开示例提供当前默认值 |

不得回显配置值、完整认证头或把这些键写入目标产品配置。Adapter 不假定配置文件的物理路径。

## 选择条件

在以下条件同时成立时选择：

1. 任务需要原创、定制或品牌化视觉，通用图库素材不足以满足；
2. 已明确单一视觉用途、构图、比例、色彩、主题、禁止元素和目标位置；
3. 当前任务已经授权图片生成及其可能产生的成本；
4. 输出将作为少量正式候选，而不是批量内容生产。

若现有项目资产或搜索型 Provider 已能满足需求，优先复用或选择已有素材，不为体现“AI 生成”而生成。

## 接口适配

使用兼容服务的 `POST /images/generations` 能力。首次接入或服务配置变化时，先核验：

- base URL 与接口路径是否会重复版本前缀；
- Bearer 或服务实际要求的认证方式；
- 模型是否可用；
- 支持的尺寸、比例、质量、格式和数量字段；
- 响应返回 `data[].url`、`data[].b64_json` 或其它兼容形式；
- 错误响应、请求 ID、限流和超时结构。

只发送完成当前视觉目标所需的字段。不要保存完整请求头、完整原始响应或包含敏感业务信息的提示词。

归一化输出应包含：Provider ID、模型标识、脱敏视觉摘要、媒体数据或当次临时 URL、生成结果数量，以及明确错误类别。

## 成本与生成限制

- 默认每次请求生成 1 张；
- 每个明确视觉目标先检查首张结果，只有发现具体可修正缺陷且当前任务仍授权成本时，才生成有限的下一候选；
- 不使用“生成到满意为止”的无界循环；
- 不为数据库、Seed、列表、索引、用户内容或测试目录批量生成；
- 配置缺失、认证失败、模型不存在、接口不兼容、限流、额度或网络失败时停止并报告；
- 不自动改用公共服务、其它模型、搜索 Provider，也不安装 SDK 或 CLI 作为 fallback。

## 视觉质量与内容边界

- 生成前写清主体、构图、留白、目标容器、色彩、风格和禁止内容；
- 检查明显畸变、错误物体、异常文字、品牌冲突、敏感内容和目标视口适配性；
- 模型图片中的文字不作为最终 Logo、品牌名称或关键产品文案。文字标识应由 SVG、字体或其它可编辑机制实现；
- 生成能力不能替代真实用户上传、客户授权素材或需要事实准确性的内容图片；
- 提示词和输出仍须遵守当前服务条款、项目授权及适用内容规则。

## 落盘与验证

1. 对 base64 响应安全解码；对 URL 响应仅将 URL 用于当次下载；
2. 将最终选定文件写入目标项目已有资产约定的位置；
3. 校验真实 MIME、文件特征、尺寸、体积、解码完整性和可读性；
4. 通过目标项目实际构建或渲染检查构图、裁剪、文字叠加和目标视口；
5. 必要时记录 SHA-256、模型标识和脱敏提示词摘要；不保存临时 URL、完整响应或凭据。

某一结果不适用时，可以在已授权的有限预算内修正明确缺陷；不能静默切换 Provider。
