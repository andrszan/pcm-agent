# App Shell Contract

本参考帮助确定项目主框架，并留下后续页面应保持一致的决定。区域图是可选择、组合和补充的结构示例，不是固定模板、像素视觉稿或必须逐项填写的表单。

## 1. 记录要点

按项目需要，用简短说明、区域图或表格讲清：

- **表面与布局**：哪些用户或工作上下文使用哪种 Shell，哪些页面共享它。
- **导航关系**：主导航、上下文导航与页面内容如何分工；当前项、返回、深链进入和上下文保持的规则。
- **区域关系**：哪些区域常驻，哪些区域滚动，sticky 相对哪个容器生效；避免无意产生嵌套滚动或内容遮挡。
- **窄屏转换**：导航如何收纳，面板如何重排或改为页面栈，入口、当前对象和返回路径不丢失。
- **页面承载**：代表性列表、详情、编辑或任务流如何放入框架，内容宽度与密度是否合适。

新项目直接记录有依据的目标布局与适用范围，不为尚不存在的实现填写整套 Current／Target 表。既有项目涉及调整时，再说明当前实现、目标、实际偏差和必要迁移；不把目标写成现状。低风险且可调整的选择按项目事实决定，不为每个字段建立状态或审批流程。

确认边界统一见 [Skill 正文](../SKILL.md#确认边界)：按具体决定的实际影响判断，不因涉及安全或恢复等主题就机械请求确认。只保留需要负责人决定的具体问题，其余合同继续收敛。

## 2. 区域示例

图中 Header 表示顶栏，Nav 表示导航，Content 表示当前任务内容。区域位置不限定具体尺寸；页面模式和滚动方式可在同一 Shell 内变化。以下倾向不是按行业自动套用的规则，同一产品也可按不同表面组合使用。

### 顶部导航与内容区

```text
┌──────────────────────────────────────────┐
│ Brand    Global Nav       Account / Tools│
├──────────────────────────────────────────┤
│ Page Heading / Local Nav                 │
├──────────────────────────────────────────┤
│                                          │
│ Content                                  │
│                                          │
└──────────────────────────────────────────┘
```

适合全局入口较少、内容浏览或阅读为主的表面。内容通常随文档滚动，顶栏按需要 sticky 于视口；局部导航不重复全局导航。窄屏将入口收纳为菜单，保持内容自然阅读顺序。

### 全高侧栏与右侧工作区

```text
┌────────────┬─────────────────────────────┐
│ Workspace  │ Header / Global Tools       │
│            ├─────────────────────────────┤
│ Main Nav   │ Page Heading / Toolbar      │
│            ├─────────────────────────────┤
│            │                             │
│            │ Content                     │
│ Account    │                             │
└────────────┴─────────────────────────────┘
```

适合频繁跨模块切换的操作型工作区。侧栏可折叠为图标栏；在视口工作区中，内容区滚动，工具栏可常驻于内容区外或 sticky 于其滚动容器。长导航可独立滚动。窄屏侧栏转 Drawer，选择入口后关闭并进入对应页面。

### 全宽顶栏与下方上下文导航

```text
┌──────────────────────────────────────────┐
│ Brand / Workspace      Global Tools      │
├────────────┬─────────────────────────────┤
│ Context    │ Page Heading / Local Actions│
│ Nav        ├─────────────────────────────┤
│            │                             │
│            │ Content                     │
│            │                             │
└────────────┴─────────────────────────────┘
```

适合全局工作区、项目或产品切换与当前模块导航需要分层的表面。顶栏控制全局上下文，侧栏只展示该上下文内入口，不能重复一套导航。内容可随文档或独立区域滚动，按实际任务选定；窄屏保留上下文标识，将局部导航收纳为菜单或 Drawer。

### 导航、列表与详情

```text
┌──────────┬───────────────┬────────────────┐
│ Nav      │ Search/Filter │ Object Actions │
│          ├───────────────┼────────────────┤
│          │ List / Queue  │ Detail         │
│          │               │                │
│          │ Scroll A      │ Scroll B       │
└──────────┴───────────────┴────────────────┘
```

适合连续扫描、选择和处理对象的任务；不需要全局导航时可去掉左栏。列表与详情可以合理地独立滚动，各自头部常驻或 sticky 于所属区域。当前选择应驱动详情，返回后保留有用的筛选与位置。窄屏通常转为“列表 → 详情 → 返回列表”的页面栈，而不是直接隐藏列表。

### 工具栏、画布与属性面板

```text
┌──────────────────────────────────────────┐
│ Document / Exit          Save / Share    │
├────────┬─────────────────────┬───────────┤
│ Tools  │                     │ Inspector │
│        │ Canvas              │           │
│        │                     │ Properties│
│        │                     │           │
├────────┴─────────────────────┴───────────┤
│ Status                       Zoom / View │
└──────────────────────────────────────────┘
```

适合编辑器、流程编排、地图或创作工具。工具与属性区也可以浮动在画布上；画布平移／缩放与页面滚动要区分，属性长内容可局部滚动。窄屏按任务把面板改为按需打开的抽屉或底部面板，不能只压缩桌面三栏；保留必要的退出、保存和当前工具提示。

### 最小专注布局

```text
┌──────────────────────────────────────────┐
│ Back / Exit        Title      Save/State │
├──────────────────────────────────────────┤
│                                          │
│       Reading / Editing / Task           │
│                                          │
│       Primary Action / Next              │
└──────────────────────────────────────────┘
```

适合阅读、编辑、向导或需要减少干扰的单一任务，不强制保留全局侧栏。内容使用合适阅读宽度，长内容通常随文档滚动；必要的保存或步骤操作可常驻，但不能遮挡正文。窄屏保持自然单列，明确退出、返回与草稿保留方式，不把普通表单机械拆成向导。

### 移动端底部导航

```text
┌────────────────────────┐
│ Context / Page Title   │
├────────────────────────┤
│                        │
│ Content                │
│                        │
├────────────────────────┤
│ Home Search  Work  Me  │
└────────────────────────┘
```

适合少量、稳定且高频的一级入口。内容滚动时底栏保持可达，并为安全区和遮挡预留空间；对象详情或专注任务可进入带返回入口的页面。它可以是桌面导航的移动替代，也可以属于独立移动表面，不要求桌面机械沿用底栏。

## 3. 结合项目完善

依据实际用户任务选择骨架，再用代表性页面检查：入口和当前上下文是否清楚，内容与操作是否放得下，滚动与常驻区域是否互相干扰，窄屏是否仍能进入、处理和返回。

需要代码写法时查阅 [`布局资源索引`](./layout-resource-library.md)，复用适用的结构与交互实现。示例未闭合的路由跳转、当前项高亮、折叠、sticky 或响应式行为，由实现方按项目实际补齐；不因预览存在就认为这些行为已经成立。

框架文档记录跨页面需要一致的决定，组件拆分、具体 CSS、动效和页面美化由实际设计与开发完善，不在这里展开逐页实现规格。已有框架稳定、仅查阅参考时，无需重新记录上述内容。
