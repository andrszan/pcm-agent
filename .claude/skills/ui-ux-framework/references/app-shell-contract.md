# App Shell Contract

当产品级框架影响产品表面、主导航、上下文导航、App Shell、页面模式、sticky 区域、滚动模型或响应式转换时，使用本参考形成可被后续需求和实现引用的合同。

本合同描述设计边界，不直接生成业务页面、组件 API、CSS 规格或开发任务。

## 1. 决定状态

对每项决定明确标记：

- **Current**：由当前代码、配置、测试或真实运行证明的实现事实；
- **已确认 Target**：用户或仍有效的项目资料已经明确决定，但不一定完全实现；
- **默认 Target**：由已确认产品事实自然推导、低风险且可调整的工作目标；必须写明依据和重新评估条件；
- **需要确认**：不同选择会实质改变跨需求体验骨架、产品表面、核心任务路径、迁移成本或兼容性；
- **已知偏差**：Current 与 Target 不一致，或现有局部模式不得继续复制；
- **非目标**：本轮明确不设计、不迁移或不验证的范围。

不得把 Target 写成 Current，也不要因为一个高影响字段待确认，就让其余可判定字段全部停留在候选状态。

## 2. 自动收敛与确认边界

可以自主形成默认 Target 的事项通常包括：

- 已有产品表面和导航方向下的区域命名与职责澄清；
- 页面模式归属；
- 明确唯一常规滚动所有者；
- sticky 元素相对其滚动容器的边界；
- 不改变任务可发现性和结果的窄屏等价收纳；
- 由现有稳定模式自然延伸的低风险布局规则。

需要确认的事项通常包括：

- 新增、移除或重组产品表面；
- 改变主导航信息架构、跨角色关系或核心返回路径；
- 在 document scroll 与视口工作区之间迁移整个页面族；
- 窄屏隐藏、合并或替换主要入口，导致任务发现方式变化；
- 大范围迁移现有页面或破坏已发布定制兼容性；
- 改变权限、危险操作、失败恢复、全局术语或品牌基础语义。

需要确认时，只隔离并呈现真正有实质差异的决定，给出推荐、影响和迁移成本；其余合同继续完成。

## 4. 区域图规则

区域图用于表达稳定关系，不是像素视觉稿。每个区域应能对应合同表中的职责和滚动边界。

### 文档滚动示例

```text
viewport / document scroll
┌──────────────────────────────────────────────┐
│ sticky global header                        │
├──────────────────────────────────────────────┤
│ page heading and local navigation           │
├──────────────────────────────────────────────┤
│ content follows document reading order      │
│                                              │
└──────────────────────────────────────────────┘
```

### 视口工作区示例

```text
viewport
┌──────────────┬───────────────────────────────┐
│ navigation   │ app header / global tools     │
│              ├───────────────────────────────┤
│              │ sticky route toolbar          │
│              ├───────────────────────────────┤
│              │ main content scroll owner     │
│              │                               │
└──────────────┴───────────────────────────────┘
```

### 列表—详情示例

```text
viewport or bounded workspace
┌──────────────┬──────────────────┬─────────────┐
│ navigation   │ list / queue     │ detail      │
│              │ scroll region A  │ region B    │
└──────────────┴──────────────────┴─────────────┘

narrow screen: navigation drawer → list route → detail route
```

区域图旁必须说明：

- 纵向滚动的唯一常规所有者；
- 额外滚动区的任务理由；
- sticky 区域相对哪个容器；
- 内容是否会被常驻区域遮挡；
- 窄屏如何重排而不丢失入口、上下文和恢复方式。

## 5. 完成反查

合同完成前，使用一条能覆盖多个页面模式的代表性任务链反查：

1. 用户能否从正常入口找到任务；
2. 当前产品表面、工作区和对象上下文是否清楚；
3. 主导航、上下文导航和局部 tabs 是否职责分明；
4. 当前项、返回关系和深链重入是否明确；
5. 内容宽度和密度是否匹配阅读、扫描或操作任务；
6. 滚动所有者和 sticky 基准能否唯一指导实现；
7. 窄屏转换是否保持同一能力、权限和结果；
8. Current、Target、偏差和迁移是否没有互相冒充；
9. 后续需求能否只引用适用决定，而不复制整份框架；
10. 合同是否仍保持技术中立，没有变成组件或 CSS 清单。
