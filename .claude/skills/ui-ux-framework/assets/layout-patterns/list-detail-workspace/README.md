# List–Detail Workspace

一个用于比较“列表与详情并列滚动 + 窄屏单 pane 转换”关系的技术中立原生参考，不是项目默认布局，也不能直接作为品牌成品或生产实现。

## 适用条件

- 用户围绕一组对象连续扫描、选择和处理，需要在列表上下文与对象详情之间频繁切换。
- 宽屏有足够空间同时保留列表和详情，且两侧内容都可能独立增长。
- 列表当前项、详情标题和处理状态能够建立稳定的一一对应关系。
- 窄屏可以把并列 pane 转换为“先列表、后详情、可返回”的单 pane 任务流。

不适用于主要按自然阅读顺序向下展开的内容页，也不适用于必须同时对照三个以上区域、自由调整 pane 宽度或拖拽对象的高密度工作台。前者应优先使用 document scroll，后者需要另行定义多 pane、splitter 和操作反馈合同。

## 区域图

```text
viewport（100dvh；body 不滚动）
┌──────────────────────────┬────────────────────────────────────┐
│ 列表 pane（独立滚动）     │ 详情 pane（独立滚动）               │
│ ┌ sticky 列表头 ───────┐ │ ┌ sticky 详情头 ─────────────────┐ │
│ ├ 当前项与其它事项       │ │ ├ 当前对象背景、清单与最近记录     │ │
│ │ 列表继续向下滚动       │ │ │ 详情继续向下滚动                 │ │
└──────────────────────────┴────────────────────────────────────┘
窄屏：同一时刻只显示列表或详情；选择事项进入详情，返回后恢复列表位置。
```

## 滚动与 sticky 合同

- Shell 固定为 `100dvh`；`body` 不承载常规页面滚动。
- 列表 pane 和详情 pane 都设置 `min-width: 0`、`min-height: 0` 与 `overflow-y: auto`，两侧是彼此独立的纵向滚动所有者。
- 列表头使用 `position: sticky; top: 0`，定位基准是列表 pane；详情头使用相同规则，定位基准是详情 pane。
- 选择有效事项后，详情 pane 回到 `scrollTop = 0`；列表位置记录在 Shell 的 `data-list-scroll-top` 属性中。
- 示例内容在 `1440 × 1024` 下足以让列表和当前详情分别产生真实滚动，不依赖 `body` 或人为 spacer。

## 窄屏转换与焦点

在 `760px` 以下，Shell 通过 `data-mobile-view="list|detail"` 只显示一个 pane，初始值为 `list`。选择列表项前先验证其 `aria-controls` 指向的预置详情和详情标题；成功后切换到详情，并仅在窄屏把焦点移到带 `tabindex="-1"` 的详情标题。宽屏选择不会强制移动焦点。

详情中的“返回列表”会把 Shell 恢复为 `data-mobile-view="list"`，将非法的已记录 `scrollTop` 按 `0` 处理，恢复进入详情前的列表位置，并使用 `focus({ preventScroll: true })` 把焦点还给当前 `aria-pressed="true"` 的列表按钮。实现不监听 `resize`；当前视口只在用户选择时通过媒体查询判断。

## 演示交互

- 选择任一事项按钮，互斥更新列表项的 `aria-pressed`，并通过 `hidden` 切换关联详情。
- 每个列表按钮使用 `aria-controls` 指向一个预置 `<article>`；列表不使用 ARIA listbox 模式。
- 选择后将详情滚动位置重置到顶部。
- 在窄屏进入详情，并通过“返回列表”恢复焦点和列表滚动位置。

DOM 属性是演示状态的唯一来源：当前项由 `aria-pressed` 表达，当前详情由 `hidden` 表达，窄屏视图和列表恢复位置由 Shell 的 `data-*` 属性表达。控件具有可见焦点、约 `44px` 或更大的触控目标；当前项同时使用文字标记和结构边线，不只依赖颜色。动效遵守 `prefers-reduced-motion`。

## 非目标

- 不模拟真实鉴权、API、路由、实时同步、数据持久化或生产错误处理。
- 不提供搜索、复杂筛选、批量操作、键盘列表模式、拖拽 splitter 或用户可调 pane 宽度。
- 不提供品牌、设计 token、图标系统或可复制的业务文案。
- 不证明任何项目应采用列表—详情布局，也不替代目标项目的可访问性和浏览器验收。

## 文件

- `index.html`：语义结构、按钮与预置详情的关联，以及中性演示内容。
- `styles.css`：`100dvh` 双滚动 pane、各自 sticky 头部与窄屏单 pane 转换。
- `script.js`：详情验证、互斥选择、窄屏焦点和列表位置恢复。
- `desktop-preview.png`：`1440 × 1024`，初始状态，第一个事项选中，列表与详情均位于顶部。
- `mobile-preview.png`：`390 × 844`，从初始列表选择第一个事项后的详情状态，返回入口与详情标题可见。
