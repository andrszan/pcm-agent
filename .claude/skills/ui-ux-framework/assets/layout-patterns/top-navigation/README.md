# Top Navigation

一个用于比较“顶部主导航 + document scroll”关系的技术中立原生参考，不是项目默认布局，也不能直接作为品牌成品或生产实现。

## 适用条件

- 一级入口较少、层级较浅，横向显示不会挤压核心工具或换行。
- 用户以阅读、浏览或顺序查看页面内容为主，内容适合自然向下展开。
- 全局入口与页面局部 tabs 能清楚分工：主导航切换产品表面，tabs 切换同一页面的相关内容。
- 窄屏可以将完整主导航等价收纳到临时 Drawer。

不适用于模块很多且需要高频跨模块切换的操作工作区，也不适用于必须常驻多个独立操作面板的场景。入口增加、层级加深或全局工具竞争空间时，应重新比较侧边栏或复合 Shell。

## 区域图

```text
viewport / document scroll
┌─────────────────────────────────────────────────────┐
│ sticky 顶部栏：产品标识、主导航、全局操作            │
├─────────────────────────────────────────────────────┤
│ 页面标题、说明和局部 tabs                            │
├─────────────────────────────────────────────────────┤
│ 内容沿 document reading order 自然向下延展           │
│                                                     │
└─────────────────────────────────────────────────────┘
窄屏：横向主导航隐藏；菜单按钮打开包含同一入口的 Drawer。
```

## 滚动与 sticky 合同

- `document` / `body` 是唯一常规纵向滚动所有者。
- `<main>`、tabs 面板和内容卡片不建立内部主内容滚动区。
- 顶部栏使用 `position: sticky; top: 0`，相对文档滚动保持可见；内容顶端留出正常文档流位置，因此不会被遮挡。
- Drawer 是临时模态层，不改变 document 的内容滚动合同；关闭时焦点回到菜单触发器。

## 响应式转换

在 `760px` 以下，宽屏横向主导航隐藏，菜单按钮显示。原生 `<dialog>` 中展示同一组主入口；选择入口、点击关闭按钮、点击遮罩或按 `Escape` 都会关闭 Drawer，并把焦点还给触发按钮。局部 tabs 保留在内容区，允许换行而不变成 Drawer。

## 演示交互

- 点击主导航项，更新 `aria-current="page"`。
- 点击局部 tabs，或使用 `ArrowLeft`、`ArrowRight`、`Home`、`End`、`Enter`、空格切换 tab 与对应面板。
- 在窄屏打开、关闭和选择 Drawer 中的主导航项。

可操作控件具有可见焦点；tabs 同步 `aria-selected`、`aria-controls` 和 roving `tabindex`；菜单状态同步 `aria-expanded`。动效遵守 `prefers-reduced-motion`。

## 非目标

- 不模拟真实鉴权、API、路由、数据持久化或生产错误处理。
- 不提供品牌、设计 token、图标系统或可复制的业务文案。
- 不证明任何项目应采用顶部导航，也不替代目标项目的可访问性和浏览器验收。
