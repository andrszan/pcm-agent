# Sidebar Workspace

一个用于比较“侧边栏工作区 + 主内容独立滚动”关系的技术中立原生参考，不是项目默认布局，也不能直接作为品牌成品或生产实现。

## 适用条件

- 桌面端存在较多模块，用户需要在模块之间频繁切换。
- 一级入口下有稳定的分组或二级上下文，常驻导航能降低寻找成本。
- 页面偏操作、扫描或处理任务，需要让导航和页面工具持续可见。
- 产品可以接受窄屏时将相同入口收纳到临时 Drawer。

不适用于入口很少且阅读顺序主要自然向下展开的内容页面；也不适用于需要同时滚动多个对象面板的列表—详情工作区。后两类场景应先明确各自的滚动合同，而不是套用本示例。

## 区域图

```text
viewport（100dvh）
┌────────────────┬──────────────────────────────────────┐
│ 侧边栏         │ 主内容滚动区（唯一常规纵向滚动所有者） │
│ - 工作区标识   │ ┌ sticky 页面工具栏 ────────────────┐ │
│ - 多层导航     │ ├ 页面标题、筛选区、内容              │ │
│ - 收起控制     │ │ 内容继续在此区域向下滚动             │ │
└────────────────┴──────────────────────────────────────┘
窄屏：侧边栏隐藏；菜单按钮打开包含同一入口的 Drawer。
```

## 滚动与 sticky 合同

- Shell 固定为 `100dvh`；`body` 不承载常规页面滚动。
- 宽屏与窄屏均由 `.content-scroll` 承载常规纵向滚动；侧边栏不建立常规滚动区。
- 页面工具栏使用 `position: sticky; top: 0`，其定位基准是 `.content-scroll`，不是视口。
- Drawer 是临时模态层，不参与页面滚动所有权；关闭后返回打开它的菜单按钮。

## 响应式转换

在 `760px` 以下，桌面侧边栏和收起控制隐藏，菜单按钮显示。菜单以原生 `<dialog>` 打开，保留所有一级、二级入口和当前项语义；选择入口、点击关闭按钮、点击遮罩或按 `Escape` 都会关闭 Drawer，并将焦点还给触发按钮。

## 演示交互

- 收起或展开宽屏侧边栏。
- 展开或收起“资料管理”二级导航。
- 选择导航项，更新 `aria-current="page"`。
- 展开或收起筛选区。
- 在窄屏打开、关闭和选择 Drawer 中的导航项。

所有可操作控件均使用原生按钮或链接，具有可见焦点；侧边栏紧凑模式同步 `aria-pressed`，分组和筛选区同步 `aria-expanded`。动效遵守 `prefers-reduced-motion`。

## 非目标

- 不模拟真实鉴权、API、路由、数据持久化或生产错误处理。
- 不提供品牌、设计 token、图标系统或可复制的业务文案。
- 不证明任何项目应采用侧边栏，也不替代目标项目的可访问性和浏览器验收。

## 文件

- `index.html`：语义结构与中性演示内容。
- `styles.css`：`100dvh` Shell、单一主滚动区、sticky 工具栏与响应式 Drawer。
- `script.js`：导航、折叠、筛选和 Drawer 行为。
- `desktop-preview.png`：`1440 × 1024` 的桌面展开初始状态。
- `mobile-preview.png`：`390 × 844`、位于页首且 Drawer 打开的窄屏状态。
