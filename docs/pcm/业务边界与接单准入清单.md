# 业务边界与接单准入清单

> 定义「能做 / 不能做」的品类与交付层级边界，作为日常接单的决策依据。
> 处于项目初期，边界随实践修正。
> 最后更新：2026-06-24

---

## 一、核心原则

**只做 Demo / 产品原型 / 毕设层级，生产级一律不接。**

同一品类，做 demo 级可能可接，做生产级则坚决不接（例如电商：演示下单流程的 demo 可做，真要上线收钱、过支付资质、抗并发就远超性价比区间）。

---

## 二、5 个判断尺子

来单先用这 5 把尺子量。**任何一项踩红线，原则上婉拒。**

| 维度 | 高性价比（适合做） | 低性价比（避开） |
|---|---|---|
| **素材依赖** | 几乎不需要美术/内容素材 | 需要大量图片/音视频/3D 素材 |
| **测试成本** | 功能可自动/快速验证 | 需大量人力手测（多端、多场景） |
| **平台/审核** | Web、H5，无需上架审核 | App 上架、小程序审核、资质要求 |
| **AI 生成友好度** | 主流框架、模式标准（CRUD、表单） | 强算法、强性能、特殊硬件交互 |
| **定制化收敛度** | 改配置/字段就能复用 | 每单几乎从零定制 |

---

## 三、品类准入矩阵

| 品类 | 结论 | 关键原因 |
|---|---|---|
| **Web 管理系统/后台** | ✅ 主力 | 全维度都绿，复用性最高 |
| **企业官网/展示站** | ✅ 适合 | 简单、快、需求标准 |
| **数据可视化大屏** | ✅ 适合 | Python 强项，视觉效果好卖 |
| **产品原型/可点击 Demo** | ✅ 第二曲线 | 纯前端、无后端、客户专业 |
| **小程序（信息/工具类）** | 🟡 谨慎 | 能做，但有审核 + 多一套环境，Phase 3 再说 |
| **电商/商城** | 🟡 谨慎 | 涉及支付，真做要资质；**仅 demo 级可接** |
| **App（原生/RN）** | ❌ 避开 | 上架、多端测试、签名证书，麻烦且重 |
| **游戏** | ❌ 避开 | 素材 + 测试人力成本高 |
| **强算法/推荐/AI 模型** | ❌ 避开 | 答辩被深挖、调参耗时、不可控 |
| **区块链/IoT/嵌入式** | ❌ 避开 | 硬件依赖、环境复杂 |

---

## 四、接单红线（婉拒清单）

出现以下任一情况，婉拒：

- 要求生产级质量、上线运营、长期维护、版本迭代。
- 需要资质（支付、医疗、金融等持牌业务的真实上线）。
- 需要大量素材准备或多端人力测试。
- 强算法/强性能/特殊硬件依赖。
- 客户需求无法收敛、反复无边界变更。
