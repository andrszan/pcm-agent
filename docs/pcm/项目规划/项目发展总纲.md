# PCM 项目发展总纲

## 我们要做什么

PCM 要做的是一门定制软件生意，以及支撑这门生意的内部生产系统。

对外，我们提供价格较低、开发较快、质量可靠、按需求重新设计的 Web 软件。内部怎样开发、使用哪些工具，属于我们的生产方法和商业秘密，不作为宣传重点。

## 整个项目有哪些部分

### 1. 定制软件业务

负责找客户、确认需求、报价、收款、开发、验收和交付。

### 2. 现有产品销售

把已经完成的产品整理成可以展示和出售的商品，确定价格、授权和交付方式。

### 3. 官网和商业平台

早期先做官网、产品展示和咨询入口。以后再增加客户登录、订单、支付和在线交付。

### 4. PCM 生产系统

负责真正生产客户项目，包括项目创建、开发流程、运行状态、质量检查、成本和交付物管理。

当前 `pcm-demo` 是前期验证工具。正式 PCM 会吸收已经验证有效的做法，但不会直接照搬 Demo 的本地实现。

### 5. 基础资源和运维

包括域名、服务器、数据库、对象存储、邮件、备份、监控、私有 Git 和第三方服务。

### 6. 内部开发能力

包括基础工程、通用组件、布局参考、开发规则和 Agent 能力。

我们不维护业务模板。每个项目的业务流程、数据模型、页面内容和最终组合，都根据需求重新完成；基础工程和通用组件可以复用。

## 几部分怎么配合

```text
官网和宣传带来咨询
        ↓
人工确认需求、报价和收款
        ↓
PCM 生产系统完成项目
        ↓
人工验收、交付和结算
        ↓
订单数据反过来改进价格、流程和系统
```

早期先用人工连接各部分。只有当某项人工操作反复出现、明显浪费时间或容易出错时，才把它做成系统功能。

## 发展阶段

### B0：前置准备

完成商业构想、开发流程和 `pcm-demo` 核心验证。这个阶段已经基本完成。

### B1：真实市场与交付验证

开始宣传、建设官网、准备资源、接真实订单、完成交付、记录成本，同时继续完善 PCM 生产能力。

### B2：稳定交付与正式 PCM

根据真实订单收敛服务、价格和流程，正式建设 PCM 生产系统。

### B3：商业平台化

当人工运营已经成为瓶颈后，再建设客户门户、订单、支付、在线交付和两套系统的自动协作。

## 当前原则

- 对外讲产品和结果，不主动讲内部开发技术；
- 不虚构不存在的团队和服务；
- 低价是优势，但价格必须覆盖真实成本；
- 不做业务模板，合理复用基础工程和通用组件；
- 交付什么、多久交付、怎么验收，都在订单里写清楚；
- 产品根管理仓、内部流程、Prompt、运行记录和秘密不交付；
- 先完成真实订单，再根据实际问题建设更多系统；
- 不追求一次把所有事情做完。

当前阶段的完整任务见 [B1：真实市场与交付验证](./阶段/B1-真实市场与交付验证/README.md)。
