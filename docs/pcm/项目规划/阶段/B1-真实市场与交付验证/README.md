# B1：真实市场与交付验证

## 这一阶段要得到什么

B1 结束时，我们应该已经：

- 有一套能对外展示的品牌和官网；
- 有明确的服务、价格和交付内容；
- 准备好域名、服务器和必要的第三方服务；
- 开始通过真实渠道获得咨询；
- 完成至少一个付费定制订单；
- 完成项目开发、验收、交付和结算；
- 知道一个订单实际花了多少钱和多少时间；
- 知道正式 PCM 和商业平台接下来最应该做什么。

## W01 市场与需求验证

**要做什么**

- [ ] 建一张简单的咨询记录表；
- [ ] 记录客户想做什么、预算、时间、指定技术和最终是否成交；
- [ ] 定期整理最常见的需求和不成交原因。

**怎么做**

每次咨询只记完成判断需要的信息，不额外收集无关个人资料。先用表格记录，不开发系统。

**完成结果**

能够说清楚市场上最常见的需求、客户最关心什么，以及当前主要为什么成交或流失。

---

## W02 产品与服务设计

**要做什么**

- [ ] 确定“现有产品购买”和“定制开发”两种服务；
- [ ] 写清楚当前能做的 Web 项目范围；
- [ ] 写清楚每种服务包含什么、不包含什么；
- [ ] 确定源码、文档、部署和售后分别怎样提供。

**怎么做**

先做一页服务清单，客户能在几分钟内看懂即可，不急着设计很多套餐。

**完成结果**

面对一个咨询时，能够直接判断应该推荐什么服务，以及交付什么内容。

---

## W03 价格与报价

**要做什么**

- [ ] 明确 800～1200 元适用于什么范围；
- [ ] 确定哪些情况需要加价；
- [ ] 确定部署、额外修改和第三方费用怎样收费；
- [ ] 做一份简单报价模板；
- [ ] 每个订单结束后调整价格依据。

**怎么做**

报价先看范围和完整成本，不只看模型费用。第一阶段不需要复杂报价系统，用表格和模板即可。

**完成结果**

收到需求后可以快速给出有依据的价格，不靠临时拍脑袋。

## W04 品牌定位与宣传内容

**要做什么**

- [ ] 确定品牌名称和一句话介绍；
- [ ] 写清楚价格低、速度快、质量可靠和高度定制的优势；
- [ ] 准备服务介绍、交付内容、常见问题和联系文案；
- [ ] 选择可以公开展示的产品和截图；
- [ ] 确定哪些内部开发信息不对外公开。

**怎么做**

所有内容围绕客户能得到什么，不介绍内部 Agent、Prompt 和自动化流程。

**完成结果**

形成一套官网、渠道发布和客户沟通都能直接使用的基础文案。

## W05 官网与对外入口

**要做什么**

- [ ] 确定官网页面；
- [ ] 完成首页、服务、产品或案例、价格说明和联系入口；
- [ ] 接入真实可用的咨询方式；
- [ ] 完成电脑和手机端检查；
- [ ] 配置域名并正式上线。

**怎么做**

B1 先做简单官网，不做客户登录、订单中心和在线支付。网站的任务是介绍清楚并带来咨询。

**完成结果**

客户打开一个正式网址，就能了解服务、查看产品并联系到我们。

## W06 宣传渠道与获客

**要做什么**

- [ ] 选择首批一到两个渠道；
- [ ] 准备并发布第一批内容；
- [ ] 记录每条内容带来的浏览、咨询和成交；
- [ ] 根据反馈调整标题、案例、价格和表达；
- [ ] 找到值得继续投入的渠道。

**怎么做**

小范围测试，不同时铺很多平台。内容以真实产品、实际功能和交付结果为主。

**完成结果**

至少有一个渠道能够持续带来真实咨询，或者明确证明当前方式无效并知道怎样调整。

## W07 销售与订单流程

**要做什么**

- [ ] 确定咨询后需要确认的问题；
- [ ] 确定需求、范围、报价和交付内容的确认方式；
- [ ] 建立订单状态表；
- [ ] 确定什么时候收款、什么时候开始开发；

**怎么做**

**完成结果**

## W08 合同、付款与经营规则

- [ ] 准备简单合同或订单确认文件；

**完成结果**

能够正常收款和签单，出现变更或争议时有明确依据。

**完成结果**

## W10 定制订单首单闭环

**要做什么**

- [ ] 获得一个真实付费定制需求；
- [ ] 确认功能范围、交付内容和不做的内容；
- [ ] 完成报价和首款；
- [ ] 准备客户材料和开发资源；
- [ ] 使用当前生产流程完成开发和验证；
- [ ] 提交第一版验收包；
- [ ] 完成范围内修改和客户验收；
- [ ] 完成最终交付和结算；
- [ ] 记录成本、周期和问题并完成复盘。

**怎么做**

按“需求确认—报价收款—开发—验收—交付—复盘”的顺序执行。当前希望验证普通项目正式开工后约 7 天提交第一版验收包，但以实际订单范围为准。

**完成结果**

至少一个定制订单完成付款、开发、验收、交付和结算，并留下真实成本和改进结论。

## W12 售后与问题处理

**要做什么**

- [ ] 确定交付后包含多长时间的问题修复；
- [ ] 区分 Bug、理解差异和新增需求；
- [ ] 确定免费处理和收费处理的范围；
- [ ] 确定客户反馈问题的方式；
- [ ] 确定项目什么时候正式关闭。

**怎么做**

售后规则写进订单，不提供无限期维护。每次问题只判断是否属于原范围。

**完成结果**

交付后出现问题时，双方知道哪些免费处理、哪些需要重新报价。

## W16 商业平台与系统协作

**要做什么**

- [ ] 明确官网在 B1 只承担哪些功能；
- [ ] 设计订单和 PCM 项目的简单编号关系；

**完成结果**

商业订单和内部项目能够清楚对应，并得到商业平台第一版应该做什么的真实依据。
