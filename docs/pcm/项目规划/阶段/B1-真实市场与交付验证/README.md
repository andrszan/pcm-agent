## W01 市场与需求验证

**定稿方案**

从真实咨询、付款和交付中判断哪些需求有人买、哪些订单值得接、哪里需要调整，不另做一轮大规模市场调研。现有产品购买和全新定制分别统计。

**要验证什么**

- 咨询中反复出现哪些产品需求和功能；
- 客户是否实际支付 800 元、1000 元或 1200 元，不只看口头认可；
- 客户是否接受源码、Git 历史、文档及本地运行交付；
- React 和 Python 能覆盖哪些实际需求，哪些需求因指定技术而流失；
- 已成交需求的实际成本和人工投入是否可接受。

**记录与复盘**

- 复用 W06 渠道记录和 W07 咨询、订单记录，不另建调查表；保留咨询来源及对应内容或产品、主要功能、指定技术和第三方依赖、价格与本地交付接受情况、B1 承接判断、报价付款成交情况，以及已知的未成交原因；
- 从正常沟通获得信息，不额外调查身份、职业或购买用途；不清楚的记为未知，不把报价后未回复直接解释为嫌贵，也不反复追问；同一笔需求的多次聊天不重复计为独立咨询；
- 区分我们主动不接、客户明确不接受、暂时没有结果三种情况；范围或能力不匹配不直接算成客户不认可产品，不能硬填未成交原因；
- 每周与 W06 渠道复盘合并查看新增需求、范围匹配、报价付款、明确障碍及信息不足之处，没有新信息就不写总结；
- 订单关闭后结合 W13 的成本、人工和售后记录，判断同类需求是否值得继续承接；发现问题先区分渠道、说明、信任或服务匹配原因，不立即降价、扩范围或承诺更多维护。

## W03 价格与报价

**定稿结论**

- B1 只接难度较低、预计不会亏损的订单，项目总价统一使用 800 元、1000 元或 1200 元三档；
- 800 元用于内容较少、流程简单的项目，1000 元用于普通小型完整项目，1200 元用于内容相对较多或包含常见第三方服务接入的项目；
- 预计 1200 元仍不能覆盖成本，或者开发难度超出当前能力范围时，B1 直接不接；
- 定制开发价格已经包含最终业务成果的独家买断，不单独收取买断费用；
- 第三方服务接入代码及开发和验收期间的必要资源使用包含在项目报价中；交付后由客户按照交付文档自行获取并承担第三方账号、授权和资源费用；
- B1 不提供现有产品购后功能增改或界面定制、客户数据处理、生产环境部署、长期托管和持续维护，因此不为这些项目报价；后续是否提供根据商业化情况决定；
- 交付前修复原范围内的缺陷，交付后免费 Bug 修复按 W12 的 14 个自然日规则处理；新增或改变需求不包含在原报价中。

**透明报价**

每份报价按实际工作列出金额，但总价只使用当前三个档位：

```text
需求和项目设计：       ___ 元
页面与交互开发：       ___ 元
业务功能与数据开发：   ___ 元
第三方服务接入开发：   ___ 元
测试、源码和文档交付： ___ 元
项目总价：             800 / 1000 / 1200 元
```

同时写清楚包含功能、不包含内容、交付方式和预计周期。涉及第三方服务时，注明开发和验收期间的必要资源使用已经包含，交付后由客户按照文档自行获取相关账号、授权和资源。报价不展示内部 Agent、模型成本和生产方法。

- [x] 确定 800 元、1000 元和 1200 元三档判断方式；

## W07 销售与订单流程

**定稿流程**

收到咨询 → 了解需求 → 判断是否能接 → 文字确认范围和报价 → 收到首款 → 正式开工。

- 只确认产品、主要流程、必做与可暂缓功能、前后端范围、技术栈、第三方服务、已有材料和期望时间；同时确认客户接受三档报价、本地运行交付并具备基础操作能力，不调查无关身份和购买用途；
- 只接需求清楚、难度较低、当前能力可以完成、报价能覆盖成本且预计约 7 天提交首版的项目；必要材料和第三方条件应能在开工前准备好；
- 超出能力、预计亏损、周期无法满足，或客户不接受当前交付方式时不接，只说明不适合当前服务；
- 将需求和 W03 报价单发给客户，以可留存的文字确认；语音沟通后也要整理成文字，不依赖零散聊天直接开工；
- 需求、报价、材料、第三方条件和起算时间确认完成，并收到 W08 约定的首款后才正式开工；开发期间的第三方资源由我们准备，费用包含在报价中；
- 开工前可以重新确认范围、报价和周期；开工后处理原范围内明显 Bug，理解差异按确认记录判断，新增或改变需求先记录，不加入当前订单，也不承诺交付后追加开发；B1 不承接现有产品购后功能增改或界面定制。
