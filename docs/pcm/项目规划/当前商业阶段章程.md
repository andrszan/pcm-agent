# PCM 当前商业阶段章程

> 这是一份内部工作章程，指导当前如何接需求、报价、交付和复盘。
> 当前阶段：B1 真实市场与交付验证
> 生效日期：2026-09-04

## 一、当前阶段要达到什么

我们现在不是先做一个完整的客户平台，而是先把真实交付跑通。

当前目标是：找到真实客户，明确订单范围，按约定完成软件，交付必要内容，记录完整成本，再根据结果调整价格、服务和系统规划。

## 二、对外怎么说

对外只讲客户关心的事情：

- 可以做什么类型的软件；
- 能交付哪些内容；
- 大致需要多长时间；
- 价格如何确定；
- 怎样验收；
- 哪些内容不包含在订单里。

我们暂时不主动介绍内部使用的 AI Agent、自动化流程、Prompt、模型和生产细节。这些是内部生产方式和商业秘密。

但“不主动介绍”不等于编造事实。对外不能虚构不存在的团队、岗位、多人协作或服务能力，也不能在被直接询问时作与事实相反的回答。技术细节可以在合理的商业保密范围内不展开。

## 三、我们提供什么

当前提供的是按需求定制的软件项目，不是固定的业务模板商品。

每个项目都会重新确认：

- 做给谁用；
- 要解决什么问题；
- 需要哪些页面和功能；
- 哪些流程必须跑通；
- 使用什么运行环境；
- 最后交付哪些源码和文档。

我们可以复用基础工程、脚手架、通用组件和布局参考，但不维护可直接套用的行业业务模板。基础能力的复用，是为了提高质量和速度，不代表业务内容没有重新设计。

## 四、交付内容怎么分

内部用三个等级帮助报价、排期和验收。它们都不是生产级系统，具体内容必须写进订单。

| 等级 | 说明 | 适合的交付结果 |
|---|---|---|
| **E1 交互展示级** | 页面和主要操作可以真实展示，可使用样例数据 | 展示页面、操作流程、界面状态和交互效果 |
| **E2 功能验证级** | 约定的核心功能可以在开发环境完成闭环 | 输入、处理、数据变化、角色操作和结果验证 |
| **E3 集成展示级** | 前端、后端、数据库或订单约定的开发服务能够一起运行 | 多角色、跨页面、跨模块的完整展示和验收 |

每个订单必须明确：页面和功能范围、数据是否真实、使用哪些环境、支持哪些浏览器和尺寸、测试到什么程度、交付哪些文档，以及明确不做什么。

“质量好”不能单独作为验收标准；验收以订单中的具体范围和用例为准。

## 五、服务边界

当前只提供完成订单所必要的服务和文档，不提供：

- 课程教学和系统培训；
- 逐行代码讲解；
- 无限次修改；
- 无限期维护；
- 没有写入订单的生产部署、运营保障或第三方资质办理。

可以提供必要的安装、启动、配置、开发账号、初始化、验收和已知限制说明。这些是交付的一部分，不是教学服务。

客户提出新增需求时，先判断是否超出原范围。超出范围的内容重新报价和排期，不通过口头沟通无限扩大订单。

## 六、价格怎么定

人民币 800～1200 元是当前首轮试单的内部低盈利价格假设，不是所有项目的统一售价，也还没有被真实市场证明。

每个订单先确定交付等级和范围，再估算价格。完整成本包括：

- 模型和 API；
- 开发、测试、部署及其它服务；
- 全部实际投入时间；
- 软件订阅、设备和固定资源分摊；
- 获客；
- 支付渠道；
- 税费；
- 返工、退款、延期和失败重跑风险。

```text
完整成本 = 上述所有成本之和
```

如果完整成本和合理收益覆盖不了，就调整报价、范围或交付等级，不靠漏记成本维持低价。订单结束后记录实际成本和结果，用于修正下一次报价。

## 七、客户最终拿到什么

### 默认交付

以订单写明的内容为准，通常包括：

- 前端和/或后端应用源码快照；
- 必要的安装、启动、配置和运行文档；
- 必要的开发账号、初始化和验收说明；
- 已知限制、验收结果和订单约定的资源。

### 默认不交付

以下内容属于内部资料，不作为客户默认交付物：

- 产品根管理仓；
- PCM 能力仓和内部规则；
- 内部 Prompt、Agent 会话、运行记录和诊断；
- 内部成本、模型配置和其它客户资料；
- 密钥、token、密码、`.env` 和外部系统凭据；
- 前端和后端 `.git` 历史。

前后端 Git 历史目前只是默认不交付，后续可以单独讨论，不代表永久禁止。内部开发仍然使用真实 Git 记录，不补造历史。

如果必要交付说明只存在于内部根管理仓，应整理成独立、干净、不含内部秘密的文档后再交付，不能直接把根仓交给客户。

## 八、每个订单都要记录什么

不论客户是谁，每个订单都按同一套方式记录：

1. 需求和范围；
2. 交付等级；
3. 报价和付款；
4. 预计投入和完整成本；
5. 需求冻结时间；
6. 修改和延期；
7. 测试、运行和验收结果；
8. 最终交付清单；
9. 售后、退款或争议；
10. 这次订单对价格、周期和交付方式带来的新结论。

客户资料只记录完成订单所需要的内容，不额外收集与交付无关的个人信息。

## 九、当前明确不承诺的内容

当前不把以下内容写成默认能力或默认承诺：

- 任何项目都能在一周内完成；
- 所有项目都适合当前 React + Python 技术范围；
- 生产级安全、高并发和长期稳定运营；
- 真实支付、持牌业务和复杂外部平台接入；
- 多端上架和复杂硬件；
- 无限修改、长期维护和永久免费托管；
- 正式 PCM 或商业平台已经上线。

这不是否定未来方向，而是把当前承诺限制在真正能够负责的范围内。

## 十、什么时候修改本章程

出现以下情况时，重新讨论并更新本章程：

- 真实订单证明价格或周期需要改变；
- 反复出现同类需求，值得固定成服务包；
- 客户经常要求新的技术架构；
- 交付或售后成本明显变化；
- Git 历史、部署或维护成为成交关键；
- 人工运营已经成为主要瓶颈。

没有明确讨论和记录之前，不能把未来设想当作当前承诺。
