# BOSS直聘 AI 精准投递助手

> 自动化高效筛岗与个性化求职沟通
>
> **自动批量收集候选岗位，精准筛选机会，高效完成个性化沟通。**

- 英文名称：**BOSS AI Apply Assistant**
- 工程标识：`boss-ai-apply-assistant`
- 产品形态：面向 BOSS 直聘网页版的 Chrome 扩展，配合扩展自身的全页工作区。
- 目标用户：有明确求职方向，需要同时推进多个机会，希望减少重复操作并保留沟通主动权的求职者。
- 文档性质：产品初稿，用于统一需求、交互和业务边界；局部设计提案与平台适配未知分别标明。
- 创建日期：2026-10-09

本产品是独立第三方求职辅助工具。工程标识用于后续 Agent 工作区和项目目录命名，名称不代表代码仓库已经创建。

## 产品主张：批量执行，精准选择

求职者面对的问题不仅是操作耗时，也包括候选岗位多、可主动沟通的名额有限、个人经历难以在有限篇幅内完整表达。每天尽快用完沟通名额，不等于找到更合适的机会。

本产品将过程分成三个部分：先用明确规则自动收集候选岗位，再结合真实经历进行 AI 匹配分析，由用户选择值得联系的机会，最后批量自动生成并发送个性化招呼。精准体现在岗位选择和内容针对性上，而不是要求用户逐个处理。

用户只需配置目标、选择联系范围并启动任务。筛选收藏、批量生成和逐个发送由插件执行。收到 HR 回复后，用户利用 AI 建议继续沟通；需要定向简历时，主动生成、下载并自行上传发送。

### 谁最能受益

- 已有目标城市、岗位方向和基本要求，反复搜索、收藏与打招呼占用大量时间的人。
- 有工作、项目或实践经历，能力不完全体现在原始简历中，希望针对岗位突出相关事实的人。
- 同时推进多个求职机会，希望把精力留给有效回复、面试和重要决定的人。

技术、产品、设计、运营等岗位均可使用。资料是否充分影响辅助效果，用户可以从简历和少量偏好开始，不必一次完成长问卷。

### 用户获得的结果

- 自动建立符合明确条件的候选岗位队列。
- 快速看到岗位与自身经历的主要相符点和缺口，并自行取舍。
- 一次启动后，为选中的多个岗位完成各自的个性化首次招呼。
- 在真实对话中得到可编辑、可调整的回复建议。
- 按需获得真实、针对当前岗位的 PDF 简历副本。
- 在本机查看求职进展，清理候选队列，并导出需要留存的内容。

## 已确认的需求与设计提案

### 已确认的产品约定

1. 产品名为「BOSS直聘 AI 精准投递助手」，描述必须突出自动化、高效与精准。
2. 收藏夹是待打招呼的临时队列。按平台现有条件与少量列表级关键词规则自动新增收藏 N 个岗位。
3. 收藏筛选采用确定规则。对已收藏岗位再做 AI 匹配分析，给出分数与简单理由，由用户决定是否清理低分岗位。
4. 支持一键取消收藏已撤销的岗位，以及一键取消收藏已打招呼的岗位。
5. 首次招呼支持用户预先上传的简历图片，目标为图片先发，随后发送文字；每组招呼控制在 2～5 条消息内。
6. 为选定岗位批量生成个性化招呼，并逐个自动发送。用户不需要逐条点击发送(注意安全机制，考虑是否加时间间隔)。当然，批量生成招呼语和自动发送可以分开来执行。因为用户担心自动话的话会触发风控，所以用户也可以自己点击复制发送招呼语。
7. 提供「招呼发送完成后，自动取消收藏」设置，整组消息成功后执行。
8. 后续回复由 AI 辅助表达，用户可以编辑、重新生成或说明调整方向，最终发送由用户决定。
9. 定向 PDF 简历由用户主动点击生成，保留原件；用户下载副本，自行上传到 BOSS 并发送。
10. 提供用户自己的本地统计、岗位内容归档和数据备份。
11. 扩展独立运行，主要资料保存在本地；少量设置使用 Chrome 同步，AI 使用用户自行配置的服务。
12. 支持 OpenAI-compatible API 与 Anthropic Messages API；浏览器交互和必要的 BOSS API 调用均可作为适配手段。(尽量使用浏览器交互的方式,用户最担心的就是账号降权和封号)

### 本稿采用的交互设计提案

以下是为使流程可实施而补充的默认方案，不冒充用户逐项确认的要求：

- 使用「BOSS 页面侧栏＋扩展全页工作区」组织界面。
- 收藏完成后展示「分析收藏岗位」入口，由用户批量发起评分；评分使用 0～100 分和简短理由。
- 每组招呼的 2～5 条按总消息数计算，图片计入一条；默认三条，实际由用户设置。
- 自动取消收藏默认关闭；用户开启后应用于之后启动的发送任务。
- 批量生成可预览，也可在设置好规则、选定岗位后直接启动生成与发送；逐条审阅为可选操作。
- 定向简历先形成可编辑的内容草稿，再预览和导出 PDF；默认采用稳定的输出版式，保留原始 PDF 供参考。原版式保留程度作为明确的适配问题处理。
- 归档采用可选内容的文件包，岗位汇总与单岗阅读材料分别组织。

## 用户的完整使用过程

1. 安装扩展，在设置中配置 AI 服务并测试连接。
2. 上传原始简历，确认解析结果，补充求职偏好和愿意提供的经历；按需上传用于首次招呼的简历图片。
3. 在 BOSS 网页设置城市、薪资等原有筛选条件，在插件中补充少量关键词和收藏数量，启动自动收藏。
4. 收藏完成后，批量分析岗位匹配度，按分数和理由比较；用户可以批量取消低分、失效或已联系岗位的收藏。
5. 选择本次准备联系的岗位及数量，配置招呼风格、条数和图片，启动批量生成与自动发送。
6. 任务逐岗执行，用户可查看进度、暂停或结束；开启自动清理时，在整组发送成功后取消对应收藏。
7. HR 回复后，用户在当前会话旁生成、编辑和调整话术，自行发送。
8. 用户需要定向简历时主动生成并下载 PDF 副本，再通过 BOSS 上传和发送。
9. 用户在本地统计中回顾进展，按需导出选中岗位材料或备份本地资料。

**收藏目标数量与本次联系数量是两个独立概念。** 收集到 N 个候选岗位，不代表要联系 N 个岗位；平台每日沟通额度是约束，不是必须用完的目标。

## 产品表面与主要入口

### BOSS 页面侧栏

侧栏服务当前页面和当前会话，显示明确的岗位、公司或聊天对象，避免用户不知道 AI 正在针对谁生成内容。

- 列表页：补充筛选条件、设置收藏数量、启动任务、查看进度。
- 岗位页：加入候选、查看匹配摘要、查看或生成招呼。
- 聊天页：查看关联岗位与必要上下文，生成和调整回复，进入定向简历生成。
- 任务运行期间：展示正在处理的岗位、计数、当前状态，以及暂停、继续和结束按钮。

### 扩展全页工作区

全页承载需要较大空间的操作，主要入口为「候选岗位」「个人档案」「简历」「个人统计」「设置」。

- 候选岗位：批量分析、排序、清理、选择联系对象和启动发送。
- 个人档案：确认解析内容、补充资料、管理表达边界。
- 简历：原件管理、当前定向稿编辑、PDF 预览和下载。
- 个人统计：进度计数、趋势、对应业务记录及归档入口。
- 设置：模型服务、招呼偏好、自动清理、少量设置同步和数据备份。

工作区由扩展提供，用户直接打开使用；跨设备的少量设置同步由 Chrome 账号及浏览器同步能力承担。

## 个人档案：真实事实、求职偏好与表达边界

### 从已有简历开始

用户上传原始 PDF，系统提取教育、工作、项目、技能等内容，以可编辑字段和段落展示。姓名、日期、职责、项目成果等关键内容需要用户有机会核对；解析不清的位置明确标出。

不能提取文字的文件应给出实际原因和可操作的补录方式，而不是生成一份看似完整的虚构档案。用户可以直接粘贴文本补充资料，解析能力的具体覆盖范围在开发验证中确认。

### 可选补充，不以完整问卷阻挡使用

档案分为三组：

- **事实经历：** 项目背景、个人职责、技术或业务能力、实际成果、团队分工、协作经历、简历未写入的技能等。
- **求职偏好：** 岗位方向、城市、薪资预期、工作方式、出差接受度、入职时间等。
- **表达边界：** 离职原因、谈薪底线、其他个人情况的可使用范围。

补充方式同时支持直接编辑、粘贴长说明和主题问答。主题问答围绕实际缺口提问，用户可以跳过。例如岗位涉及团队协作，而资料不足时，询问是否承担过任务分配、评审或新人指导，再由用户确认提取的事实。

性别等个人信息按用户意愿提供，不作为资料完整度的必填门槛。工作年限可以从经历中辅助计算，但日期冲突或重叠需要明确提示，不替用户推定。

### 信息可以辅助判断，不代表可以对外披露

用户可将内容设为「可用于求职表达」或「仅供内部参考」。内部参考信息可以影响筛选建议或表达策略，但不得直接出现在招呼、回复或简历中。例如薪资底线用于理解谈判边界，不自动成为报价。

AI 使用真实、已确认的材料。资料未写某项能力，不能直接断言用户不会；同样，未经确认也不能把它写成用户已经具备。用户修正资料后，后续生成使用当前内容，正在展示的旧草稿保留为待重新生成的草稿，不自动发出。

## 自动收藏：少量规则，批量执行

### 条件来源与任务范围

用户在 BOSS 页面使用现有城市、薪资、经验等筛选条件。插件使用当前有效搜索结果作为任务来源，并明确显示当前搜索范围。

插件补充三个简单字段组：

- 岗位名称包含词与排除词。
- 列表已提供的职位／技能标签关键词。
- 公司名称包含词与排除词。

同一组多个包含词建议按「至少命中一个」处理，不同字段组同时满足；排除词命中时排除。空字段组不增加约束。输入框提供简短例子，避免让用户编写表达式。列表未提供用户要求的标签时，应标明无法判断并跳过，不为这个条件额外读取详情。

收藏筛选只使用列表已提供的数据，不通过 AI 判定是否收藏，也不为关键词筛选逐岗读取完整 JD。匹配分析、个性化招呼或简历生成需要正文时，再针对正在处理的收藏岗位按需读取。

### 数量语义

用户填写的是「本次新增收藏 N 个岗位」。只有平台实际收藏成功的新增岗位才计入 N：

- 已经收藏过的岗位不重复计数。
- 同一岗位重复出现时去重。
- 用户已联系的岗位应在状态可确认时跳过，避免回到待联系队列。
- 收藏失败不计入成功数。

达到 N 后停止收藏；搜索范围耗尽时按实际数量结束，并简明汇总排除原因。系统不为凑数擅自放宽条件。用户可以修改条件后再次启动。

### 任务过程

显示已扫描、规则符合、新增收藏成功、跳过及失败数量，以及当前岗位。用户一次启动后连续执行，无需逐岗确认。

单个岗位失效可跳过并继续；登录失效、平台验证、账号切换、平台明确限制或无法识别操作对象等影响整个任务的问题，应暂停并说明恢复条件。任务在当前用户浏览器中运行，关闭相关页面、退出浏览器或扩展运行被中断时，不展示为仍在后台持续执行。

继续任务前以可核验的当前状态避免重复处理，不将未知的旧结果直接当作失败重做。

## 候选岗位：比较、清理与选择联系对象

### 收藏映射

插件展示当前可获取的 BOSS 收藏岗位，包含岗位名、公司、列表摘要、收藏状态、已联系状态和 AI 匹配结果。读取范围、最后获取状态和不可识别项目需要可见，不把局部获取展示为已经完整同步所有收藏。

平台收藏是待联系队列。用户在 BOSS 中增删收藏后，插件刷新时据实际状态更新。取消收藏后，已经联系岗位的必要资料仍可用于聊天辅助、简历和统计，但不再混在待联系队列中。

### AI 匹配分析

用户批量发起分析后，系统结合当前个人档案与选中岗位内容给出：

- 0～100 的匹配参考分。
- 一至两个主要相符点。
- 一至两个缺口或待确认点。
- 有明确依据时，单独提示与求职偏好的冲突。

评分主要表达岗位要求与已知经历的相关程度，不表示录用概率或平台推荐权重。缺少完整 JD 或个人资料时，应标明分析依据不足；若只读到了摘要，明确显示「基于岗位摘要」，不伪装成完整分析。

分析期间逐项展示结果，单项失败允许后续重试。用户可以按分数排序和选中岗位；评分本身不触发取消收藏或发送。

### 三类批量清理

- **低分清理：** 用户输入阈值，查看命中范围后执行取消收藏。未评分或分析失败的岗位不按零分混入。
- **失效清理：** 一键取消收藏平台明确标示撤销、关闭或失效的岗位。加载失败不等于失效。
- **已联系清理：** 一键取消收藏已能确认打过招呼的岗位，既可覆盖本插件发送的结果，也可覆盖平台能明确识别的既有沟通。

清理按钮展示命中数量和操作范围，成功与失败分别反馈；操作只影响收藏。用户清理后，系统不自动补足原来的收藏数量。

### 联系队列

用户选中实际准备联系的岗位，可以结合匹配排序调整顺序，并单独决定本次联系数量。界面明确显示候选数、已选数及本次联系数。

主流程先完成候选收集与比较，再对选中岗位启动发送。列表是否符合关键词，不直接等同于获得联系授权；用户也不必逐条审阅消息才能启动已选队列。

## 首次招呼：个性化生成与批量自动发送

### 一次配置，多岗位执行

用户设置表达风格、希望突出的经历、消息条数、是否附简历图片，以及是否发送完成后自动取消收藏。用户资料中的表达边界始终生效。

每组招呼为 2～5 条，建议默认三条；图片计入总条数。开启图片时使用用户预先上传并预览确认的那张图片，目标是先发图片，再发文字。用户应能辨认当前使用的是哪张图片，并在启动新任务前替换或关闭。

文字各自承担清楚的作用，例如简短介绍与相关经历、针对岗位的补充说明、自然的沟通请求。内容根据岗位调整，而非只替换公司名；不把一句话机械拆开凑条数。

### 平台默认招呼提示

根据用户在当前网页上的使用反馈，HR 未回复前可以发送图片和普通消息，回复后可主动发送附件简历；点击「立即沟通」可能先发送平台默认招呼。

首次配置时提示用户关闭 BOSS 自带招呼语，避免内容重复。具体设置入口以及图片能否成为实际第一条，需按开发时页面验证。若平台已先发默认消息，界面应反映真实结果，不声称图片是第一条。插件不擅自改变平台设置。

### 生成和启动

用户可以先批量生成并预览、编辑，也可以在完成通用配置并选定岗位后，直接启动「生成并发送」。预览是可选能力，不能变成每条消息的必经审批。

自动任务对每个岗位读取所需资料，生成对应消息组并按顺序发送，然后处理下一个岗位。个人资料不足时使用有依据的较简短表达，不能捏造事实；若缺失信息使当前配置无法完成，应将该岗位标为待处理并说明原因。

### 结果、暂停与自动取消收藏

- 显示当前岗位、消息组进度、完成岗位数、部分完成数、跳过数和失败数。
- 发送前确认岗位与接收对象关联，避免页面变化后发给错误对象。
- 以明确的发送回执或可核验的会话内容确认消息成功，点击按钮本身不算完成。
- 同一岗位的部分消息成功时，保留已知结果；继续前核对，不整组重复发送。
- 已联系岗位默认跳过，不把已有聊天误记为本次成功发送。
- 用户可暂停、继续和结束。遇到验证、登录失效或平台限制时暂停，不凭空推算还有多少可用沟通额度。
- 「招呼发送完成后，自动取消收藏」开启时，只有整组消息均成功才取消该岗位收藏。部分成功、失败或未知均保留收藏。
- 发送成功但取消收藏失败时，两种结果分别展示，后续只需处理收藏，不重发招呼。

平台沟通额度按实际账号和页面反馈处理，不写死一个通用每日数量，也不把耗尽额度作为完成目标。

## HR 回复助手：生成建议，用户掌握对话

用户打开会话后，侧栏识别当前岗位和聊天对象。生成依据包括该岗位、当前可读取的会话上下文，以及与问题相关且允许使用的个人信息。

用户点击「生成回复」得到一份可编辑草稿，可以：

- 直接修改文字。
- 点击「重新生成」，获得另一种表达。
- 输入「简短一些」「更自然」「突出某项经历」「先问清楚职责」等方向重新生成。
- 将选定草稿填入当前聊天输入框，再由用户检查并通过 BOSS 发送。

填入前再次确认会话对象，已有未发送输入时不静默覆盖。插件不因检测到 HR 新消息就自动向对方回复。

到岗时间、离职原因、薪资等事实缺失时，先提示用户补充或给出明确待填写的草稿，不猜测承诺。针对职责、工作方式等未明确内容，也可建议用户向 HR 提问。

如当前页面只提供部分历史，应说明上下文范围；不能把未读取到的内容当作已经检查过。岗位与聊天文字是分析材料，不构成执行额外操作或扩大资料外发范围的指令。

## 定向 PDF 简历：按需生成，用户自行交付

### 入口与输入

用户从岗位或聊天侧栏主动点击「生成岗位简历」。输入为选中的原始 PDF、当前岗位内容和已确认个人档案。HR 索要简历可以提醒用户使用该入口，但不自动启动生成。

### 内容与交互

1. 展示当前岗位与原始文件，避免选错对象。
2. 生成定向内容草稿，突出相关经历，调整项目和技能顺序，压缩不相关内容。
3. 用户可编辑内容，查看需要补充或确认的位置。
4. 预览完整页面，确认中文显示、段落、分页和内容完整性。
5. 导出与该岗位对应的新 PDF，文件名能区分岗位和原件。

原始文件保持不变。只能使用真实资料；不得增加不存在的技能、数字成果、任职时间或管理职责。生成失败时保留用户可见的当前草稿，不声称已经生成可下载文件。

默认提案是生成稳定、易读的新版式 PDF，而不是承诺任意扫描件或复杂原 PDF 均能无损保留版式。若后续选择保留原版式，应先用代表性真实文件明确覆盖范围；这一选择尚未被用户单独确认。

用户自行下载、上传到 BOSS，再发送给 HR。插件只能将有证据的状态计为已发送简历；单纯生成或下载不能算发送。用户可确认实际使用的副本与岗位关联，便于之后准备面试。

## 用户自己的统计与可视化

统计服务于求职者判断「进展在哪里、哪里值得继续投入」，数据保存在本机，来自插件可观察到的执行结果、已读取会话和用户确认。

### 业务口径

主要按岗位关联会话统计，同时允许查看去重后的招聘联系人数量。初步包括：

- 已联系岗位：存在可确认的主动联系结果；同一岗位发送多条招呼只计一个岗位。
- 收到回复：观察到对方消息；可识别时区分自动欢迎与实质回复。
- 索要简历：对方提出请求或存在明确的平台请求状态。
- 已发送简历：以可识别的实际发送状态或用户确认为依据。
- 面试邀请与已确认面试：分别记录邀请和用户确认结果，避免混成同一指标。

识别结果允许用户纠正。状态可以跳跃发生，不要求先索要简历才能记录面试。未同步手机端会话、未读取历史和站外沟通属于覆盖缺口，界面需明确统计范围；未知不等于没有发生。

### 图表的用途

- **阶段人数／岗位数横向对比：** 展示已联系、收到回复、索要简历和面试等计数，帮助用户理解目前主要停留在哪些环节；不强行画成必须逐层递减的严格漏斗。
- **按时间的联系与回复趋势：** 基于已知事件时间观察近期进展，辅助安排待回复和后续跟进；缺失日期不补造。
- **从数字回到岗位：** 点击计数或图表分组进入对应岗位，用户能查看具体对象并纠正误判。

比率必须显示分子、分母及对应范围。例如回复率以同一批已联系岗位的可观察回复为依据，不能把本周收到的全部回复直接除以本周新联系数。样本少或覆盖不完整时明确说明，不从少量记录推导话术提升效果。

空状态展示真实的零或尚无数据，并引导开始任务，不放模拟业绩充当个人结果。

## 归档与数据备份

### 选中岗位归档

用户选择岗位并勾选需要的内容后下载文件包。提案包括：

- 岗位汇总 Excel：公司、岗位、薪资摘要、链接、匹配结果和当前求职状态。
- 单岗位 Markdown：已获取的岗位正文或摘要、匹配理由、用户选定的沟通摘要和准备事项。
- 用户选定的定向 PDF 副本。

导出使用本地已知资料；正文缺失时明确标记。完整聊天与完整个人档案不因导出岗位而自动混入，具体内容由用户选择。文件包不包含 AI Key 等认证信息。

### 本地资料备份

提供独立的导出与导入入口，供用户换设备或卸载前保存个人资料、岗位关联、统计和所选文件。备份说明包含哪些内容，并提醒用户妥善保管。

导入前展示备份基本信息及将影响的本地内容，避免静默覆盖当前资料。备份交互的具体格式与冲突处理在详细设计中收敛，初稿只要求用户能理解并控制导入结果。

## AI 设置与数据边界

### AI 服务配置

用户选择 OpenAI-compatible API 或 Anthropic Messages API，填写 API URL、API Key 与模型名称，执行连接测试。测试应展示真实结果，区分地址不可达、鉴权失败、模型不可用等可识别情况，并只发送最小测试内容。

运行时使用用户配置的服务完成档案整理、匹配分析、招呼、回复及简历内容生成。调用失败保留当前输入与已完成成果，不将网络失败记为分析成功或自动换用未配置的服务。

每次任务只发送完成当前任务需要的信息；模型输出需遵循真实资料和表达边界。岗位与聊天内的内容不能改变这些约束，也不能授权读取 Key 或发送其他用户资料。

### 数据去向

| 数据 | 保存或处理位置 | 用户控制 |
|---|---|---|
| 档案、岗位资料、任务结果、个人统计、会话所需内容 | 当前浏览器中的扩展本地存储 | 查看、修改、清除、备份 |
| 原始 PDF、图片、定向副本 | 本地保存和用户下载位置 | 替换、删除、导出 |
| 少量筛选偏好、招呼偏好、自动清理开关 | 本机及用户启用的 Chrome 设置同步 | 设置同步选择与浏览器同步状态 |
| AI Key | 默认仅保存在当前设备的扩展受控配置中 | 修改、清除，不进入普通备份和导出 |
| 当前 AI 任务所需材料 | 用户配置的 AI 服务 | 配置服务、发起任务，并了解将发送的信息类别 |

Chrome 同步总容量约 100 KB、单项约 8 KB，适合少量配置。同步依赖用户浏览器账号及相关同步设置；未启用时，本机功能仍然可用。完整档案、文件和持续增长的岗位记录采用本地保存与备份。

开发者不是用户资料和业务统计的数据接收方。用户配置的 AI 服务、Chrome 同步各自涉及实际数据传输，因此隐私说明不能宣称「所有数据绝不离开设备」。本地存储也不等于永久保存，卸载扩展或丢失浏览器配置可能导致本地资料丢失。

## 产品成立所需的验证与重要未知

### 已有研究能支持什么

- `boss-daily-brief` 主要是招聘方候选人处理和飞书简报流程，可参考资料整理与解释性结果组织。
- `boss-auto-job` 展示了求职方搜索、匹配和招呼流程，但核查路径中的实际发送与 README 宣称存在差异，不能直接视为可用成品。
- `boss-helper` 更接近扩展形态，核查版本采用页面内部状态与直接网络调用的混合路径，不能作为纯 DOM 自动操作的成功证明。
- 上述研究属于公开资料和源码静态核查，未验证本产品在 BOSS 当前页面中的真实运行效果。

### 在实现中优先验证的依赖

1. **页面与操作适配：** 列表可用字段、收藏读取与增删、失效状态、既有沟通识别、实际消息回执和会话关联。
2. **首次消息行为：** 图片与文字是否可按目标顺序发送、平台默认招呼的设置和实际行为、当前入口的消息约束。用户已报告的使用体验是设计依据，具体入口仍须真实核验。
3. **任务连续性：** 浏览器页面切换、扩展生命周期、账号状态变化后的实际可执行范围，不能承诺浏览器退出后继续运行。
4. **PDF 处理：** 中文、扫描件、复杂布局的解析及输出质量；稳定新版式和保留原版式的成本与覆盖差异。
5. **聊天与统计覆盖：** 页面实际暴露哪些上下文和业务状态，无法识别时如何明确标未知并允许用户修正。
6. **同步与模型兼容：** Chrome 同步前提及配额，不同用户 API 服务的协议兼容和错误表现。

浏览器操作和必要 API 均可使用，具体路径由实际验证决定，不在初稿中固定 Playwright 或某个私有接口。技术路径必须服务可识别对象、可核验结果和可暂停的批量自动化。

BOSS 官网当前协议入口展示了第三方接入及非正常获取信息的限制。是否能够稳定执行、平台是否允许接入、扩展商店发布要求是不同问题；控制频率或使用浏览器不能作为账号安全保证。相关平台与隐私条件应在对外发布前单独处理，不以虚构的「已获允许」或「不会受限」替代事实，也不把核心自动化静默改成全手动。

## 如何判断这份产品设计被正确实现

- 用户只提供原始简历与基本偏好就能开始使用，补充问答可跳过，已确认事实能直接编辑。
- 设置列表级关键词与 N 后，系统自动新增收藏，按实际成功计数、去重，不为收藏筛选逐岗获取全文或调用 AI。
- 收藏分析给出简明、有依据的分数和理由；低分清理由用户发起，未知结果不混作低分。
- 三类收藏清理以及发送成功后自动取消收藏均只改变应处理的收藏，不删除聊天或误清其他岗位。
- 用户选定多个岗位后，一次启动即可批量生成并逐个发送，每个岗位内容有针对性，无须逐条点击确认。
- 消息条数、图片使用和顺序符合设置及已验证的平台能力，发送结果与页面／回执一致。
- 部分发送、发送未知、清理失败和任务暂停能被区分，不因继续操作而整组重复发送。
- HR 后续回复由用户掌握发送动作；编辑、重新生成和方向调整均能保留当前岗位与会话关联。
- 定向简历仅在用户发起后生成，原件不被覆盖，PDF 可预览、下载，内容不捏造，生成或下载不被统计为已发送。
- 用户自己的统计能回到具体业务对象，明确覆盖范围、样本量和未知状态；归档、备份不混入认证信息。
- 本机功能不依赖产品服务器或额外产品账号；少量设置的同步与主要资料的本地保存符合说明。
- AI 任务只向用户配置的服务提交所需材料，资料披露边界在招呼、回复和简历中保持一致。
